## 4. 三条铁律（违反会导致返工）

1. **不要动 `E:\FPGA\...` 之外的绝对路径假设**。
   `design_top_wrapper.v`、`.al`、`.sdc`、`pin.adc` 里都有写死的工程路径。
   你改了就请一并提交，**并在 commit message 首行写** `TOUCHES: <文件名>`。

2. **不要在没有证据的情况下改这三个值**（A 已经反复横跳过，别再重演）：
   - `proj/baseline/lab3/user_source/hdl_source/isp/demosaic_4x_2_0/mipi_to_raw_converter.v` 的
     `parameter [9:0] BLACK_LEVEL = 10'd56`（10bit RAW 域黑电平，已有 TB `ALL PASS`）
   - `design_top_wrapper.v` 里 `wire S_blk_bypass = S_sw1_sync1;`（**不要加反相**）
   - `pin.adc` 里 `I_switch` 的 `PULLTYPE`（拨码开关极性依赖它）

3. **不要新增乘法器**。TD 会把 `a*b` 推断成 DSP；整机 DSP 是 40 个且历史上被顶满过，
   顶满后会迫使 `hdmi_mixer` 的乘法改走 LUT，进而在 HDMI 像素域产生时序违例。
   需要乘常数请写成**移位 + 加法**。

## 5. 怎么跑（三条命令）

### 5.1 全树语法检查（每次提交前必跑）

```bash
python <REPO>/_analysis/scripts/compile_check.py
```

**基线：`exit=0: 39 / 40`**（2026-10-12 实测）。唯一允许失败的是
`ph1p35_ddr/ph1p35_324_ddr_wrapper.v(61): (vlog-2730) Undefined variable: 'dhi_clk'`（黑盒保护）。
如果出现**别的**失败，就是你的改动引入的，先修掉再提交。

> 脚本已做**路径可移植化**（2026-10-12）：仓库根从脚本位置自动上溯推断，不用改代码。
> ModelSim 路径按 `环境变量 MODELSIM_BIN` → 常见安装位置 → `PATH` 的顺序查找。
> 如果报「找不到 vlog.exe」，先设：
> ```cmd
> set MODELSIM_BIN=<你的 ModelSim 安装目录>\win32aloem
> ```
> 手动指定仓库根也可以：`python compile_check.py <仓库根>`

### 5.2 ModelSim 仿真

用 ModelSim 命令行，**不要用 `.bat`**（cmd 不认 UTF-8 中文注释）。示例（BLC + Gamma）：

```bash
cd <REPO>/_analysis/sim/blc_gamma
mkdir run_tb && cd run_tb
vlib work
vlog ../mipi_to_raw_converter.v ../tb_blc_template.v
vsim -c -do "run -all; quit -f" tb_blc_template
```

输出的最后一行必须是 `ALL PASS, errors=0`。

> **AWB 相关仿真要注意**：`awb.v` 例化了 TD 的除法器门级网表，需要 TD 的仿真库。
> 正确顺序是
> `al_phy_glbl.v + al_map_basic.v + al_map_lut.v + al_map_adder.v + al_map_alu2b.v + al_map_mux4.v + al_map_seq.v + DUT + TB`，
> 然后 `vsim -c -do "run -all; quit -f" glbl <tb_name>`。
> **`glbl` 必须显式作为顶层传进去**（其唯一定义在 `<TD>/sim_release/common/al_phy_glbl.v`，
> 不在 `common/glbl.v`，那个文件不存在）。

### 5.3 综合 + 布线（只有 A 需要跑；B、C 可选）

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
& "<REPO>\_analysis\misc\td_run_direct.ps1" syn_1 phy_1
```

> 脚本里 Tcl 路径**必须用正斜杠**（反斜杠会被 Tcl 当转义吃掉，报
> `couldn't read file "E:TDdocscriptsDefaultFlow.tcl"`，而 **exit code 仍然是 0**）。
> 脚本已加产物 mtime 校验来识破这种「假成功」。

**基线 QoR（2026-10-12 K=45 版）**——你的改动不应该让它变差：

| 指标 | 基线 |
|---|---|
| Setup WNS / TNS / 违例端点 | **+84 ps / 0 / 0** |
| Hold WNS / TNS / 违例端点 | +20 ps / 0 / 0 |
| `#slices` | 17687 (83.37%) |
| `#RAMs` | 60 |
| `#DSPs` | **8**（若变多，说明你引入了乘法） |
| `#eram` | 60 / 108 |
| `#lut6` | 14915 / 21216 (70.30%) |

## 7. 队友 B 的任务：AWB 鲁棒化 + 色彩验收

### 任务目标

让 `awb.v` 在白平衡上真正做到「输出帧均值 R/G = B/G = 1.000 ± 0.02」，
并且在场景亮度快速变化时**不漂移**。

### 已有事实（别重复踩）

- **`awb.v` 的算法本身是正确的，已用仿真证明**：喂一帧恒定 `R=80/G=100/B=90`（输入 R/G=0.8000），
  输出 R/G 精确 = **1.0000**（B/G=0.9900 只是 8bit 截断损失）。
  参见 `_analysis/sim/awb/tb_awb_means.v`。
- **除法器 IP 也没问题**：`_analysis/sim/awb/tb_div_pattern.v` 证明在真实 valid 占空比
  （1,1,0 循环）下 `done` 照常拉高、商永远正确。
- 增益参数：`WB_GAIN_MIN=0x08000`(0.5x) / `WB_GAIN_MAX=0x40000`(4x) / `WB_DAMP_SHIFT=2`（约 4 帧常数）；
  `in_r_rN` 只在真复位时置 `0x10000`，之后每帧靠 `S_tuser_rise` 向 `in_r_tN` 走 1/4。
- **但上板实测有 5 次独立复现的固定加性偏置**：R 比 G 低约 **3 码**、B 比 G 低约 **3 码**，
  且**与亮度无关**（Y 均值 20~69 之间都是 −2.5 ~ −3.2）。见 `captures/2026-10-12_*` 各 README。
- 这个偏置**不在采集链路里**：同一张图上 Logo 蓝色区 `(28,45,78) → (27,44,75)`，
  R−G 逐码不变，说明采集链在同等信号电平上不改变 R−G。
- 一张**均匀灰面**的实拍里（`captures/2026-10-12_AWB诊断基准面/`），整帧 R/G 只有 **0.9295**，
  而灰世界的定义要求它精确等于 1.000。

### 你要做的

1. **先复现**：把 `tb_awb_means.v` / `tb_awb_zones.v` 跑起来，确认你得到同样的结论。
2. **找一个能解释「加性偏置」的机制**。已知候选（**未定案，需要你验证**）：
   - `awb.v` 里 `R_new = (R * gain) >> 16` 的截断（理论上只解释 −0.5 码，实测 −3 码）；
   - 去马赛克 `demosaic` 的通道相关定点（BGGR 下 G 用 `>>1`、R/B 用四邻域 `>>2`）；
   - 黑电平常数 56 是否偏低（实测传感器黑基座 R=66.4 / G=67.9 / B=66.1 raw10，通道间差 1.9 码）。
3. **提出一个可验证的修法**，并写出对应的 TB。
   - 如果修法需要新的 RTL，请用移位/加/减实现，**不要引入乘法器**。
   - 建议同时加一个**可关闭的开关**（默认关闭 = 逐位等价于现状），方便 A 做上板 A/B。
4. **准备色彩验收脚本**：`_analysis/scripts/stat_imgs.py` 已经能算
   Y 均值/分位/过曝/暗部/通道比，直接基于它扩展即可。要求能对任意两张实拍图输出：
   通道均值、R−G、B−G、R/G、B/G、分带（上中下）比值、Logo identity 校验（判断采集链是否可信）。

### 完成标准

- 用一张**均匀面**实拍，输出 R/G 与 B/G 都落在 **0.98 ~ 1.02**。
- 用一张**真实彩色场景**实拍，R−G 与 B−G 的绝对值都 **≤ 1.5 码**。
- 分带 R/G 的极差 < 0.01（说明没有逐行漂移）。

## 8. 队友 C 的任务：色调曲线改真 S + OSD 参数数值显示

### 任务目标

1. 把 `isp_gamma.v` 里的曲线从**反 S** 改成**真 S 曲线**（压暗部、提高光、保留中间调）。
2. 在画面上**显示参数数值**（当前 OSD 只有 Logo + `安路 CNT:xxxxxx` + `MODE n`，
   一个参数数值都没有，而赛题扩展要求明确写了「并在画面上呈现参数变化信息」）。

### 已有事实（别重复踩）

- 曲线在 `proj/baseline/lab3/user_source/hdl_source/isp/isp_gamma.v`：
  **12 路并行 256×8 ROM**（96bit = 4 像素 × 3 通道，一拍 12 个字节），
  `initial` 里内联 256 个初值到 `mem_b00`，然后用 `for` 循环复制到 `mem_b01..mem_b11`。
  **固定 2 拍延迟**，`I_gamma_bypass=1` 直通。
- **必须用内联表，不能用 `$readmemh`**：TD 综合的工作目录是 run 目录
  （`..._Runs\syn_1`），相对路径会静默读不到 ⇒ 表全 0 ⇒ 上板全黑，而综合/布线/时序报告全部正常。
- 生成脚本在 `_analysis/scripts/`：`gen_gamma_lut_twoseg.py`、`gen_gamma_lut_blackpoint.py`。
  当前表是 `p160_a050` + 黑位 K=45：`y = 255 * (x/160)^0.5`（x≤160 段）等两段幂函数，
  再叠一个黑位恢复 `new = round(y − K*(1 − y/255)^2)`。
  **`A = B = 0.5` 意味着两侧都是凹函数 = 降对比度 = 反 S，这是"画面发灰发闷"的直接原因。**
- 改完表，**必须同步改 TB 里的 `` `include `` 目标**（`_analysis/sim/blc_gamma/tb_gamma_bp.v`），
  否则会看到几千个假 FAIL。
- OSD 在 `hdmi_mixer.v`：三层（Logo ROM + 黄色帧计数 + 绿色 MODE 行）。
  `COLOR_DYN_TEXT = 24'hfff200`、`COLOR_ALG_TEXT = 24'h00ff88`，
  字符用 `osd_char_lib.v` 的 16×16 点阵查表拼。

### 你要做的

1. **曲线**：把指数改成真 S（建议先试 `A = 1.15, B = 1.10`，可用
   `gen_gamma_lut_twoseg.py` 的参数化接口），并保留黑位恢复那一层。
   约束：`y(0)=0`、`y(255)=255`、`y(128)≈128`、x=8 处斜率 ≤ 1.2、单调不减。
   同时生成 `.hex/.mif/.coe/.vh` 全套。
2. **OSD 参数数值**：在画面右上角（当前 CNT 行下方）增加一行参数显示，至少包含

## 10. 遇到问题

- **`compile_check.py` 报的失败和基线不同** → 先看是不是你的改动，八成是漏登记 `.al`。
- **仿真里 `Unresolved reference to 'glbl'`** → `glbl` 没作为顶层传进 `vsim`。
- **TD 综合说成功了但画面没变** → 检查脚本里 Tcl 路径是不是用了反斜杠
  （反斜杠被 Tcl 吃掉，报 `couldn't read file`，但 **exit code 仍是 0**）。
- **上板全黑但报告全绿** → 十有八九是 `$readmemh` 读不到表。
- **采集图颜色不对劲** → 先跑 `_analysis/scripts/_capture_chain_fit.py` 校验 OBS 采集链
  （应该输出 `VERDICT: capture chain is IDENTITY`）。链子不准时所有色彩结论都作废。
