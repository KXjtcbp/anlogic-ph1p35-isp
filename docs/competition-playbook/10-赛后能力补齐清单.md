# 10 · 赛后能力补齐清单

> 这份清单不是"我该学什么"的愿望列表，是**下一场比赛开赛前必须打完的关卡**。
>
> 每条都有「怎么算补好了」。**做不出那个动作，就是没补上**——不要用"我看过/我懂了"结账。

---

## 0. 怎么用

- 按 **P0 → P1 → P2 → P3** 顺序做。**P0 没打完不要碰 P1**，因为 P1 全建立在 P0 之上。
- 每条标了来源：
  - **`[实践]`** —— 这次赛事亲身踩出来或亲身验证过的。
  - **`[外部]`** —— 来自公开获奖作品、复盘、教材、厂商文档，**我们没有自己验过**。
- 时间栏是「一个普通大三学生、每周 6 小时」的估算，不是最低要求。
- 清单末尾 §6 有一份「下次不用管的」，避免把这次的特殊性当成通用规律。

## 1. 先看清这次的短板分布

不是"哪里都差"，是**分布很不均**。这张表决定后面先补哪块。

| 维度 | 本次实际水平 | 证据 |
|---|---|---|
| 执行与验证纪律 | **强** | 单变量对照做了四次独立复测；每张采集图都记 CNT；发现并纠正过 agent 的读数错误 |
| 记录与追溯 | **强** | 34 个版本目录、每版比特流核 md5、每轮采集归档 + CSV |
| 提问质量 | **强** | 反复把"方案是什么/为什么这样/还有哪些没做"问到位，逼出了可执行的结论 |
| 独立闭环（改→编→烧→看） | **弱** | 全程没有一次是你自己写一行 RTL 然后上板看出变化 |
| 读 RTL | **弱** | 能看懂模块接口和注释，看不懂并发、位宽、跨时钟域 |
| 自己造判据 | **中偏弱** | 能执行判据、能判断数字合不合理，但"判据应该是什么"基本由 agent 给 |
| 归因定位 | **中偏弱** | 会设计对照实验，但"这个现象是谁的问题"多数靠 agent 推 |
| 应用叙事 | **弱** | 报告写了五个应用场景，删掉它们作品一点不受影响——那是叙述，不是方向 |

> **结论**：你不缺"认真"，缺的是**独立性**。三个强项都是"把已有的事做扎实"，三个弱项都是"从零产生一个东西"。
> 所以 P0 全部指向同一件事：**独立走完一次最小闭环**。

## 2. P0 · 不补下次还是这样（必做，约 6 周）

### P0-1 独立走完一次「改一行 → 编 → 烧 → 看变化」`[实践]`

**为什么**：这是整份清单里唯一真正的分水岭。本次全部 8 个自研模块都是 agent 写的，你验证得很扎实，但没有一次是"你写的"。评委问"这行代码为什么这么写"时，扎实的旁观者答不上来。

**怎么练**（用你手上这块板子，不用买新的）：

1. 打开 `proj\baseline\lab3\user_source\hdl_source\hdmi_mixer.v`，找到 `localparam COLOR_DYN_TEXT = 24'hfff200;`（CNT 那行的黄色）。
2. 改成 `24'h00ffff`（青色）。
3. 跑 `_analysis\misc\td_run_direct.ps1 syn_1 phy_1`，确认四条构建判据都过（详见 `03` §5）。
4. 烧 `proj\...\phy_1\camera_to_dsi_display.bit`，**拔电 5 秒再上电**。
5. 看屏幕：CNT 那行变青了没有。

**✓ 怎么算补好了**：不看任何文档，能自己复现上面 5 步，并且说得出「为什么改了参数不用改接线」「为什么必须拔电」。

**时间**：第一次 3 小时（会卡在构建判据上），之后每次 40 分钟。

---

### P0-2 能读懂一个模块的 RTL，做得到「逐行讲出它在干什么」`[实践]`

**为什么**：本次的 `awb.v`（帧内增益爬坡）、`obj_detect.v`（`tlast` 是帧末不是行末）、`motion_detect.v`（块均值）三个真 bug，全都是"读代码才看得出来"的。你不读，就只能等别人看。

**怎么练**（从小到大，每篇都写一句总结）：

| 顺序 | 文件 | 行数量级 | 读什么 |
|---|---|---|---|
| 1 | `isp\isp_gamma.v` | ~270 行 | 12 张并查表 + 2 级流水，最干净的样板 |
| 2 | `isp\ae_stat.v` | ~190 行 | 单纯移位加法做统计，看它怎么避开乘法器 |
| 3 | `isp\obj_detect.v` | ~280 行 | 坐标计数 + 块累加 + 孤立块滤除 |
| 4 | `isp\lsc.v` | ~430 行 | 二维表 + 双线性插值，最难但最值钱 |
| 5 | `isp\awb\awb.v` | ~400 行 | 为什么"每拍改写增益"是错的 |

**每篇要求**：能不看注释，把「输入什么、输出什么、内部有几个状态/几级流水、哪个时钟域、最坏情况几拍出结果」写成一页纸。

**✓ 怎么算补好了**：拿 `isp\awb\awb.v`，能在 15 分钟内指出「增益是在哪里被更新的、这为什么会导致帧内偏色」。这是本次最经典的一个 bug，讲得出来说明真的会读了。

**时间**：每篇 2~4 小时，5 篇约 3 周。

---

### P0-3 能自己造出一条判据，并说清它为什么可信 `[实践]`

**为什么**：本次所有"我们做好了"的结论，判据都是 agent 给的。你会执行、会质疑数字，但不会从零造。没有判据的调试就是猜。

**判据三要素**（`03` §3 有完整表述，这里是你必须内化的版本）：

```
数值  —— 量什么？单位是什么？（"逐列 R/G 的极差"而不是"看起来均匀"）
条件 —— 在什么条件下量？（同机位、同光照、只拨一个开关、同一比特流）
复查 —— 别人怎么复现？（跑哪个脚本、几张图、差多少算过）
```

**怎么练**：给自己手上的任意一个改动造判据。比如 P0-1 里把 CNT 改青色：

- 数值：CNT 文字区域的 R 通道均值，从 ≈255 掉到 ≈0
- 条件：同一张 OBS 截图、遮掉 logo 与其余 OSD
- 复查：`python _analysis\scripts\stat_imgs.py <图>` 看 R 均值

**✓ 怎么算补好了**：连续三个改动，你都能在动手之前把判据的三要素写下来；并且事后发现判据不够严时，知道该收紧哪一条。

**时间**：跟着 P0-1 一起练，边际成本几乎为零。

---

### P0-4 能用「四判据」识破假成功 `[实践]`

**为什么**：本次踩了三次「构建报告全绿、上板没效果」。这个坑不是 FPGA 独有，任何"构建产物 → 烧录"的链路都有。识破它是省时间的第一技能。

**四判据**（`03` §5 与 `platforms/fpga.md` §3）：

1. 日志里没有「模块是黑盒 / 找不到文件」
2. 新模块能在网表报告里搜到，且资源占用是合理量级（不是 0、也不是暴涨）
3. **关键数字有变化**（`route.qor` 的时序、资源、线长）
4. 关键资源数没有异常下降（掉一半以上 = 整条链被当冗余扫掉了）

**✓ 怎么算补好了**：看到一份"全绿"的构建报告，能在 2 分钟内判断它是真成功还是假成功，并说出该去看哪两个文件的哪几行。

**时间**：1 天（把本次三次假成功的日志重看一遍就够）。

## 3. P1 · 决定名次（4 周）

### P1-1 时序与资源口径 `[实践]`

**要会的**：`Setup WNS` / `Hold WNS` / `TNS` / 违例端点数的含义；`#slice` 与 `#lut6` 为什么分母相同但含义不同；为什么"厂商标称等效 LUT 38184"和工具里的 `#lut6 21216` 不是一回事；ERAM 单块 20 Kbit、`#RAMs` 与 `#DSPs` 的预算意识。

**✓ 怎么算补好了**：给你一份 `route.qor` 和 `phy.area`，能在 5 分钟内说出「时序余量还剩多少、还能往哪加东西、加多少会出问题」。

**时间**：1 周，配合读 3 份真实的 `route.qor`。

### P1-2 跨时钟域（CDC）`[实践]`

**要会的**：单 bit 用两级同步器、多 bit 数据必须配使能或握手、**事件不能用单周期脉冲跨域要用电平翻转 + 边沿检测**。本次 AE 的 `O_frame_tgl` 就是这个。

**✓ 怎么算补好了**：能指着一份 RTL 说「这条路径跨了两个时钟域，它会/不会出问题，为什么」。

**时间**：1 周。

### P1-3 工具链的命令行与自动化 `[实践]`

**要会的**：命令行构建（不依赖 GUI）、构建成败判定、批处理脚本、产物归档与 md5 核对。本次最大的时间黑洞就在这——TD 命令行只认 run 目录的 `.prj` 不认 `.al`，踩了三次。

**✓ 怎么算补好了**：能写一个脚本，一条命令完成「同步文件清单 → 综合布线 → 判成败 → 归档 → 报 md5」。

**时间**：1 周（含踩坑）。

### P1-4 应用叙事（选方向的能力，不是写文档的能力）`[实践]`

**为什么单列**：这是本次**最贵的一个失分点**，而且它不靠技术补。报告里写了五个应用场景，但删掉它们作品一点不受影响 ⇒ 那是叙述，不是方向。

**怎么练**（`07` §3 的三连造句法，练到能条件反射）：

> 我能感知到 **A**，判断 **B**，然后让 **C** 做出 **D**。

四个空必须都填上，填不满就是在做 demo。本次我们填了 A 和 B，C 只到"画一个框"——**没有动作，就没有闭环**。

**✓ 怎么算补好了**：拿到任意一块陌生的开发板，60 分钟内写出「一句话方向」，且这句话里有一个具体的"谁"和一个具体的"动作"。

**时间**：跟 `07` §7 的 60 分钟流程练三次。

## 5. P3 · 认知层（长期，不占专门时间）

- **区分"做完了"和"做成了"**：本次 8 个模块都"做完了"，但只有一个有量化达标证据（LSC 的 43~46%）。**做完是过程，做成是判据。**
- **警惕"资源用得多 = 技术含量高"**：本次自研 8455 LUT 只占 51.6%，另一半是官方 IP 底座；而 8 个小功能每一个都"看不见"。**评委记住的是深的那一个，不是宽的那八个。**
- **接受"选错了要早改"**：选题阶段改主意是免费的，实现阶段很贵，提交前不可能。本次失分的 80% 在选题那一周就决定了。

## 6. 下次不用管的（这次的特殊性，别当通用规律）

这些只跟"安路 PH1P35 + TangDynasty + 本次赛题"绑定，换赛道/换板子就作废，**不要花时间背**：

- 安路这套工具链的具体坑（`.prj` vs `.al`、`.bit` 恒为 1 789 539 字节、ChipWatcher 调试中枢吃资源）→ 换平台就换一张平台卡，见 `platforms/`。
- SC500CS 传感器的寄存器细节、MIPI 2-lane 解包格式。
- 本次赛题的评分表与提交项细节 → 在 `_本项目配置.md`，换比赛整份重填。
- 我们那 8 个自研模块的具体实现 → 它们是"这个题"的答案，不是"任何题"的答案。

> **判断标准**：如果一条经验换个赛道/换个板子就不成立了，它属于平台卡或配置，不属于你自己的能力清单。

> 这三条做到，下次比赛你就不再是"执行得很好的旁观者"，而是能独立起盘的人。
