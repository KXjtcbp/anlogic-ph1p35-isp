# 07 · 从开发板到项目方向（自下而上）

> `02-题目到方向.md` 解决的是**有赛题、没方向**（自上而下）。
> 这一份解决的是**有板子、没题目**（自下而上）。
>
> 适用场景：手头有一块开发板 / 一个传感器 / 一个模块，但不知道拿它做什么；或者在做课程设计、个人项目、开源项目，没人给你出题。

---

## 0. 两种起点，两种方法

| | 起点 | 问题 | 用哪份 |
|---|---|---|---|
| 自上而下 | 有赛题/需求 | 题目看不懂、不知道能干什么 | `02` 四问法 |
| **自下而上** | **有硬件** | **不知道能做什么** | **本文件** |

**`[实践]` 关键认知**：绝大多数人卡在自下而上这一侧，却用自上而下的方法去找答案——拿着板子问"这块板子能干什么"，永远得不到答案。

正确的问法是：**"这块板子能感知到什么、能改变什么？"** 然后从答案里挑一个，配上"谁需要"。

---

## 1. 第一步：把板子的能力写成五层清单（15 分钟）

不要看开发板手册的引脚表，看**能力**。按五层填：

### 1.1 五层模板

| 层 | 问自己 | 填 |
|---|---|---|
| **① 感知层** | 它能"看见/听见/感觉到"什么？ | 摄像头、麦克风、温湿度、IMU、气压、光敏、气体、电流、超声波、雷达、GPS、指纹、触摸 |
| **② 执行层** | 它能让外部世界发生什么变化？ | 直流电机、步进、舵机、继电器、LED、屏幕、扬声器、蜂鸣器、电子锁、加热、风扇 |
| **③ 算力层** | 它能算什么？算多快？算多少？ | 定点/浮点、主频、是否并行、有没有 OS、能不能跑 Python/CNN、有没有 DSP/NPU |
| **④ 通信层** | 它能连什么？ | UART、I2C、SPI、CAN、USB、以太网、WiFi、BLE、4G/5G、LoRa、红外 |
| **⑤ 呈现层** | 它能把结果呈现成什么？ | 屏幕、指示灯、蜂鸣、手机 App、网页、串口日志、云平台、存储卡 |

### 1.2 本次（FPGA 板 + 摄像头）填出来是这样

| 层 | 本次有什么 |
|---|---|
| ① 感知 | 摄像头（可见光，1280×720@60）、4 个拨码、4 个按键 |
| ② 执行 | 4 个 LED、8 段数码管、蜂鸣器、若干 GPIO（可接舵机/电机） |
| ③ 算力 | 38 K 等效 LUT、40 DSP、108 块片上 RAM —— **强项是"每拍并行处理"**，弱项是"复杂串行判断" |
| ④ 通信 | 以太网口、USB-UART、I2C/SPI（接传感器） |
| ⑤ 呈现 | HDMI 输出（1280×720@60）、屏上叠字叠框 |

> **看"③ 算力层"那一行**：`强项是每拍并行处理`——这就是这块板子的**差异化能力**。
> 它适合做"对每一帧/每一个采样点都要做同一件事"的活，不适合做"要反复查表回溯"的活。
> **一个项目的方向，往往就藏在"这块板子最擅长的那一格"里。**

## 2. 第二步：先判断这块板子属于哪一类（决定能做什么）

不同平台的能力边界差别极大，选错平台，后面全是坑。

### 2.1 五类平台能力对照表

| | **FPGA** | **MCU（单片机）** | **SoC + ARM（带 OS）** | **单板计算机** | **云 / PC** |
|---|---|---|---|---|---|
| 典型芯片 | 安路、Xilinx、紫光同创 | STM32、ESP32、GD32、51 | Zynq、RK3568、i.MX | 树莓派、Jetson | 服务器 |
| 算力特征 | **并行极强**、串行弱 | 串行够用、并行很弱 | CPU + 可选 NPU | CPU/GPU 通用算力 | 最强 |
| 实时性 | **纳秒~微秒级、确定** | 微秒级、确定 | 毫秒级、不确定 | 十毫秒级、不确定 | 网络延迟 |
| 上手难度 | 高（时序、资源、工具链） | **低** | 中（驱动/系统） | **最低** | 低 |
| 开发周期 | 长 | 短 | 中 | 短 | 短 |
| 典型适合 | 图像/信号/高速采样/多路并行 | 控制、传感采集、低功耗节点 | 图像+AI+控制混合、要能跑 Linux | 快速验证、带 GUI/AI 的演示 | 训练、批量处理 |
| 典型不适合 | 复杂业务逻辑、网络协议栈 | 图像处理、大算力 | 硬实时要求极高 | 硬实时、低功耗 | 现场设备 |

### 2.2 一句话选型规则

- **要在每个采样点上做同一件重活 → FPGA**
- **要控制几十个外设、跑状态机、省电 → MCU**
- **既要算力又要操作系统和驱动 → SoC + ARM**
- **只想最快看到效果、验证想法 → 单板计算机**
- **只做算法验证、不关心实时 → PC/云**

> **`[外部]` 竞赛场景的隐含偏好**：电赛偏"电路 + 实时控制"（MCU/模拟电路为主，FPGA 是加分）；集创赛有明确赛道划分（芯片设计/FPGA/嵌入式/AI），**先看赛道再选平台**；嵌入式类竞赛（如全国大学生嵌入式芯片与系统设计竞赛）通常指定开发板，**没得选**。
> `[推断]` 如果目标是"拿名次"，平台选择的权重大约和算法选择相当——选一个大家都用的平台，评委更容易看懂。

### 2.3 本项目同类平台的迁移成本（`[推断]` 基于本次经验）

| 想做的事 | FPGA 成本 | 换 MCU | 换 SoC+ARM | 换单板计算机 |
|---|---|---|---|---|
| 720p 视频直通显示 | 中（要写时序） | ❌ 做不到 | 中（有驱动） | 低（有库） |
| 每帧算 30 万像素 | 中（并行） | ❌ 太慢 | 低（CPU 算） | 低 |
| 精确定时采样 | 低 | 低 | 中（要实时内核） | ❌ 不稳 |
| 神经网络推理 | 高（要手写量化） | ❌ | 低（有 NPU） | **最低** |
| 低功耗常开 | 中 | **最低** | 高 | 高 |

> **用法**：先看你项目的**核心那一件事**落在哪一行，再选平台。不要为了"想用 FPGA"而选 FPGA。

## 3. 第三步：用「感知 → 判断 → 动作」造句（核心方法）

**任何有意义的项目都是这三段：感知到什么 → 判断了什么 → 做了什么。**

板子缺哪一段，就是你的第一个设计决策（补硬件、还是换方案）。

### 3.1 造句模板

> **「当【感知层】检测到【某种状态】时，【算力层】判断【是否满足条件】，然后【执行层】做【某个动作】，并把结果显示在【呈现层】。」**

### 3.2 用本次板子造 10 句（示范，不是答案）

1. 摄像头看到**画面里有东西在动** → 判断**动了多少块区域** → **LED 亮起**，屏上**框出运动区域**
2. 摄像头看到**红色物体** → 判断**它在画面哪个位置** → **舵机转向它**，屏上**标出坐标**
3. 摄像头看到**画面整体变暗** → 判断**该加曝光了** → **传感器增益加大**，屏上**显示当前增益**
4. 摄像头看到**人形轮廓** → 判断**人数** → **蜂鸣器提示**，数码管**显示人数**
5. 摄像头看到**车道线** → 判断**车是否偏出** → **蜂鸣器报警**，屏上**画参考线**
6. 摄像头看到**产品的划痕** → 判断**是否超阈值** → **继电器剔除**，屏上**计数不良品**
7. 摄像头看到**手势** → 判断**是哪个手势** → **LED 组合变化**，屏上**显示识别结果**
8. 摄像头看到**颜色先后顺序** → 判断**是否匹配密码** → **继电器开锁**
9. 摄像头看到**火焰颜色** → 判断**面积是否扩大** → **蜂鸣器 + 继电器切水泵**
10. 摄像头看到**文字/数字** → 判断**读数多少** → **数码管显示**

> **`[实践]` 我们这次做的是第 1 句的前半段**（能看出"哪块动了"），**但没有后半段**（动起来之后干什么）。
> 于是作品停在"能演示"，没到"有用"。

### 3.3 三连缺一段怎么办

| 缺哪段 | 表现 | 怎么办 |
|---|---|---|
| 缺**感知** | 有算力、有动作，但不知道根据什么触发 | 加一个最便宜的传感器（几块钱）就够；或者用按键/拨码当"人工感知"（演示也能过） |
| 缺**判断** | 有输入输出，但中间只是直通 | 这里才是你的技术含量所在；加阈值/分类/计数/比较，**哪怕只有一条规则** |
| 缺**动作** | 能识别但只显示在屏幕上 | 加一个执行器（舵机/继电器/LED/蜂鸣器），**这是"闭环"和"演示"的分界线** |

> **`[实践]` 教训**：我们缺的是"动作"。识别出运动之后，只是画个框——评委看到的仍然是"一个能看的东西"，不是"一个能干活的东西"。
> **补上"动作"往往比提升识别精度更能加分，而且更便宜。**

## 4. 第四步：30 个「能力 → 项目」对照（按能力挑，不要按兴趣挑）

先找到**你的板子最强的那一格**，再从对应行挑。

| 最强能力 | 可以做什么（挑一个） |
|---|---|
| **图像 + 并行算力**（FPGA） | ① 划痕/瑕疵在线检测 ② 运动目标框选与计数 ③ 车道线识别与偏离报警 ④ 手势/颜色密码锁 ⑤ 火焰/烟雾视觉报警 ⑥ 分拣机（颜色或形状） |
| **图像 + CPU/GPU**（SoC、单板机） | ⑦ 人脸门禁 ⑧ 口罩/安全帽识别 ⑨ 车牌识别 ⑩ 果实成熟度分级 ⑪ 姿态估计与动作纠正 ⑫ OCR 读表/读码 |
| **精确定时采样**（FPGA/MCU） | ⑬ 示波器/逻辑分析仪 ⑭ 心电/肌电采集与显示 ⑮ 振动监测与故障预警 ⑯ 电能质量分析 ⑰ 超声测距与避障 |
| **多路控制 + 低功耗**（MCU） | ⑱ 温湿度+光照自动补光种植箱 ⑲ 智能家居节点（灯/窗帘/插座） ⑳ 电池管理+充电监控 ㉑ 步进电机定位平台 ㉒ 环境数据记录仪 |
| **通信 + 组网**（任意平台 + 无线） | ㉓ 无线传感网网关 ㉔ 远程设备监控与 OTA 升级 ㉕ 蓝牙信标定位 ㉖ LoRa 农业监测 |
| **人机交互 / 呈现**（任意平台 + 屏/App） | ㉗ 教学实验箱（可切换多种算法并显示效果） ㉘ 数据可视化面板 ㉙ 语音控制家电 ㉚ 体感游戏控制器 |

> **挑法**：先从"最强能力"那一列选 3 行 → 每行挑 1 个 → 用 §5 的四道筛子筛 → 剩 1 个。

---

## 5. 第五步：四道筛子（必须全过）

| 筛子 | 问什么 | 过不了怎么办 |
|---|---|---|
| **① 时间** | 我能在 `<N>` 周内做出**能演示的版本**吗？ | 砍功能，只留"感知→判断→动作"最小闭环 |
| **② 画面** | 有没有一个**能拍成 5 秒视频的瞬间**？ | 换呈现方式：加屏幕/加蜂鸣/加 LED |
| **③ 对象** | 有没有一个**具体的人**会觉得有用？ | 回到 `02` 四问法的问 2、问 3 |
| **④ 差异** | 别人做过的版本，我的**哪一点不一样**？（更快/更小/更省/更便宜/能离线） | 加一个自加限制（见 `02` §4.3） |

> **`[实践]` 第 ② 道最容易忽略、最致命**：我们功能做了一堆，但**没有一个"一看就懂"的瞬间**。
> 评委一天看几十个作品，抓不住瞬间就等于没做。

## 6. 反向清单：这块板子**不能**做什么

**知道不能做什么，比知道能做什么更能定位方向。**

- FPGA：不适合复杂业务逻辑、网络协议栈、大量分支判断（写起来极痛）
- MCU：不适合图像处理、大矩阵运算、跑模型（算力不够）
- SoC/ARM：不适合"硬实时"（Linux 下抖动毫秒级）
- 单板计算机：不适合低功耗常开、硬实时
- 任何平台：不适合"没有明确判断规则"的问题（那是算法的活，不是硬件的活）

**限制法（`02` §4.3）的延伸**：把这些"不能"写成"我偏要"的项目限制，往往能出好作品——
- "FPGA 不适合跑 CNN" → "用 FPGA 跑一个只有 3 层的极简 CNN，证明能行"
- "MCU 不适合图像" → "在 MCU 上做 64×64 的图像识别，看极限在哪"

## 7. 60 分钟流程（从"有板子"到"一句话方向"）

| 时间 | 做什么 | 产出 |
|---|---|---|
| 0–15 min | 填 §1 五层清单 | 一张能力表 |
| 15–25 min | 用 §2 判断平台类别，圈出"最强那一格" | 一句话："这块板最强的是 ___" |
| 25–40 min | 按 §3 造句，至少造 10 句 | 10 个候选项目 |
| 40–50 min | 按 §4 的 30 行表补 3 个 | 13 个候选 |
| 50–55 min | 过 §5 四道筛子 | 剩 1~2 个 |
| 55–60 min | 写成一句话方向，用 `02` §6 的 8 条清单打勾 | **一句话方向** |

> **`[实践]` 如果 60 分钟做不出"一句话方向"，不要开始写代码。**
> 我们这次就是没做这一步，直接开始写 ISP，三个月后才发现方向错了。

## 8. 常见的五种死法

| 死法 | 表现 | 根因 |
|---|---|---|
| **"炫技型"** | 用了很厉害的算法，但没人知道它解决什么问题 | 只做了 §1 的③算力层，没做①②⑤ |
| **"demo 型"** | 能演示，但关掉演示环境就没用 | 缺"动作"，只有"显示" |
| **"重复造轮型"** | 做的东西和开源项目一模一样 | 没过第 ④ 道筛子（差异） |
| **"平台错配型"** | 用 MCU 硬做图像，或用 FPGA 硬做协议栈 | 没做 §2 平台判断 |
| **"无闭环型"** | 感知有了、判断有了、就是不动作 | 缺 §3.3 的"动作"那一段 |

> **这五种死法我们占了三种**（炫技型 + demo 型 + 无闭环型）。写在这里，是为了下次开局对照一遍。
