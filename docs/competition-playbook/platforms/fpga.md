# 平台卡 · FPGA

> 本次实践平台：安路 `PH1P35MDG324`（`HX1P35A` 开发板）+ `TangDynasty V6.2.168116`。
> 换 Xilinx / 紫光同创 / 其他安路型号时，**第 3、4 节要重写，第 1、2、5、6 节基本通用**。

---

## 0. 一句话定位

**最强：每个时钟拍对所有输入并行做同一件事**（图像、信号、多路采样）。
**最不适合：复杂串行判断、协议栈、大量分支业务逻辑**（写得极痛且耗尽资源）。

## 2. 资源口径（★这节最容易吃亏★）

| 项 | 标称 | 工具报告 | 说明 |
|---|---|---|---|
| 逻辑单元 | **38 184 等效 LUT** | `#lut6` 总数 **21 216** | ★**两个数不是一回事**。对外讲优化效果时用工具数；被问"38 K 只用了 77%"时，要能解释口径差异★ |
| 触发器 | 42 432 DFF | `#reg` / `#slice reg` | |
| 片上 RAM | 108 块 ERAM（2 160 Kbit） | `#eram` / 108 | 每块 20 Kbit；**查表用 12 块只用 10% 容量的情况真实发生过** |
| DSP | 40 | `#dsp` / 40 | **常数乘法会被推断成 DSP**（`r * 77` 这种），用移位加法替代 |
| 时序 | — | `Setup WNS` / `Hold WNS` | 交付前保证 `WNS > 0` 且 `TNS = 0` 且违例端点 `= 0`；留 ≥100 ps 余量 |

## 3. 工具链与最小验证路径

```
编译（综合）：   <工具>\bin\<命令行 exe>  <flow 脚本>
布局布线：      同一条命令里的后两个 stage
产物目录：      <工程>\..._Runs\<run名>\
```

- **★什么算"构建成功"（四判据，缺一条就等于没成功）★**
  1. 日志里**没有** `black box` / `HDL-8007` 一类警告
  2. 新加的模块在**网表**（`gate.area` / `phy.area`）里能搜到，且 LUT 数合理
  3. **时序与资源数字发生了变化**（和上一版逐项比）
  4. 关键资源数**没有异常下降**（掉了就是被当冗余扫掉了）
- **最小可上板验证**：原厂示例原样编译 → 烧板 → 看到图 → 存档其 `.bit` / `route.qor` / `phy.area` 当对照组。
- **下载方式**：JTAG（开发中）/ QSPI Flash（交付，断电自启）。
- **冷启动**：烧完**拔电 5 秒**再上电（不是按复位键）——传感器/外设的初始化表通常只在冷启动时重来。

## 4. 这类平台的专属坑

| 坑 | 表现 | 怎么避 |
|---|---|---|
| 命令行读的工程文件 ≠ 图形界面那份 | 改了 `.al` 但命令行构建完全没变化 | 命令行只认 `..._Runs\<run>\.prj`；写成脚本每次构建前同步 |
| 工具会**回写**你手改的清单文件 | 手工改完、跑一次构建、再看发现改动被冲掉了 | 一律改成脚本重新生成，不要手改 |
| 相对路径**静默失败** | 初始化表读成全 0，上板黑屏，而报告全绿 | 表内联进代码；或构建后检查文件内容；静默失败要加断言 |
| 编码 | BOM 让仿真器语法报错；命令行脚本里的中文被误码解码吃掉引号 | 脚本文件只写 ASCII；改过的文件检查前三字节 |
| 退出码不可信 | 一行没跑也 `exit 0` | 检查产物 mtime 是否真的更新 + 扫日志关键字 |
| 长时间构建别用 `Start-Process` | 卡死几个小时没输出 | 用后台任务 + 轮询 + 超时 |
| 忘了接输出端口 | 整条链路被当冗余扫掉（`#RAMs` 40→12、`#DSPs` 9→1） | 综合后核对关键资源数 |
| 常数乘法吃 DSP | `#dsp` 顶满，别的模块被迫走 LUT，逻辑层级变深触发时序违例 | 移位加法替代 |

## 5. 交付物检查项（这类平台特有）

- [ ] 工程文件（`.al` 等）——**引用的每个源文件都在包内**
- [ ] 约束文件（时序 `.sdc`、引脚 `.adc`）
- [ ] IP 描述文件（`.xml` / `.ipc`）
- [ ] **时序报告**（`route.qor` / `.timing`）★最易漏★
- [ ] **面积报告**（`*.area`）★最易漏★
- [ ] 交付比特流 `.bit` + 其 md5
- [ ] 引脚分配表
- [ ] `README_CODE.txt` 里写明：**哪几个模块是自己写的、各占多少 LUT**

> **`[实践]` 我们这次就漏了中间三个**：代码 61/61 都在、一点不缺，但"证明它能跑"的三个文件全被扩展名过滤器剔掉了。

## 6. 判据怎么写（FPGA 的可测数字通常是这些）

| 目标 | 可测判据 |
|---|---|
| 通路打通 | 输出分辨率 / 帧率 / 帧计数与墙钟误差 <0.3% |
| 时序收敛 | `Setup WNS > 0` 且 `TNS = 0` 且违例端点 = 0 |
| 资源可控 | `#slices` / `#lut6` / `#eram` / `#dsp` 各自百分比，留 ≥20% 余量 |
| 画质功能生效 | 关/开两次采集，**同一个数字**变好（逐列极差、帧均值、通道比） |
| 长跑稳定 | 连续 15 分钟，关键指标漂移 <1% |
| 上电自启 | 拔电 5 秒后再上电，10 秒内自动出画面 |

## 7. 迁移提示（从软件/MCU 过来最容易犯的错）

1. **不要用"分支"思维写 RTL**：每个 `if` 都是硬件，能并行就并行。
2. **资源是硬的**：多加一个功能就是多几千 LUT，没有"以后再优化"。
3. **时序是硬的**：逻辑层级太深就是跑不到目标频率，改算法比改约束有用。
4. **仿真不能代替上板**：仿真全过但上板黑屏是常态（见第 4 节）。
5. **"看起来对"不算对**：必须有一个可测数字（见 `03` §3 判据三要素）。
