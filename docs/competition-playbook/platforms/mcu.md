# 平台卡 · MCU（单片机）

> **内容来源标注**：本卡绝大部分是 `[外部]`（通用嵌入式工程实践、主流 MCU 厂商文档与开源项目惯例），**不是本次实践的亲验结果**。用到时请按你的具体芯片手册核对。

---

## 0. 一句话定位

**最强：控制几十个外设、跑状态机、低功耗常开、成本极低。**
**最不适合：图像处理、大矩阵运算、跑神经网络**（算力差两三个数量级）。

---

## 1. 能力清单

| 层 | 典型配置 |
|---|---|
| ① 感知 | ADC、GPIO 中断、I2C/SPI 传感器（温湿度、IMU、气压、气体、光敏、霍尔）、比较器、电容触摸 |
| ② 执行 | GPIO 输出、PWM（舵机/电机/调光）、继电器、蜂鸣器、步进驱动 |
| ③ 算力 | 几十~几百 MHz 单核/双核，几十~几百 KB RAM，几 MB Flash；**无并行** |
| ④ 通信 | UART、I2C、SPI、CAN、USB、WiFi/BLE（ESP32 类）、LoRa/NB-IoT 模组 |
| ⑤ 呈现 | OLED/LCD 小屏、LED、串口日志、手机 App（经 BLE/WiFi）、云平台 |

---

## 2. 资源口径（★同类陷阱：Flash 不等于 RAM★）

| 项 | 常见标称 | 实际可用 | 说明 |
|---|---|---|---|
| Flash | 256 KB / 1 MB | 减去 Bootloader 与文件系统后明显更少 | **代码大小**受它限制 |
| RAM | 20 KB / 64 KB / 520 KB | 减去栈、堆、RTOS 后更少 | **全局数组 / 缓冲区**受它限制 |
| 主频 | 72 / 168 / 240 MHz | 实际有效算力远低于同频 PC | 别按 PC 的直觉估 |
| 定时器/PWM 通道 | 若干 | 引脚复用后可能更少 | 多路 PWM 常被引脚冲突卡住 |

> **`[推断]` 最常见的新手误判**：以为"1 MB Flash 很大"，结果一个浮点库 + 一个协议栈就吃掉大半。

---

## 3. 工具链与最小验证路径

| 环节 | 典型做法 | 关键检查 |
|---|---|---|
| 编译 | 厂商 IDE 或 `arm-none-eabi-gcc` + Makefile | 看 **Flash / RAM 占用百分比**（不是"编译通过"就算成功） |
| 烧录 | ST-Link / J-Link / DAP-Link / USB-DFU / 串口 ISP | 确认烧的是**新编译的那份**（比文件 md5 或看编译时间戳） |
| 最小验证 | LED 闪 + 串口打印一行 | **能打印就说明时钟、时钟树、串口、烧录全对** |
| 调试 | SWD 单步 + 串口日志 + 逻辑分析仪 | 时序问题必须上逻辑分析仪，不要靠 printf |

- **★什么算"构建成功"★**：编译 0 error 0 warning **且** Flash/RAM 占用在预算内 **且** 烧录后能打印版本号（不是"烧录软件说 success"）。
- **冷启动**：断电再上电（很多外设的初始化只在复位时跑一次，热复位可能漏掉）。

## 4. 这类平台的专属坑

| 坑 | 表现 | 怎么避 |
|---|---|---|
| 时钟树配错 | 串口乱码、延时不对、外设全不通 | 先跑"LED 闪 + 串口打印"，通了再上外设 |
| 引脚复用冲突 | 配了 PWM 但另一个功能占了同一引脚 | 画一张引脚占用表，开工前填满 |
| 中断里做重活 | 偶发死机/丢数据 | 中断只置标志，主循环处理 |
| 用 `delay()` 阻塞 | 多任务时互相拖死 | 用状态机 + 定时器节拍 |
| RAM 溢出 | 跑一阵莫名重启 | 看栈水位；大数组用 `static` 或放外部 RAM |
| 浮点运算慢 | 控制环跑不到目标频率 | 改定点；查芯片有没有 FPU |
| 看门狗没喂 | 定期重启 | 喂狗放在主循环最高优先级位置；调试时先关 |
| 烧录的是旧固件 | "改了没效果" | 每次烧完先打印版本号/编译时间 |
| 电源噪声 | ADC 抖动、通信误码 | 模拟地和数字地分开；ADC 采样加多次平均 |

## 5. 交付物检查项

- [ ] 完整工程（含厂商工程文件与源码，不只是 `.hex`）
- [ ] 引脚分配表（**引脚复用是重灾区，必须写**）
- [ ] 时钟树配置（外部晶振频率、各总线分频）
- [ ] 外设初始化参数（串口波特率、I2C 地址、ADC 采样率）
- [ ] 固件 `.hex` / `.bin` + md5
- [ ] 关键指标：Flash 占用 / RAM 占用 / 主循环周期 / 功耗
- [ ] `README_CODE.txt`：哪几个模块是自己写的、各自作用

## 6. 判据怎么写

| 目标 | 可测判据 |
|---|---|
| 通路打通 | 串口每秒打印一行，10 分钟不丢行 |
| 采样精度 | 已知输入下读数误差 < ±X% |
| 控制响应 | 从传感器变化到执行器动作 < X ms（用逻辑分析仪测） |
| 低功耗 | 休眠电流 < X µA，唤醒时间 < X ms |
| 长跑稳定 | 连续 24 小时不重启、不丢数据 |
| 资源 | Flash / RAM 占用 < 预算的 80% |

## 7. 迁移提示（从 FPGA / 软件过来）

1. **别指望并行**：MCU 是一行一行执行的，"同时处理 8 路"要靠时间片。
2. **引脚是稀缺资源**，不是"随便接"——开工前先画引脚表。
3. **实时性是"够用"不是"确定"**：中断延迟有几微秒到几十微秒的抖动，硬实时要用硬件外设（定时器/比较器）。
4. **调试靠串口和逻辑分析仪**，不要靠"感觉"。
5. **功耗是设计出来的**，不是省出来的：休眠策略要在架构阶段决定。
