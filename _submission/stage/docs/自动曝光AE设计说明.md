# 自动曝光 AE —— 设计说明与上板验收（2026-10-12）

> 对应提交：`8c80c2e`（ae_stat + TB）、`99bd620`（ae_ctrl + TB），以及本轮的接线改动。
> 全部 RTL 在 FPGA 内自主实现，不依赖任何片内 MCU 或外部处理器。

---

## 0. 一句话

**原厂的 AE 通路其实已经预置了 90%，唯一真正断掉的是一根线**：`uicfgcs500_720p.v`
把曝光/模拟增益写成了硬编码 `wire`，把同名输入端口完全屏蔽掉了。本轮补齐了这根线，
并新增两个模块：`ae_stat.v`（帧亮度统计，60MHz 域）+ `ae_ctrl.v`（闭环控制，24MHz 域）。

## 1. 为什么 AE 值得优先做

重新精读官方资料（`.extract/选题二.txt`，即 `官方资料\选题二.docx` 的 2.5/2.6 节，
这两节在《选题指南（康芯版）》里没有）后确认：

- **§2.6 一、基础要求（4）**：「**系统稳定性：系统长期运行无花屏、无缓存溢出，光线剧烈变化时工作正常。**」
- **§2.6 二、（二）高阶挑战项（5）**：「**画面自动曝光/白平衡等优化**」。
- **`赛题解析二.pptx` slide23**：「随后通过**自动白平衡**调整红、绿、蓝三个通道的比例，改善画面偏色问题」。
- **slide25 进阶要求 5**：「图像质量自动调节：可探索自动曝光、白平衡或直方图均衡等 ISP 处理，提升画面适应能力。」

⇒ AE **同时命中一条基础要求和一条高阶挑战项**，不是纯加分项。

而改动前的现实是：曝光硬写死 `0x3e00/01/02 = 1990`（= `2×VTS−10`，已顶满），
模拟增益只能靠 SW4 在 4.000×/15.750× 二选一，且**必须断电重启才生效**。
演示现场光照不可控 ⇒ 这是开盲盒。

## 2. 数据通路与统计点

```
I_tdata[39:0] RAW10
   → demosaic(BGGR,1280x720)      128bit
   → data128_96                    96bit (4 像素 × 24bit RGB)
   → ★ae_stat 统计点★ ─────────────► O_luma_sum / O_pix_cnt / O_hi_cnt / O_lo_cnt / O_frame_tgl
   → awb                           （统计点与 awb 是"并联"，只读不写，不产生反压）
   → isp_gamma (S 曲线, 2 拍)
   → my_algo (MODE 0..4)
   → data_96bit_to_128bit
   → hdmi_mixer (OSD) → HDMI
```

**为什么统计点选在这里（`isp_top.v` 里 `u_ae_stat` 的例化处）**：

| 约束 | 理由 |
|---|---|
| **在 `awb` 之前** | AE 与 AWB 解耦。AWB 调增益不会改变 AE 的观测量；反之 AE 调增益也不会让 AWB 的灰世界统计跟着漂 |
| **在 `isp_gamma` 之前** | 拨 SW2 开关 S 曲线不会让 AE 的目标亮度漂移。若统计点在曲线之后，同一个场景在 SW2 上/下会得到两个不同的帧均值，AE 会跟着跳 |
| **与 `awb` 共用同一对 `tvalid`/`tuser`** | `isp_top.v` 里 `data128_96` 只连了 `.I_tdata/.O_tdata` 两个端口，`tvalid` 是 demosaic 那一路。自己另配一对极易错拍；直接复用 awb 消费的那三根，可保证 AE 与 AWB 看到的是同一条码流 |

`ae_stat` 完全被动（没有 `I_tready`），只监听，不影响像素通路。

## 3. 控制律与参数

`ae_ctrl.v` 顶部是完整的 parameter 块，**没有魔法数字埋在逻辑里**：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `TARGET_MEAN` | `8'd70` | 目标帧均值（8bit 线性亮度域）。**唯一需要现场迭代的量** |
| `NOM_PIX` | `32'd921600` | 标称每帧像素数 = 230400 拍 × 4 像素 |
| `EXPOSURE_FIXED` | `16'd1990` | 曝光行数。`2×VTS−10`，720p60 下的上限 |
| `GAIN_IDX_INIT` | `7'd64` | 上电初始档 = `{0x0F,0x20}` = 4.000×（厂商原值，安全默认） |
| `SETTLE_FRAMES` | `8'd60` | 配置完成后先静默 1 秒再开始闭环 |
| `STEP_FAST / MID / SLOW` | `8 / 2 / 1` | 误差 >100% / >25% / 其余 时每帧的索引步进 |
| `HI_GUARD_SHIFT` | `6'd6` | 高光护栏：`hi_cnt > pix_cnt >> 6`（≈1.56%）就**无条件降档**，优先于亮度目标 |
| `LO_GUARD_SHIFT` | `6'd2` | 暗场护栏：`lo_cnt > pix_cnt >> 2`（25%）时**停止加亮**（再加只是放大噪声） |

**决策优先级**（`S_gi_next`）：

```
不允许动作            → 保持
高光超限              → 降档          （护栏优先，哪怕亮度正好在靶心）
亮度偏高              → 降档
亮度偏低 且 非暗场    → 升档
其他                  → 保持（死区 ±4.76%）
```

- **死区**：`DEADBAND = TARGET_SUM / 21` ≈ ±4.76%。
- **零乘法零除法**：`TARGET_SUM = NOM_PIX * TARGET_MEAN` 与 `DEADBAND` 都是 `localparam`，
  在 elaboration 期折叠成常数；运行时只有 40bit 比较与加减。护栏阈值用**移位比较**。
- **收敛速度**：误差 >25% 时每帧走 2 档，进入 25% 以内后每帧 1 档。
  从 4.000× 爬到 15.750× 需要走 63 个索引 ≈ 0.5 秒（30 帧 @60fps）。

### 为什么曝光锁死 1990 不参与调节

720p60 的 VTS = 1000 行，`60fps` 要求帧长恰好 1000 行。曝光到 1990 = `2×VTS−10` 已经是
"一帧曝光跨两帧读出"的极限，再长会让帧率掉到 30fps ⇒ **掉帧**。
所以 AE 唯一可用的**连续**杠杆就是模拟增益。这是物理约束，不是设计取舍。

## 4. 与传感器的接口（不需要任何查表转换）

`uics500regAE.v` 的 `REG_SIZE = 9'd8`，把三个变量直接拆成寄存器字节：

| 索引 | 寄存器 | 内容 |
|---|---|---|
| 0 | `0x3e00` | `{4'h0, exp[15:12]}` |
| 1 | `0x3e01` | `exp[11:4]` |
| 2 | `0x3e02` | `{exp[3:0], 4'h0}` |
| 3 | `0x3e08` | `analog_gain[15:8]` |
| 4 | `0x3e09` | `analog_gain[7:0]` |
| 5 | `0x3e06` | `digital_gain[15:8]`（SW3 控制，AE 不动） |
| 6 | `0x3e07` | `digital_gain[7:0]` |

⇒ `O_exposure_time` 就是**曝光行数**（1990 = `0x07C6`）；`O_analog_gain` 就是
`{3e08, 3e09}` 这个**原始寄存器字节对**，完全不需要查表。

**模拟增益阶梯**（本轮订正）：

- `3e08 ∈ {0x03,0x07,0x0F,0x1F}` = ×1 / ×2 / ×4 / ×8 —— ★注意不是 `0x03<<n`★
- `3e09 ∈ 0x20..0x3F` = ×1.000 ~ ×1.969（32 级，每级约 2.2%）
- ⇒ `{0x0F,0x20} = 4.000×`、`{0x1F,0x3F} = 15.750×`、`{0x1F,0x2D} = 11.25×`
  （最后一个正是历史记录里"下载后几分钟变暗约 10 倍"那个值）
- 再乘 SW3 的数字增益 ×1/×2 ⇒ 总范围 **1.000× ~ 31.500×**

### 一条硬约束

`uicfgcs500_720p.v:83-91` 的握手逻辑是：

```verilog
end else if (I_ae_req)      begin O_ae_cfg_done <= 1'b0; reg_index <= 9'd0; end
else if (!O_ae_cfg_done)    begin if (reg_index == ae_size) O_ae_cfg_done <= 1'b1; else state <= 2'd1; end
```

⇒ **`I_ae_req` 必须是单拍脉冲**。拉高不放会一直复位 `reg_index`，AE 表永远走不完。
`ae_ctrl.v` 里 `O_ae_req` 在每个时钟默认清 0、只在唯一那个分支置 1；
TB 的 CASE 8 专门断言 `max_pulse == 1`。

### ★TB 抓到的两个 DUT 真 bug（值得写进报告）★

1. **决策与下发用了同一个组合表达式**
   `S_gi_next = !S_can_act ? S_gi : ...`，而 `S_can_act` 里含 `!S_req_pend`。
   下发那一拍 `S_req_pend` 已经拉高 ⇒ `S_can_act` 变假 ⇒ `S_gi_next` 组合地"回退"成 `S_gi`
   ⇒ `S_gi <= S_gi`，**增益永远不动**。现象：`req_n = 90` 但 `gain_idx` 恒 64。
   修法：决策时把目标锁存进 `S_gi_tgt`，下发用 `S_gi_tgt`。
2. **`wire S_gi_dec` 忘了写位宽** ⇒ 被推断成 **1 bit** 的线 ⇒ `120−1=119` 被截成
   `119` 的最低位 = `1` ⇒ **增益一帧从 120 掉到 1**。
   修法：`wire [6:0] S_gi_dec`。教训：**任何做算术的 `wire` 都必须显式写位宽**。

另修一处设计缺陷：稳定帧计数器 `S_settle` 原本会被 `I_ae_cfg_done` 清零，
而每次下发 AE 表它都会拉低 ⇒ AE 退化成"每 60 帧才走一档"。已改为只由 `!I_cam_cfg_done` 清零。

## 7. 上板验收步骤

**前置**：烧 `..._Runs/phy_1/camera_to_dsi_display.bit`（AE 版）。
四开关建议：SW1 上（黑电平开）、SW2 上（曲线开）、SW3 上（数字 ×2）、**SW4 上（AE 开）**。

| 步 | 操作 | 检查点 |
|---|---|---|
| 1 | 上电，不动任何开关 | 画面比旧版**暗约 1/4**（预期！初始 8.000×） |
| 2 | 等 1 秒 | 画面**自己变亮**到以前的水平（AE 爬到 15.750×） |
| 3 | 把 SW4 拨**下**，等 1 秒 | 画面**定住**不再变化（AE 冻结） |
| 4 | 把 SW4 拨回**上** | 画面重新开始爬（若已经在顶档则不动，属正常） |
| 5 | 关掉房间的灯，只留显示器 | 画面**明显变亮**（AE 加增益） |
| 6 | 打开灯 / 拿手电照镜头 | 画面**明显变暗**、不再一片白（AE 降增益），且**没有削顶白块**（高光护栏生效） |
| 7 | 用 `_analysis/scripts/stat_imgs.py` 统计第 5、6 步的截图 | Ymean 应落在 **65~85**（目标 70、死区 ±4.76%、加上曲线影响）；`>=250` 占比应 **< 2%** |

**失败排查**：

| 现象 | 看哪里 |
|---|---|
| 第 2 步画面不变亮 | `AE 表有没有下发` → 用 ChipWatcher 抓 `u_ae_ctrl/O_ae_req`、`O_gain_idx`、`O_state`；`O_state` 应为 2（闭环） |
| `O_state` 恒 0 | `S_cam_cfg_done` 没来，或 AE 表握手卡住（查 `O_ae_req` 脉冲宽度是否 1 拍） |
| `O_state` 恒 1 | 稳定计时器没走完（`S_settle` 被反复清零） |
| `O_state` = 3 | `I_ae_en = 0`，即 SW4 没拨上（LED4 应不亮） |
| 高光时画面一片白 | `HI_GUARD_SHIFT` 调小（例如 7 → 更灵敏），或 `TARGET_MEAN` 调低 |

## 8. 已知边界与限制

1. **室内目标 70 大概率够不着**。02:18 开灯室内实测：31.500×（= 模拟顶档 × 数字 ×2）、
   曲线旁路（线性域）下整帧 Y 均值只有 **58.0**。⇒ AE 会**一直贴在最高档**，
   目标 70 形同虚设。**这不是 bug，是光照不足**——"想更亮"的杠杆是加光，不是 AE。
   目标 70 的价值体现在**白天靠窗**等明亮场景：那时 AE 会主动往下调。
2. **掉帧风险**：曝光已顶满，AE 只动增益 ⇒ 不改变帧长 ⇒ 不影响 60fps。
3. **增益档位是量化的**：相邻档 1.6%~3.1%，所以 AE 收敛后会有 ±1 档的稳态抖动，
   死区（±4.76%）已覆盖这个量级，正常运行不会来回跳。
4. **准静态 CDC 未做握手**：`ae_stat` 的 5 组输出每帧只变一次、保持约 16.7ms；
   `ae_ctrl` 用 `O_frame_tgl` 的翻转沿（内部 2 级同步 + 边沿检测）采样，
   采样时刻比数据变化晚 3 个 24MHz 周期（125ns），相对 16.7ms 的保持时间余量约 13 万倍。
   这条路径已在 SDC 里加了 `set_max_delay -datapath_only ... 20.000` 兜住绕线。
5. **验证过但还没上板**：`ae_ctrl`/`ae_stat` 目前只有 ModelSim 级别的验证，
   上板行为（尤其真实 I2C 下发节奏）待第 7 节的 7 步走完再确认。

## 9. 顺带治好的老问题

「**下载后几分钟画面变暗约 10 倍**」这个悬了很久的现象，最可能的解释是
**传感器寄存器掉回上电默认**：模拟增益从 11.25×（`{0x1F,0x2D}`）掉到 1.000×（`{0x00,0x20}`），
比值 11.25 与实测的约 10.4 倍吻合。工程只在开机初始化时写一次，之后再没人写回去。

**AE 上线后这类漂移会被闭环自动纠正** —— 只要增益掉了，下一帧的亮度统计就会偏低，
AE 立刻补回去。这是 AE 除了"适应光照"之外的第二个实际收益。

另有一条待修的小隐患：`uics500reg_720p60.v` 的 init 表在索引 0 写软复位 `0x0103=0x01`
之后**没有任何等待**就写索引 1（只有索引 115 之后才有延时）。建议后续加 `POST_RESET_DELAY`。
