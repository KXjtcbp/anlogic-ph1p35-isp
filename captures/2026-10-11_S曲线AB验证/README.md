## 同时暴露的三个问题

### D1 这条 LUT 是"反 S"（降对比），不是赛题要求的 S 曲线
- 160 以下 `y = 160*(x/160)^0.5`：凹函数 -> **抬暗部**
- 160 以上 `y = 160+95*(1-((255-x)/95)^0.5)`：也是凹的 -> **压高光**
- 两侧都压缩 ⇒ **对比度下降**，画面发灰发闷（"糊成一团"的主因）。
- 用户最初的需求（m00002）是"**压暗部、提高光、保留中间调**"，即真正的 S 曲线。
  更早的 `p118_k125`（指数 1.25）才是真 S 曲线，被 `p160_a050` 取代后方向反了。

### D2 黑场丢失
- `<=8` 的像素占比：10 号 **3.082%** -> 11 号 **0.082%**（后者只剩真正的 0）。
- 曲线底部 `y(1)=13, y(2)=18, y(3)=22` 把传感器噪声底抬成可见灰。
- 视觉证据：10 号右侧近黑区域在 11 号变成一片平灰。

### D3 白平衡残差 11%（线性域）
- 10 号是**唯一一张开关状态已知的曲线旁路图**，所以它的通道比就是 AWB 之后的线性域真值：
  - `R=32.88 G=36.87 B=34.65`  ⇒ **R/G = 0.8919, B/G = 0.9399**
- 灰世界 AWB 的目标是 1.0000（已由 `tb_awb_means.v` 仿真证明该模块算法本身精确正确）。
- ★**已由仿真证实（2026-10-11 20:33，`tb_awb_zones.v`，Elapsed 0:26:12）**★
  `awb.v` 的增益是**逐行递推**的（`sum_*` 在 `I_tuser` 清零，`done` 每拍更新），
  所以第 N 行用的是第 0..N 行的累计比 —— **运行中的非稳态增益无法归一化整帧均值**。
- 分区分帧测试（H=8；上 4 行 R=60、下 4 行 R=140，G=B=100，**帧输入均值 R/G 恰为 1.0000**）：
  ```
  MODE 0 对照（整帧 R=G=B=100）    in R/G=1.0000 -> out R/G=1.0000   gainR=10000  OK
  MODE 2 对照（整帧 R=60）         in R/G=0.6000 -> out R/G=0.9900   gainR=1aaaa  OK
  MODE 1 分区（帧均值 R/G=1.0000） in R/G=1.0000 -> out R/G=1.3396   偏 34%
  ```
  MODE 1 的逐输出行 R/G：`0.9900, 0.9900, 0.9900, 1.9633, 1.6280, 1.4567, 1.3591`
  —— 增益在帧内**先过冲再回落**，是一条明显的斜坡。
- ⇒ **均匀帧能被正确归一化（0.9900），有纵向色偏的帧不能（1.3396）。**
  这是 `awb.v` 的一个真实、可修的缺陷，不是参数问题。
- 修法方向（尚未实施）：① 增益**不要**在 `I_tuser` 清零（`awb.v:281-296` 目前每帧把
  `in_r_r1/in_b_r1` 复位成 `20'h10000`，导致第 0 行永远未校正）；② 加**阻尼**
  `g += (target - g) >>> N`（N≈4~6），使增益在单帧内近似恒定 —— 这同时顺带解决了
  传感器自动曝光剧烈游走时白平衡"追不上"的问题；③ 把增益钳到 `[0.5x, 4x]`。
- TB 源码：`E:\FPGA\_analysis\sim\awb\tb_awb_zones.v`；日志 `_analysis\out\_tb_awb_zones_raw.log`。
  ★踩坑★：第一版把像素打包写成 `{8'h00, r, 8'h64}`，变化值落进了 G 通道、`inR` 恒为 0，
  整个 R 通道测试是空的（表现为 `gainR=fffff` 饱和）。正确打包 = `{r, 8'h64, 8'h64}`。
