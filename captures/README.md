### 2026-10-11 12:49–12:50 三张（模块 A 取证）—— ★这组图定不了黑电平★
1. CNT `004476 → 004714 → 006592`，帧差对应 3.97 s / 31.3 s，与墙钟 4 s / 31 s 逐段吻合 ⇒ 同一次上电、无复位、无人动过电；三张 `MODE 0`。
2. **★原始截图没有记录开关状态★**（那个时点 SW1–SW4 的位置没有任何记录）。因此归档文件名一律写「开关未记录」，**事后不得补填一个状态上去**——这组图的价值恰恰在于它暴露了"采集时不记开关，事后就无法解读"。
3. 盖镜头那张 Y 均值 **40.521**、p50 41、std 2.74、max 60，R/G 0.9552、B/G 0.9650。
   曲线内联表 = `gamma_lut_twoseg_p160_a050.hex`，反推：`x = 160 × (40.52/160)² = 10.26`（8bit，曲线输入端）。
4. 能产生"曲线输入 ≈ 10"的组合有**四个**，单凭这一张图分不开（基座可能是 41，也可能是 217）：

   | 世界 | SW1 / SW2 | 需要的 raw10 基座 |
   |---|---|---|
   | A | 下(旁路) / 上(曲线开) | **41**（`41>>2 = 10` → `gamma[10] = 0x28 = 40`） |
   | B | 上(BL=56) / 上(曲线开) | **94…97**（`(95−56+2)>>2 = 10`） |
   | C | 下(旁路) / 下(曲线关) | **162…165**（`162>>2 = 40`） |
   | D | 上(BL=56) / 下(曲线关) | **214…217**（`(215−56+2)>>2 = 40`） |

5. **但四个世界里把 `BLACK_LEVEL` 从 56 改成 42 都不会让 40.5 变黑**：A、C 里 BLC 不在通路上（改常数**零作用**）；B 里 `(95−42+2)>>2 = 13` → `160·√(13/160) = 45.6`（**更亮 5 码**）；D 里 `(215−42+2)>>2 = 43`（**更亮 3 码**）。
   ⇒ **无论拨码在哪一档，把 56 调小到 42 要么没影响、要么让黑底更亮，永远不可能变黑。** 这就是 2026-10-11d 那次改动的根因错误：把"旁路（或漏光）条件下**读到**的画面亮度"当成了"黑电平**常数该设**多大"。这条结论不需要知道当时的开关状态就成立。
6. 顺带纠正上一版 README 的一个说法：**"盖住镜头"不等于纯黑**。这张图和 01:37 那张都受遮光不严影响，真正能定位基座的是直接抓 RAW10 域（10-09 ChipWatcher：盖镜头时值域 `[57..79]`、均值 67.02）。

### 四档盖镜头（02:00）结论
1. **四档的 8bit 黑电平均为 0~1 码**（R/B 恒 0，只有 G 高约 1 码）⇒ 当前比特流下画面黑就是 0，**链路上没有可见的基座**。
2. 但 **SW1 的状态未确认**，两种世界都能产生"0~1 码"：
   - SW1 **下**（`I_blk_bypass=1`，直通）：读数 = raw/4 ⇒ 传感器基座 ≈ 0~7 个 raw10；
   - SW1 **上**（启用扣除，常数 56）：读数 = (raw−56+2)/4 ⇒ 基座 ≈ 54~61 个 raw10（与 10-09 实测 57~79 一致）。
   两者的原始基座差 50 多个 raw10，**只有再做一次"明确 SW1 拨下 + 盖镜头 + 单档"的采集才能定论**。
3. 01:37 那张"盖住镜头"读到 53.7 码（曲线前 ≈18 码 ⇒ raw10 ≈72）**与本次四张矛盾**，判为**遮光不严（漏光）**，不能再当作黑电平依据。
4. 由此推翻一个假设：**曲线底部的抬升不是"把基座抬成灰"**——既然黑就是 0~1 码，曲线对 2~8 码的抬升提的是真实暗部信号。所以"给曲线加线性趾"这个候选（`_analysis/scripts/gen_gamma_lut_toe.py`，表在 `_analysis/lut/candidates/`）**已评估后否决**，未写入 RTL。
5. 四张图 CNT 连续（084848→085414，间隔 3.05/3.52/2.87 s = 59.5~60.5 fps）⇒ **同一次上电、无复位，四档增益实时切换成功**；CNT 084848 ≈ 1414 s ≈ 23.6 min，与 01:37 那组（3923/6823/10850）同一次上电（20 min 差对应 73998 帧）。
