```

                            │      (RAW10 ×4 像素/拍 → 8bit ×4)
```

## 2. 为什么必须回退 42 + SW1 反相

### 2.1 证据一：10-11d 把「旁路域**读到**的画面亮度」当成了「黑电平**常数该设**多大」

`Screenshot 2026-10-11 12-50-24.png`（盖镜头，遮掉 OSD 后）实测：
**Y 均值 40.521、中位 41、std 2.74、max 60**，R/G=0.9552、B/G=0.9650。

同一次上电的另外两张（12-49-49 室内常光、12-49-53 直看光源）把 OSD 文本区裁出来放大后可读：
`CNT:004476` / `CNT:004714` / `CNT:006592`，三张全是 `MODE 0`。
相邻两两差 **238 帧**和 **1878 帧**，@60 fps = **3.97 s** 和 **31.3 s**，
与墙钟间隔 12:49:49→12:49:53（4 s）、12:49:53→12:50:24（31 s）吻合
⇒ **三张同属一次连续上电，中间没有复位、没有人动过电。**
（裁图脚本 `_analysis/scripts/_crop_osd_triple.py`，结果 `_analysis/out/osd_1211_triple.png`。）

曲线内联表 = `gamma_lut_twoseg_p160_a050.hex`（脚本已逐条核对 256/256 一致），
`x ≤ 160: y = 160·(x/160)^0.5`。把 40.52 反推回曲线**输入端**：

```
x = 160 × (40.52 / 160)² = 10.26      (8bit, 曲线输入)
```

**但 10.26 只说明"曲线输入端约等于 10"这一个事实。** 四种（BLC × 曲线）组合里，能产生 Y≈40.5 的有：

| 世界 | SW1 / SW2 | 需要的 raw10 基座 | 验算 |
|---|---|---|---|
| **A** | 下(旁路) / 上(曲线开) | **41** | `41>>2 = 10` → `gamma[10] = 0x28 = 40` ✓ |
| **B** | 上(BL=56) / 上(曲线开) | **94…97** | `(95−56+2)>>2 = 10` → `40` ✓ |
| **C** | 下(旁路) / 下(曲线关) | **162…165** | `162>>2 = 40` ✓（曲线旁路时 `Y = raw/4`） |
| **D** | 上(BL=56) / 下(曲线关) | **214…217** | `(215−56+2)>>2 = 40` ✓ |

⇒ **四个世界都活着，单凭这一张图判不出来。** 基座可能是 41，也可能是 217 —— 差 5 倍。

**真正硬的是下一条 —— 在全部四个世界里，把 `BLACK_LEVEL` 从 56 改成 42 都不会让这个 40.5 变黑：**

| 世界 | 改成 BL=42 之后 | 效果 |
|---|---|---|
| A | BLC 不在通路上 | **零作用** |
| B | `(95−42+2)>>2 = 13` → `160·√(13/160) = 45.6` | **更亮 5 码** |
| C | BLC 不在通路上 | **零作用** |
| D | `(215−42+2)>>2 = 43` | **更亮 3 码** |

**⇒ 无论拨码在哪一档，把 `BLACK_LEVEL` 从 56 调小到 42，要么毫无影响，要么让黑底更亮。
它永远不可能让黑底变黑。** 这就是 10-11d 那次改动方向必然错误的原因 ——
而这条结论**与"当时开关到底在哪一档"无关，不需要那个信息就成立**。
（即便按用户的记忆"当时四个开关都拨下"，即世界 C，结论也一样：BLC 被旁路，改常数零作用。）

> ⚠️ 10-11d 的补丁注释声称"当时 SW1 下（直通）、SW2 上（曲线开）"，
> 但这个断言**没有独立证据**：没有任何一条记录写下过 12:49–12:50 那一刻的拨码位置。
> 40.52 唯一能确定的是"曲线输入端 ≈ 10"，**不是"SW1 在哪一档"**。
> 本方案第 8 节的 V 矩阵因此把"开关状态"列为必须先记录的字段。

**⇒ 10-11d 的根因错误**：它把一个「旁路（或漏光）条件下拍到的画面亮度」
直接当成了「黑电平常数应该设多大」。观测基座回答的是"**基线在哪**"，
不是"**应该扣多少**"。

**⇒ 而且这个 40.5 本来就不适合当黑电平依据。** 镜头没盖严时，漏进来的光会被算进基座。
真正能定位基座的是直接抓 RAW10 域 —— 见 `mipi_to_raw_converter.v` 注释里
2026-10-09 的 ChipWatcher 记录：**盖住镜头时值域 `[57..79]`、均值 `67.02`**。
那是目前唯一一次在**扣除之前**、对**真实像素流**的直接测量。

### 2.2 证据二：四张盖镜头增益梯证明 BL=56 已经"够用"

`captures/2026-10-11_标定/黑电平_*.png`（01:59–02:00，四档增益连续采集、CNT 084848→085414 无复位）：

| 图 | 增益 | Y 均值 | `Y==0` 占比 |
|---|---|---|---|
| `黑电平_4.000x_两下.png` | 4.000× | 0.00 | **99.894%** |
| `黑电平_8.000x_SW3上.png` | 8.000× | 0.01 | **99.471%** |
| `黑电平_15.750x_SW4上.png` | 15.750× | 0.07 | **93.720%** |
| `黑电平_31.500x_两上.png` | 31.500× | 0.30 | **76.532%** |

这些图 Y≈0 —— **只可能出现在「BL=56 扣除启用」的世界**。
若当时是旁路，基座 42 会读出 `gamma[10]=40`（曲线开）或 `10`（曲线关），
400 万像素里不可能有 99.9% 是 0。

⇒ **BL=56 在四档增益、从 1 倍到 7.87 倍噪声放大的条件下，都把基座牢牢压到 0。它是"够用"的。**

### 2.3 证据三：BL=42 的余量是 0 码，会被曲线趾部放大 13 倍

| | BL=42 | BL=56 |
|---|---|---|
| 对实测基座 42 的余量 | **0 个 raw10 码** | 14 个 raw10 码 |
| 基座漂到 44 时 | 8bit 出现 1 码 | 仍为 0 |
| 该 1 码经 S 曲线后 | `gamma[1] = 0x0d = **13**` | — |
| 对「基座 67~72」世界的输出 | 33 / 36 | **23 / 27** |

曲线的趾部斜率 `gamma[1]/1 = 13`，等于把 BLC 的余量问题**放大 13 倍**。
BL=56 的代价只是把 raw10 44…57 钳到 0 = 3.5 个 8bit 码 = **1.4% 的暗部**，肉眼不可见。

**⇒ 56 在「基座 42」和「基座 67~72」两个候选世界里都优于 42。选 56 是稳健解。**

![BLC + S 曲线合成响应](out/blc_module_a.png)

*左：全量程合成响应。右：暗部放大——蓝线（旁路+曲线开）在 raw10 41–43 处正好给出 Y=40，与 12:50 实测 40.52 逐码吻合；红线（BL=56）直到 raw=57 才离开 0；橙线（BL=42）在 raw=43 就开始冒头，raw=56 时已经爬到 25。*

## 3. 模块 A 定版 RTL

### 3.1 已落地的实现（当前源码，仅展示核心）

`isp/demosaic_4x_2_0/mipi_to_raw_converter.v`（**GBK 编码**，勿存成 UTF-8）：

```verilog
module mipi_to_raw_converter #(
    parameter [9:0] BLACK_LEVEL = 10'd56   // [HDR-2026-10-11e] 黑电平扣除（10bit RAW 域）
                                           //   标定依据：2026-10-09 ChipWatcher 盖住镜头时
                                           //   RAW10 值域 [57..79]、均值 66~67 ⇒ 取最小值-1 = 56
)(
    ...
);

wire [9:0] S_blk_level = BLACK_LEVEL;

// ★ 模块 A 核心：逐像素 clamp(in - black_level) ★
//   4 个像素字段各自独立，raw10 减法 + 饱和 + 四舍五入补偿(ROUND_ADD=2，即 4/2)
wire [9:0] S_blk_f0 = I_blk_bypass ? I_raw_tdata[ 9: 0]
                    : (((I_raw_tdata[ 9: 0] > S_blk_level) ? (I_raw_tdata[ 9: 0] - S_blk_level) : 10'd0) + ROUND_ADD);
wire [9:0] S_blk_f1 = I_blk_bypass ? I_raw_tdata[19:10]
                    : (((I_raw_tdata[19:10] > S_blk_level) ? (I_raw_tdata[19:10] - S_blk_level) : 10'd0) + ROUND_ADD);
wire [9:0] S_blk_f2 = I_blk_bypass ? I_raw_tdata[29:20]
                    : (((I_raw_tdata[29:20] > S_blk_level) ? (I_raw_tdata[29:20] - S_blk_level) : 10'd0) + ROUND_ADD);
wire [9:0] S_blk_f3 = I_blk_bypass ? I_raw_tdata[39:30]
                    : (((I_raw_tdata[39:30] > S_blk_level) ? (I_raw_tdata[39:30] - S_blk_level) : 10'd0) + ROUND_ADD);

always @(posedge I_clk) begin
    raw_data_r0 <= {S_blk_f0[9:2], S_blk_f1[9:2], S_blk_f2[9:2], S_blk_f3[9:2]};  // 10bit -> 8bit
end
```

**为什么是 `+2` 再 `>>2`**：10bit→8bit 要除 4。不补就直接截断（偏暗 0~3 码）；
补 2（= 4/2）是标准四舍五入。这一级是**原有寄存器**，BLC 与它合并 ⇒ **零额外延迟**。

### 3.2 同步信号打拍（★已按实际 RTL 更正，旧文档差 1 拍★）

| 信号 | 本级延迟 | 说明 |
|---|---|---|
| `raw_data_r0[31:0]` | 1 拍 | 与 `S_blk_f*` 同拍寄存，**不新增延迟** |
| `raw_tlast` / `raw_tuser` / `raw_tvalid` | 1 拍 | 各自独立的一级寄存器，与数据同相 |
| `raw_tready` | 0（组合） | `assign I_raw_tready = O_raw_tready;` 全链路无真反压 |

**与下游 `isp_gamma`（模块 B）的关系**：`isp_gamma` 是 **2 拍**流水
（`rom_q/d1/v1/l1/u1/b1` 为第 1 级，`q2/v2/l2/u2` 为第 2 级；`b1 ? d1 : rom_q`）。
它的 `tvalid/tuser/tlast` 走同一组寄存器链，天然与数据同相；
`I_tready` 照抄 `awb.v:513` / `my_algo.v:96` 的**组合直通**写法 —— 本级绝不能停拍，停拍必丢 beat。

顺序上 **A 在 B 之前**（BLC 先扣基座，S 曲线再做色调映射）。反过来做会把基座也送进曲线趾部，
正是 12:50 那张 40 码灰底照片的成因。

### 3.3 动态档位版（为扩展加分项预留；当前未启用，默认仍走 `BLACK_LEVEL` 常数）

`_analysis/lut/blc/blc_levels_pkg.vh` 给出 16 档（`level = 40 + 2·index`，index 8 → 56）：

```verilog
wire [9:0] S_blk_level = S_blc_dyn_en ? blc_level_of(S_blc_idx) : BLACK_LEVEL;
```

零成本：`blc_level_of` 是 16 路 10bit 常数选择 = 一个 4→10 的 LUT 网络，约 10~20 个 LUT，
无 ERAM、无 DSP、无额外流水级（`S_blk_level` 进的是组合比较器，不引入新寄存级）。

## 4. 参数寄存器映射建议（扩展加分项接口）

### 4.1 现状：物理拨码（已实现，无需 MCU）

| 开关 | 引脚 | 逻辑电平（拨下=1） | 功能 | 拨上(0) | 拨下(1) |
|---|---|---|---|---|---|
| SW1 | A4 | 实测极性 | **黑电平扣除使能** | **启用扣除** | **旁路**（= 10-09 老行为） |
| SW2 | B4 | 实测极性 | **S 曲线使能** | **启用曲线** | **旁路** |
| SW3 | E11 | 实测极性 | 数字增益 ×2 | 关 | 开 |
| SW4 | D11 | 实测极性 | 模拟增益 11.25× | 4.000× | 11.25× |
| K1–K4 | D5/A9/B9/C7 | 按键 | `my_algo` 算法 MODE 0–4 | — | — |

同步：SW1/SW2 在 `S_csi_rx_clk` 域两级同步；SW3/SW4 在 `S_24m_clk` 域两级同步。
`PULLTYPE=PULLUP` ⇒ 悬空/未插读 1 ⇒ 旁路 ⇒ 老行为 = 安全默认。
`O_led = {S_sw4_sync1, S_sw3_sync1, S_sw2_sync1, S_sw1_sync1}`，
上电时 LED1–LED4 **全亮** = 四个开关都是 1（拨下），可当静态接线自检。

### 4.2 建议的「参数寄存器」抽象层（`isp_param_reg.v`，草案）

把「谁改参数」和「参数是什么」解耦，为 OSD 数值显示 + 后续 MCU/上位机预留：

```
地址  位域              名称              复位值   说明
0x40  [0]               blk_en            1'b0    0 = 启用黑电平扣除, 1 = 旁路
0x40  [1]               gamma_en          1'b1    0 = 启用 S 曲线,    1 = 旁路
0x40  [2]               blc_dyn_en        1'b0    1 = 用 blc_level_idx 而不是常数 56
0x40  [7:4]             blc_level_idx     4'd8    黑电平档位（0..15 → 40,42,...,70）
0x41  [3:0]             gamma_curve_sel   4'd0    0=p160_a050 1=p118_k125 2=纯 1/2.2 3..F=预留
0x42  [7:0]             blc_manual_ofs    8'd0    在档位基础上再 ±偏移（有符号，细调）
0x43  [7:0]             osd_param_page    8'd0    0 = 不显示参数行；1..N = 显示第 N 页
```

**优先级（高 → 低）**：
`DIP 拨码开关` > `按键/OSD 菜单` > `寄存器默认值`。
即：只要 SW1 拨下，无论寄存器说什么都旁路 —— 保证评委现场误操作后能一键回到安全状态。

**写通路（关键合规点）**：赛题原文「参赛作品中所展示的所有算法、控制逻辑及数据处理流程
应在 FPGA 中自主编程实现，**不得带有额外处理器**」。因此参数寄存器必须由
**FPGA 内部逻辑**驱动（拨码开关两级同步器 / 按键去抖计数器 / OSD 状态机），
**不能用片内 RISC-V 硬核、也不能外挂 MCU**。本工程已有的 I2C 写通路
（`uicfgcs500_720p`，运行时下发曝光/增益）就是纯 FPGA 逻辑实现的，**同一套机制可以复用到参数寄存器**。

### 4.3 与 OSD 的衔接（下一步就做这个，投入产出比最高）

`hdmi_mixer.v` 现在是三层：红三角 logo + 黄色 `安路 CNT:xxxxxx` + 亮绿 `MODE n`。
在里面加一行 **白/青色参数行** 就能凑齐「实时参数调节与 OSD 信息叠加」这条扩展要求：

```
BLC 56 S-CURVE ON  GAIN 31.5x  MODE 3
```

字模用现成的 `osd_char_lib.v`（16×16 点阵），窗口复用 `COLOR_DYN_TEXT` 的参数化写法。
**注意 OSD 每多一行，`hdmi_mixer` 的像素域组合深度就多一层** —— 这块正是 10-10 那次
`HDMI_PIXEL_CLK` 域 28 个违例的来源，必须复用 `mult0_syn_*` 那套已修好的写法，不要新开乘法。

### 6.2 ★四个必须避开的坑（TB 侧，全部实际踩过）★

**坑 1：40 bit 字面量写 12 个十六进制位会被静默截断。**
`40'h0A2_13F_001_3FF`（12 位十六进制 = 48 bit）不会报错，只在编译时给一句
`(vlog-2600) [RDGN] - Redundant digits in numeric literal`，然后**悄悄丢掉高 8 位**。
第一版 TB 因此产生 1029 个 FAIL，看起来像 DUT 算错。
⇒ 40 bit 一律写成 4 个 10 bit 拼接：`{10'h0A2, 10'h13F, 10'h001, 10'h3FF}`。
10 bit 字段的位宽在源码里一眼可数，不会写错。

**坑 2：参考模型的字段顺序与 DUT 相反。**
DUT 是

```verilog
raw_data_r0 <= {S_blk_f0[9:2], S_blk_f1[9:2], S_blk_f2[9:2], S_blk_f3[9:2]};
```

而 `S_blk_f0` 取自 `I_raw_tdata[9:0]`（**最低位**字段）。
⇒ **输出的最高字节对应最低的输入字段**。TB 必须写

```verilog
exp4 = { exp_one(v[ 9: 0], byp), exp_one(v[19:10], byp),
         exp_one(v[29:20], byp), exp_one(v[39:30], byp) };
```

写反的症状是**逐字节镜像**：`got=f200ee13 exp=13ee00f2`。
它看起来像"全错"，其实是顺序问题 —— 如果只盯着一个字段调试会浪费很多时间。

**坑 3：NBA 采样 —— 只写 `@(posedge clk)` 会读到上一拍。**
`@(posedge clk)` 在 active region 就恢复执行，而 DUT 的 `raw_data_r0 <= ...`
是 NBA，要到**同一时间步的 NBA region** 才更新。于是 TB 读到的是上一拍的值。
危害最隐蔽的地方在于：**数据不变时"看起来是对的"**（因为上一拍的值恰好相同），
只有某个拍真的发生变化时才暴露 —— 例如 CASE 6 热切换 bypass 报
`FAIL hot-switch(1) got=f2f2f2f2 exp=ffffffff`，而 CASE 1–5 全过。
⇒ 采样一律写 `@(posedge clk); #1;`。

**坑 4：不要用 `.bat` 包 ModelSim 命令。**
写一个含中文注释的 UTF-8 `.bat` 再 `cmd /c` 跑，cmd 完全不认 UTF-8，
会把注释里的汉字拆成单字节命令，报一屏
`'o' is not recognized as an internal or external command` /
`'work\' is not recognized` / `The system cannot find the path specified.`，
真正的错误被淹没。⇒ 直接在 PowerShell 里依次调用 `.exe`。

### 6.3 TB 覆盖判据

每条都必须 0 错误才算模块 A 通过：

1. 复位后输出确定（无 X）
2. 11 个手算锚点，特别是 **56 / 57 / 58 三点**（`BLACK_LEVEL` 边界）
3. 0…1023 全量扫描 × 4 字段 = 4096 个值
4. `bypass=1` 时**逐位等于** `v >> 2`（等同回退到 10-09 版本）
5. 四个像素字段互不串扰
6. 运行时热切换 bypass 立即生效、拍数不变

### 6.4 DUT 端口清单（写 TB 时直接照抄）

```

  I_clk, I_rst_n, I_blk_bypass
  I_raw_tdata[39:0], I_raw_tdest[9:0], I_raw_tlast, I_raw_tvalid, I_raw_tuser
```

### 7.2 与「LUT < 15%、ERAM < 30%」这条自定预算的对照（必须如实说明）

**这条预算以官方底座为基准就不成立**，不是本次改动造成的：

| 资源 | 官方 lab3 底座（10-09） | 现状 | 自定预算 | 判定 |
|---|---|---|---|---|
| `#eram` | 39 / 108 = 36.1% | 51 / 108 = 47.2% | < 30% | **底座单独就已 36%**（DDR / MIPI / HDMI 控制器占用） |
| `#slice*` | 13 862 / 21 216 = 65.3% | 13 966 / 21 216 = 65.8% | — | 底座单独就已 65% |

⇒ **真正的红线只有三条**：(a) 不溢出；(b) 时序收敛；(c) 给后续模块留余量。
现状三条全过。ERAM 47% 距离 100% 还有 57 块的余量，够再放 4~5 个 256×8 的表。

### 7.3 若将来 ERAM 真的吃紧：把 S 曲线改成 16 段折线（记录备选，暂不做）

12 张 256×8 表 = 12 × 20 480 bit 的 ERAM20K 块，实际只用了 24 576 bit（**效率 10%**）。
原因是 96bit/拍的并行度要求**每拍 12 个独立查表口**，无法用一块 ERAM 时分复用。
替代方案：**16 段分段线性（PWL）** ——

- 16 个断点 × 8bit = 128 bit 存 `localparam`（零 ERAM）
- 每级：段选择（4bit 比较链）+ 一次 `slope × dx >> shift`
- 代价：约 300~500 个 LUT（当前 `#slice*` 有 7 250 个 slice 余量，放得下）
- 精度：p160_a050 是 α=0.5 的幂函数，16 段线性逼近的最大误差约 ±2 码，肉眼不可见

⇒ 需要时这是一个**能一次还掉 12 块 ERAM** 的杠杆，写进报告的"资源优化"一节。
