## 1. 改动 A —— S 曲线黑位恢复（`isp_gamma.v`）

### 1.1 位置
`isp_gamma.v` 的 `initial begin ... end` 里 `mem_b00[0..255]` 的 256 条内联初值
（本次改动后在文件 **第 128 行起**；`mem_b01..mem_b11` 由紧随其后的 `for` 循环整体复制，
所以只改一处、12 路严格同表）。

### 1.2 为什么改

改动前生效的表是 `p160_a050`（两段幂函数，`P=160, A=0.50, B=0.50`）。
它的两端都是**凹**的：`x<160` 时 `y=160·(x/160)^0.5`（抬暗部），`x>160` 时同样凹（压高光）。
两点后果：

1. **黑场丢失**。表底 `y(1)=13, y(2)=18, y(3)=22`。传感器在暗部的噪声底（raw≈1~10）
   被映射成 13/18/22 这样的可见灰。
   S 曲线 A/B 实测（`captures/2026-10-11_S曲线AB验证/`）：
   `<=8` 的像素占比从 **3.082%（曲线旁路）掉到 0.082%（曲线启用）** —— 即除了纯 0，
   1~8 码全空，暗部整片被抬成平灰。
2. **两侧都压缩对比**，所以严格说它是**反 S**，不是赛题要求的 S 曲线。
   赛题/需求原文是"压暗部、提高光、保留中间调"；`p160_a050` 恰好相反。

### 1.3 改法与关键数值

```
soft:  new[x] = round( p160(x) − K·(1 − p160(x)/255)² )     K = 24（默认）
```
阴影加权扣减：`x` 越暗 `(1 − x/255)²` 越大、扣得越多；高光处几乎不动。
（备选 `affine: new[x] = (p160(x) − K)·255/(255 − K)`，整体更暗、对比更强；
见生成脚本 `--mode affine`。）

| 输入 | 改前 | 改后 | 说明 |
|---|---|---|---|
| 0 | 0 | 0 | |
| 1 | 13 | **0** | 噪声底归零 |
| 2 | 18 | **0** | |
| 3 | 22 | 2 | |
| 4 | 25 | 5 | |
| 8 | 36 | 18 | |
| 13 | 46 | 30 | |
| 16 | 51 | 36 | |
| 34 | 74 | **62** | 中间调（±16%） |
| 64 | 101 | 92 | |
| 96 | 124 | 118 | |
| 128 | 143 | 138 | |
| 160 | 160 | 157 | |
| 200 | 183 | 181 | |
| 255 | 255 | **255** | 强制保持 |

改动后 256 个输入映射到 **190 个不同输出**（改前 192），仍严格单调不减。

### 1.4 预期上板效果
* 暗部重新"黑得下去"，画面不再整体蒙一层灰 —— 对比度主观提升。
* `Y mean` 会下降（同一场景约 −10%~−18%），这是**预期**而不是变暗故障；
  因为原来是把黑位当亮度加在了整幅画面上。
* 若觉得太暗：把 `K` 调小（如 12）或改用 `--mode affine` 的更大 K，重跑脚本即可。

## 2. 改动 B —— AWB 增益帧锁存 + 阻尼 + 钳位（`awb.v`）

### 2.1 位置
`...\hdl_source\isp\awb\awb.v`
* **新增声明与函数**：紧接 `reg [19:0] in_b_r4;` 之后（改后 `:279-322`）——
  `WB_GAIN_MIN/MAX`、`WB_DAMP_SHIFT`、`in_r_tgt1..4`/`in_b_tgt1..4`、
  `S_tuser_d`/`S_tuser_rise`、函数 `wb_clamp_gain()` / `wb_damp_gain()`。
* **替换 4 个增益 always 块**（原 `:281-296 / :298-313 / :317-332 / :337-352`，4 通道同构）。

### 2.2 改动前（原厂实现）

```verilog
always @(posedge I_clk or negedge I_rst_n)begin
    if(!I_rst_n || I_tuser)begin
        in_r_r1 <= 20'h10000;  in_b_r1 <= 20'h10000;   // 帧首把增益复位成 1.0
    end
    else if(done[0])begin
        if(|in_r_x1[47:20]) in_r_r1 <= 20'hfffff;      // 上限 ≈16.0x
        else                in_r_r1 <= in_r_x1[19:0];  // 用「第 0..N 行累计比」直接覆盖
        ...
    end
end
```

### 2.3 为什么改（有实测证据，不是推测）

`awb.v` 的**算法**没错 —— `tb_awb_means.v` 用整帧恒定 `R=80 G=100 B=90`
（输入 `R/G=0.8000`）跑出来的输出 `R/G = 1.0000`，精确。
但**增益施加方式**有问题，`tb_awb_zones.v` 的分区激励把它抓出来了：

激励：`H=8`，上 4 行 `R=60`、下 4 行 `R=140`，`G=B=100` ⇒ **整帧输入均值 `R/G` 恰好 1.0000**。

| 模式 | 输入帧均值 R/G | 原厂输出帧均值 R/G |
|---|---|---|
| 0 对照（整帧 R=G=B=100） | 1.0000 | 1.0000 |
| 2 对照（整帧 R=60） | 0.6000 | 0.9900 |
| **1 分区** | **1.0000** | **1.3396** ← 偏 34% |

MODE 1 的逐输出行 `R/G` = `0.99 / 0.99 / 0.99 / 1.96 / 1.63 / 1.46 / 1.36`
—— 典型的**帧内斜坡**：第 N 行用的是「前 N 行」的比值，不是整帧的比值。

结论两条：
1. `done[i]` 每个有效拍都在覆盖增益，而累加和是运行值 ⇒ **增益在帧内不恒定**，
   灰世界"整帧均值归一到 1.0000"的数学前提被破坏。
2. `I_tuser` 把增益复位成 1.0 ⇒ **每帧第 0 行永远未校正**，画面上沿会有一条色带。

再叠加"传感器自动曝光剧烈游走"（实测同一场景 30 s 内 Y 均值 39→89→31→65），
白平衡增益就成了一个永远追不上的移动靶 —— 这正是画面**偏绿且漂移**的来源。

### 2.4 改动后

```verilog
// 新增（模块级）
localparam [19:0] WB_GAIN_MIN   = 20'h08000;   // 0.500x
localparam [19:0] WB_GAIN_MAX   = 20'h40000;   // 4.000x
localparam [4:0]  WB_DAMP_SHIFT = 5'd2;        // ~4 帧时间常数

reg  [19:0] in_r_tgt1, in_b_tgt1;   // ... tgt2/3/4 同
reg  S_tuser_d;  wire S_tuser_rise;
always @(posedge I_clk or negedge I_rst_n)
    if (!I_rst_n) S_tuser_d <= 1'b0;  else S_tuser_d <= I_tuser;
assign S_tuser_rise = I_tuser & ~S_tuser_d;

function [19:0] wb_clamp_gain;      // 商 -> 钳位后的 Q16 增益
    input [47:0] q;
    begin
        if (|q[47:20])                  wb_clamp_gain = WB_GAIN_MAX;
        else if (q[19:0] < WB_GAIN_MIN) wb_clamp_gain = WB_GAIN_MIN;
        else                            wb_clamp_gain = q[19:0];
    end
endfunction

function [19:0] wb_damp_gain;       // 每帧向目标走 1/2^WB_DAMP_SHIFT
    input [19:0] cur, tgt;  reg [19:0] d;
    begin
        d = (tgt > cur) ? (tgt - cur) : (cur - tgt);
        d = d >> WB_DAMP_SHIFT;
        if (d == 20'd0) d = 20'd1;
        wb_damp_gain = (tgt > cur) ? (cur + d) : (cur - d);
    end
endfunction

// 通道 1（2/3/4 同构）
always @(posedge I_clk or negedge I_rst_n)begin     // 目标：每拍跟踪商，只钳位
    if(!I_rst_n)begin in_r_tgt1 <= 20'h10000; in_b_tgt1 <= 20'h10000; end
    else if(done[0])begin
        in_r_tgt1 <= wb_clamp_gain(in_r_x1);
        in_b_tgt1 <= wb_clamp_gain(in_b_x1);
    end
end

always @(posedge I_clk or negedge I_rst_n)begin     // 实际增益：只在帧边界更新
    if(!I_rst_n)begin in_r_r1 <= 20'h10000; in_b_r1 <= 20'h10000; end
    else if(S_tuser_rise)begin
        in_r_r1 <= wb_damp_gain(in_r_r1, in_r_tgt1);
        in_b_r1 <= wb_damp_gain(in_b_r1, in_b_tgt1);
    end
end
```

三点设计意图：
* **`S_tuser_rise` 而不是 `I_tuser` 电平** —— 上游若把 `tuser` 给成多拍电平，
  增益也必须只更新一次。
* **在 `tuser` 上升沿锁存读到的商，是"上一帧末"的值** —— 除法器 `PIPLE=50`
  的固有延迟让 `in_r_tgtN` 在那一刻仍反映帧末的完整累计比。
  所以第一帧之后，每个新帧用的都是上一帧的整帧均值 ⇒ 帧内恒定、均值被真正归一化。
* **钳位收紧到 `[0.5×, 4.0×]`**（原来上钳 ≈16×、无下钳）。室内实测传感器原生
  `R/G≈0.86`，需要的增益 ≤1.2×；4× 余量充足，同时挡住除法器分母为 0 时的野值。

### 2.5 预期上板效果
* 白平衡**在帧内恒定**：整幅画面用同一个 R/B 增益，不再出现帧内色温斜坡。
* 消除**每帧第 0 行未校正**带来的上沿色带。
* 自动曝光游走时增益不再逐行抖动（阻尼 ~4 帧时间常数 ≈ 67 ms），
  画面色温变"稳"，代价是遇到光源突变需要 ~0.2 s 收敛。
* 对当前 `R/G = 0.8919 / B/G = 0.9399`（10 号 A/B 图，曲线旁路线性域实测）的残留偏色，
  这一改**不会立刻把比值拉到 1.00** —— 它修的是"施加方式"，不是"目标值"。
  但它让灰世界的靶子第一次变成真正可命中的；如果重采后仍偏，下一步才是调目标
  （例如从纯灰世界换成带场景门限的版本），那时改动是**加法**，不是推倒重来。

## 3. 可调参数一览（都在 RTL 里，不用改脚本即可微调）

| 参数 | 文件:位置 | 默认 | 作用 |
|---|---|---|---|
| `K`（黑位扣减量） | 生成脚本 `--K`，或直接改表 | 24 | 越大暗部越黑、对比越强 |
| `mode`（soft/affine） | 生成脚本 `--mode` | soft | affine 更狠、整体更暗 |
| `WB_GAIN_MIN` | `awb.v` 新增声明 | `20'h08000` = 0.50× | 增益下限（防分母为 0） |
| `WB_GAIN_MAX` | `awb.v` 新增声明 | `20'h40000` = 4.00× | 增益上限 |
| `WB_DAMP_SHIFT` | `awb.v` 新增声明 | `5'd2`（~4 帧） | 越大越稳、收敛越慢 |

这三处 `localparam` 是给后续「实时参数调节 + OSD」加分项留的天然挂点：
`WB_DAMP_SHIFT` / `WB_GAIN_MAX` 换成拨码开关或参数寄存器驱动的 `wire` 即可现场调。

### 8.2 根因

```
uics500_cfg\uics500regAE.v:83   7: REG_DATA = {16'h4501, I_test_pattern ? 8'hbc : 8'hb4};
                                                          ^^^^ 0xbc = 灰度递增测试图【开】
```

`S_tp_canary = 1` 的条件是**四个开关全部拨上**。而四个全上恰好就是推荐工作档
（SW1=黑电平扣除启用、SW2=S曲线启用、SW3=数字增益×2.000、SW4=模拟增益15.750×）。
原注释写的“正常使用绝不会出现的状态”是错的。

且重下发只由 SW3/SW4 变化触发（`S_gain_applied` 只有 2 bit），所以拨 SW1/SW2 不会重发表
⇒ 测试图一直开着。这解释了为什么 20/21 两张都是测试图、只有曲线差异。
