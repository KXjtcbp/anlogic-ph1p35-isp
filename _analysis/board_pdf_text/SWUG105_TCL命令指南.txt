1 概述 
TangDynasty®（TD） 支持使用Tcl 命令行或 Tcl 脚本来执行 FPGA 设计流程。本文介绍 TD 支持的 Tcl
命令以及使用方法。 
2 Tcl 命令及脚本的运行方法 
2.1 在 TD界面模式下 Console 窗口运行 
在GUI 界面中，在Console 窗口可以运行Tcl 命令。 
 
图 2-1 Console 窗口运行 Tcl 命令 
注： 
在 Console 窗口中，Tcl 命令须在适当的阶段运行， 例如在open_run phy_1 后不能在Console 运行Syn
阶段的Flow Step 命令(elaborate/optimize_rtl/optimize_gate 等)。 
2.2 TD 命令模式下运行 
2.2.1 Windows系统 
1. 在 Windows 下启动 TD CMD 窗口：  
Start → All Programs → td_commands_prompt 
2. 运行Tcl 命令：在此CMD 窗口中可直接运行单独的Tcl 命令； 
3. 运行Tcl 脚本：进入Tcl 脚本所在目录，执行命令source demo.tcl

3 Tcl 脚本运行工程 
本节介绍如何编写完整的TD Tcl 脚本运行整个流程。主要分为工程模式和非工程模式。 
3.1 工程模式 
工程模式需要先用Tcl 命令创建一个TD 工程，基于此工程管理的方式来进行后续流程的命令。 
3.1.1 工程模式脚本结构 
1. 创建工程（create_project） 
2. 打开工程（open_project） 
3. 设置工程top module 名字（top_module） 
4. 添加源文件和约束文件（add_files） 
5. 如果需要多个run，添加run（create_run） 
创建工程后，syn_1 和 phy_1 是默认就存在的，不需要再创建。 
6. 设置参数（set_param） 
a) multi run 模式下set_param 命令需使用-run 选项指定参数设置对应的run 名称。 
b) 可以使用set_seed_param 为active run 设置multi seeds，同时需要设置enable_seed
参数为on 
7. 启动运行并等待运行结束（launch_runs, wait_run） 
8. 筛选并保存最好结果（save_best_bits） 
9. 关闭工程（close_project） 
3.1.2 工程模式脚本示例 
以下为包含multi runs 和multi seeds 功能的脚本示例： 
create_project test ./ -family ph1 -device PH1A100SFG676 -speed 2 
open_project ./test.al 
 
top_module run_led

3.2 非工程模式 
3.2.1 非工程模式脚本结构 
1. import_device 
2. 设置参数（set_param） 
3. 添加源文件（read_hdl） 
4. 添加约束文件，运行综合阶段分步命令以及每个步骤后需要产生各种报告和输出文件的命令 
注：read_adc 需在optmize_rtl 前执行， read_sdc 及read_sdc -ip 需在optimize_gate 或
map_macro 前执行。 
5. legalize_phy_inst 命令 
6. read_sdc 及read_sdc -ip 再次读入SDC 文件 
7. 布局布线阶段分布命令以及每个步骤后需要产生各种报告和输出文件的命令

legalize_phy_inst

2. 以 single run 模式打开工程（open_project）

map_macro 前执行。 
5. legalize_phy_inst 命令

4 Tcl 命令 
本章节按照Tcl 命令的功能类别介绍各命令的用法。 
4.1 工程管理 
4.1.1 import_device 
导入所使用的device。 
命令参数： 
import_device -package <package_name> [-speed <speed_number>] db_name 
参数释义： 
-package <package_name>:  
（必选）指定导入device 的型号及封装 
-speed <speed_number>:  
（可选）指定导入device 的速度等级。若未使用此选项则使用该器件默认速度等级。 
db_name:  
（必选）指定导入device 的db 文件名。db 文件名列表见附件一。 
命令示例： 
import_device ph1_100.db -package PH1A100SFG676 -speed 2 
4.1.2 create_project 
创建工程，指定工程.al 文件所在路径，工程名称（即.al 文件名） ，以及所使用的器件 
命令参数： 
create_project <project_name> <project_directory> -family <device_family> -device <de
vice_part_number> [-speed <speed_grade>] 
参数释义： 
project_name：  
（必选）指定工程名称，即.al 文件名（不带.al 后缀） 。 
project_directory：

（必选）指定工程根路径，即.al 文件所在绝对路径或相对路径。 
-family <device_family>： 
（必选）指定所使用器件的family。具体器件列表见附录一 
-device <device_part_number>： 
（必选）指定所使用器件的型号。具体器件列表见附录一 
-speed <speed_grade>： 
（可选）指定所使用器件的速度等级。若未使用此选项则使用该器件默认速度等级。

命令示例：

create_project test -family ph1 -device PH1A100SFG676 ./

project_file:  
（必选）.al 文件的绝对路径或相对路径及文件名。 
-single_run:  
（可选）是否以single_run 模式打开工程。若不使用此选项，则为默认multi_run 模式。 
注： 
 .al 文件目录（除目录分隔符“/”以外）禁用以下字符：*\/|:”?<>C 且不能以数字开头。

应） 。此时 net 和 cell 一样具有层级结构，具体寻找模式请见下文。 
（3）由用户在 verilog 中定义的 wire 型 net，由 wire 名命名。

中没有的信号，所以不推荐试图用这些名字来搜索 net。 
在以上三类 net 中，第2 类net 由于与寄存器（每个 reg 都可以看成一个 cell）相关，所以和
cell 一样具有层级结构，隶属于某一层module。 
默认模式中， 匹配 net 名称时会需要同时匹配路径 （即层级地址） ， 此时完整的net 名称应该包含

命令参数 
 -name {<clock name>} 
 -period <time ns> 
 -waveform {<rise time ns> <fall time ns>} 
 [<Target>] 
 -add 
参数释义 
-name {<clock name>} 
用于指定时钟名字， 该名字将用于时序分析和其它时序约束命令中的使用。 该参数不能省略， 否则

-period <time ns> 
<<<page 45>>>
 
 
TangDynasty® TCL Command User Guide

用于指定时钟的周期，时间单位为纳秒（ns） ，数值为正，数字格式是保留小数点后三位。 
-waveform {<rise time ns> <fall time ns>} 
用于指定时钟第一个上升沿与第一个下降沿的时间点， 可以指定不同相位或者不同占空比，时间单
位为纳秒（ns） ，数字格式是保留小数点后三位。如果省略该参数，TD 时序分析工具将该项默认为相位
为零，占空比为50%的时钟波形。当设置的时间点不在周期内时，TD 时序分析工具将报错提醒。 
[<Target>] 
用于指定时钟在FPGA 内的时钟源点， 一般对象是I/O 管脚 （可以使用get_ports 来约束） 或者FPGA
内硬核的时钟管脚（可以使用get_pins 来约束） 。 
-add 
用于指定对同一时钟对象进行多次约束， 可以约束为不同的频率、 不同的相位或不同的占空比， 一
般用于时钟 MUX 的约束。如果省略该参数，并且用户对同一时钟对象进行了多次约束，TD 时序分析工
具将最后的一次约束覆盖之前的约束。 
使用说明 
定义一个主时钟，同时指定其属性，如名称，周期，上升下降沿时间或占空比等。 
命令示例 
1、标准示例： 
create_clock -name clk_25m -period 40.000 -waveform {0.000 20.000} [get_ports {clk_25
m}]

参数释义： 
 基本选项General Option 
-bit <bitfile_path_name>: 
（可选）指定 bit 文件的绝对路径或相对路径及文件名。-bit 和-bin 两个选项需至少使用一
个。 
-bin <binfile_path_name>： 
（可选）指定 bin 文件的绝对路径或相对路径及文件名。-bit 和-bin 两个选项需至少使用一
个。 
-gen_mask： 
（可选）生成bitstream 的 mask 文件，在对SRAM 做回读校验时不去校验mask 文件被设上
的码点。使用此选项时需同时使用-bit 选项。如果工程存在DRAM init value ，并且需要做SRAM
回读校验时需要设置此选项。 
-hd <string>： 
（可选）在 bin 文件前面添加16 字节的信息，用于离线下载。使用此选项时需同时使用-bin
选项。此选项的值为32 位16 进制数值，默认值为00000000AA5599669100050000000000。 
-id <string>： 
（可选）在bin 文件前面添加2 字节的信息，作为bin 文件的id 使用，用于区分不同bin 文
件。使用此选项时需同时使用-bin 选项。此选项的值为4 位16 进制数值。 
-version <string>： 
（可选）指定bit 文件的version 信号， 该配置会写到位流文件中， 并且可以从芯片中回读显
示在download 界面。如果Download 界面存在多个bit 文件，可以通过界面显示的version 值来

-security： 
（可选）屏蔽SRAM 回读功能。 
-no_date_info： 
（可选）bit 文件不写入文件创建时间信息，用于在比较不同 bit 文件时忽略时间戳的影响。

-embedded_compress：

-seu_all: 
（可选）开启全码流seu 检测功能。仅PH1A100 和PH1A400 支持此选项，默认不开启。 
-unused_io_status <pullup/pulldown/keeper/none>： 
（可选）将实际逻辑中未使用的IO 启动状态统一设定，默认值pullup。
