1 概述 
本文档主要介绍了TangDynasty®（以下简称 TD ）中如何实现安路FPGA 应用下的工程仿真，TD 联
合仿真工具支持TD 6.0 及其以上版本。通过此文档，可协助用户在工程设计流程的各个阶段实现快速
仿真并验证设计功能和时序的正确性。 
2 仿真简介 
仿真是在软件环境中模拟真实设计行为的过程，仿真通过施加激励并观察设计输出来帮助验证工
程设计的功能，本章节主要介绍了在TD 软件中的仿真流程以及各器件库支持的仿真工具。 
2.1 工程仿真流程 
在工程设计流程的各个阶段都可以进行仿真验证，在较大的工程中通常需要进行反复的仿真测试
以保证功能和时序满足要求。

2.1.1 Behavioral Simulation 
FPGA Flow 运行完Read Design 这一步并执行open run 操作后，可执行Behavioral Simulation，
即 RTL 行为级仿真。 该阶段仿真在综合前验证设计， 检查代码的语法错误以及代码行为的正确性， 是源
码级的仿真，可初步修复设计的问题从而节约设计周期。 
初始的设计为行为级的代码有以下优点： 
（1）行为级代码更具备可读性； 
（2）行为级代码具备复用性，可在其他工程设计中使用相同的RTL 代码； 
（3）行为级代码具备可移植性，可移植到其他器件系列使用； 
（4）行为级代码的仿真更便捷。 
2.1.2 Post RTL Simulation 
FPGA Flow 运行完Optimize RTL 这一步并执行open run 操作后，可执行Post RTL Simulation，
即后RTL 级仿真。该阶段仿真是对优化后形成的门级电路网表的仿真，验证工程功能的正确性。 
2.1.3 Post Gate Simulation 
FPGA Flow 运行完Optimize Gate 这一步并执行open run 操作后， 可执行Post Gate Simulation，
即后 Gate 级仿真。该阶段仿真是对门级电路转换成的安路器件库底层物理电路网表的仿真，可验证综
合后设计工程功能的正确性。 
2.1.4 Post Route Simulation 
FPGA Flow 运行完Optimize Placement 以及Optimize Routing 这两步并执行open run 操作后，
可执行Post Route Simulation，即后Route 级仿真。该阶段仿真是对物理单元布局布线优化后电路网
表的仿真， 分为功能仿真和时序仿真， 其中时序仿真需要包含SDF 文件， 该文件可由TD 软件自动生成，
时序仿真可以保证布局布线后的设计满足功能和时序的要求。

3 TD 联合仿真工具 
TD 软件集成Simulation Libraries Compiler 以及Project Simulation 两个联合仿真工具以协助
用户实现设计流程中各个阶段的工程仿真，前者的功能是编译TD 器件库以支持第三方仿真工具调用，
后者的功能是在TD 各个flow 阶段仿真时自动生成对应的仿真文件并实现一键自动仿真。 
3.1 Simulation Libraries Compiler 
Simulation Libraries Compiler 工具的主要功能是在TD 软件中实现对Anlogic 器件库/IP 仿真
库的一键编译，第三方仿真工具可选择 Modelsim/Questasim，支持自定义编译库路径并生成相应的器
件库目录。选择Tools → Simulation Libraries Compiler 使用该工具，如图3-1 所示。 
 
图 3-1 Simulation Library Compiler 工具选项 
3.2 Project Simulation 
Project Simulation 工具的主要功能是在TD 软件的各个flow 阶段实现对工程的快速一键仿真，
如图2.1 所示。Project Simulation 工具可自动化生成testbench 文件、仿真脚本以及网表文件，用
户只需编写 testbench 的激励部分代码即可实现联合第三仿真工具 的自动化仿真，实现 Behavioral 
Simulation、Post RTL Simulation、Post Gate Simulation以及Post Route Simulation。选择Tools 
→ Project Simulation 使用该工具，如图3-2 所示。 
注：使用TD 的Project Simulation 工具必须打开并编译工程。

4 仿真准备 
本章节描述了对安路器件上的工程进行仿真前所需的组件以及仿真相关设置。 
在执行仿真之前需要完成以下准备事项： 
（1）进行仿真相关的设置，选择第三方仿真工具及其可执行文件目录等等，VCS 仿真时必须勾选
flow_sim_filelist 选项，不勾选此选项默认是Modelsim 的仿真设置； 
（2）编译器件库； 
（3）创建一个映射仿真行为的testbench 文件以及仿真脚本； 
（4）生成网表（Post RTL Simulation、Post Gate Simulation 及Post Routing Simulation 需
要网表文件） 。

4.2 编译器件库 
TD 软件提供仿真模型作为库文件，在设计仿真之前用户需要应用第三方仿真工具编译这些文件。
仿真库包括器件模型、IP 行为模型和时序模型，编译后的库可以直接应用在多个工程设计中。 
注：用户如果使用的是同一版本的工具，只需要进行一次编译库的操作。但是，如果更改了TD 工
具或者仿真工具版本就需要重新编译器件库。 
有关第三方仿真工具编译库的详细信息，可以参照第三方仿真工具的文档。

4.3 准备 testbench 和仿真脚本 
TD 软件中testbench 有两种生成方式， 支持用户自定义testbench 文件或通过Project Simulation
工具自动生成testbench 文件。  
testbench 是用来仿真的激励文件，可使用硬件描述语言verilog 或者system verilog 编写，其
主要功能如下： 
（1）例化并初始化设计； 
（2）为工程设计产生激励； 
（3）模拟设计输出的结果并验证设计功能的准确性。 
testbench 可以简单地按顺序对特定的输入施加激励， 并可以包含子程序调用、 从外部文件读取的
激励、条件激励或者其他更复杂的结构。 
testbench 相对于交互式仿真有独特的优势， 一是支持在整个设计过程中的重复仿真， 二是可提供
测试条件的文档。 
在创建testbench 文件过程中需要注意以下几点： 
（1）在testbench 文件中添加`timescale， 即时间单位以及仿真精度， 例如`timescale 1ns/1ps； 
（2）在仿真开始时刻需要给设计的所有输入赋初始值以正确地开启仿真过程； 
（3）在释放全局复位（GSR）之后启动时钟源； 
（4）使用安路器件的相关源语时，testbench 需要调用全局复位文件，调用方式如图 4-5 所示，
其中PH1_PHY_GSR 源语用于PH1 系列器件库，PH2_PHY_GSR 源语用于PH2 系列器件，glbl 源语用于EF2、
EF3、EF4、EG、SF1 器件库。

以下是编写testbench 激励时一些建议的规范： 
（1）使用initial 块或always 块：在testbench 中，通常使用initial 块或always 块来编写测
试激励，initial 块适用于一次性的初始化和测试，而always 块适用于循环测试； 
（2）添加时间延迟：在testbench 中，根据需要添加适当的时间延迟以确保测试激励的顺序和时
序是正确的； 
 
（3）使用任务（task）或函数（function） ：将测试激励的相关代码封装到任务或函数中，以提高
可维护性和代码重用性； 
 
（4）添加注释：在testbench 中添加详细的注释，解释测试激励的目的、顺序和预期结果； 
（5）使用测试配置参数：在testbench 中使用参数来配置测试，以便在不同的测试场景中重复使
用相同的testbench； 
initial begin 
//Stimulate input signals 
input_signal = 1'b0; 
#10; 
input_signal = 1'b1; 
#20; 
input_signal = 1'b0; 
 
//Additional testbench code 
end 
task apply_test_pattern; 
//Your testbench code here 
Endtask 
 
//…… 
 
initial begin 
    apply_test_pattern; 
end

5 与第三方仿真工具的联合仿真 
本章节介绍了在完成仿真准备工作后如何实现与第三方仿真工具的联合仿真，并描述了 VCS 仿真
流程以协助用户在Linux 系统中使用VCS 仿真工具进行工程仿真。 
TD 工程支持使用第三方仿真工具进行仿真， 可以直接由TD 集成设计环境执行联合仿真或使用用户
自定义的外部仿真环境。 
VCS 仿真工具暂未关联到 TD 软件环境中，如果用户需要使用 VCS 仿真目标工程，可自定义外部仿
真环境。 
VCS 仿真流程如下： 
（1）设置环境变量：在使用VCS 之前，需要设置VCS 工具的环境变量，以便系统能够找到VCS 的
执行文件； 
（2）生成 filelist 文件：文件列表包括 testbench 文件、源文件、IP 的仿真文件以及其他源语
文件，VCS 仿真时仿真设置必须勾选 flow_sim_filelist，在目标工程的对应 flow 阶段使用 Project 
Simulation 工具即可在仿真目录下自动生成testbench 文件和filelist 文件，详见第4 章； 
（3）编写Makefile 脚本文件：在目标工程的对应仿真目录下创建一个新的Makefile 文件，添加
仿真时需要的编译命令和选项，如图5-1 所示，VCS 编译命令和选项设置可参照VCS 工具文档； 
 
图 5-1 Makefile 脚本的 VCS编译命令和选项 
（4）运行VCS 编译：执行Makefile 脚本，使用make 命令即可启动VCS 仿真编译； 
（5）查看仿真波形：VCS 编译完成后，可通过 DVE 工具或者 verdi 工具查看仿真波形，若用户添
加了 verdi 的环境变量并在 Makefile 脚本中添加了 verdi 命令和选项，如图 5-2 所示，可使用 make 
verdi 命令直接启动verdi 查看波形。

VCS 时序仿真中的SDF 反标有两种方式，如下： 
（1）在 Makefile 中调用，使用命令 vcs–sdf min|typ|max:instance_name:file.sdf ，其中
min|typ|max 表示选择最小、典型或最大时序信息，instance_name 是指定时序信息应用的实例名称，
file.sdf 是包含了SDF 信息的文件; 
（2）使用$sdf_annotate 函数将SDF 文件反标到网表中,函数声明为$sdf_annotate ("sdf_file" 
[,module_instance][,"sdf_configfile"][,"sdf_logfile"][,"mtm_spec"][,"scale_factors"] 
[,"scale_type"])，参数说明可查阅VCS 仿真工具文档。 
注： （1）用户使用VCS 工具执行sdf 后仿真时，需要将+notimingcheck/+nospecify 等屏蔽时序检
查的参数去掉； （2）PH2 仿真模型没有SDF 相关的sepcify 描述，暂不支持时序仿真。
