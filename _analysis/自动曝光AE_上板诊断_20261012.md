## 3. 根因：两个 RTL bug

### bug ① 量纲差 256 倍（这是"越开越黑"的直接原因）

```
ae_stat.v:66   output reg [39:0] O_luma_sum,   // Σ (Y * 256)      ← 契约
ae_stat.v:90   wire [17:0] luma_beat = (sr<<6)+(sr<<3)+(sr<<2)+sr  ← 无 >>8
                                        + (sg<<7)+(sg<<4)+(sg<<2)+(sg<<1)
                                        + (sb<<4)+(sb<<3)+(sb<<2)+sb;
ae_ctrl.v:133  wire [39:0] S_lsum = S_luma_sum;               ← ✗ 直接当成 ΣY
ae_ctrl.v:88   localparam [47:0] TARGET_SUM = NOM_PIX * TARGET_MEAN;  // = ΣY
```

`S_lsum` 恒为 `S_target` 的 256 倍 ⇒ `S_too_bright` 恒真 ⇒ **每帧都执行 `S_gi_dec`**。

验算 A4：Y 均值 0.98 ⇒ ΣY = 0.98 × 921600 = 903168 ⇒ `S_lsum` = 231,220,992；
而 `TARGET_SUM` = 921600 × 70 = 64,512,000。231M > 64.5M ⇒ 判过亮 ⇒ 降档。
**哪怕画面亮度只有 0.25 也仍然是"过亮"。**

而且此时 `S_absdiff` = 167M > `S_target` ⇒ 走 `STEP_FAST = 8` 档 ⇒ 8 帧内从
索引 64 掉到 0 ⇒ 模拟增益从 4.000× 砸到 1.000×（合计 = 1.000× × SW3 数字 2.000× = 2.000×），
比之前惯用的 31.500× 暗 **15.75 倍**。这与"画面几乎全黑"完全吻合。

**修法**（`ae_ctrl.v:133`）：
```verilog
wire [39:0] S_lsum = {8'd0, S_luma_sum[39:8]};   // 精确除以 256，无信息损失
```
（Σ(Y×256) 一定是 256 的整数倍；ΣY 最大 2.35e8 < 2^28，32 位足够。）

### bug ② 增益回绕（TB 抓到的）

```verilog
wire [6:0] S_gi_inc_raw = S_gi + S_step_n;                          // ✗ 7 位求和
wire [6:0] S_gi_inc = (S_gi_inc_raw > 7'd127) ? 7'd127 : S_gi_inc_raw;
```
`124 + 8 = 132` 先在 7 位里截成 `4`，之后 `4 > 127` 恒假 ⇒ **钳位形同虚设**。
后果：AE 爬到接近满档时**跳回最低档**，在"爬升→回绕→再爬升"之间振荡。
实测（TB CASE 6）：`增益 116 → 4`，一帧掉 112 档。

**修法**：先在 8 位上求和，再判溢出。
```verilog
wire [7:0] S_gi_inc_raw = {1'b0, S_gi} + {1'b0, S_step_n};
wire [6:0] S_gi_inc = (S_gi_inc_raw > 8'd127) ? 7'd127 : S_gi_inc_raw[6:0];
```

### bug ③（设计判断错误）暗场景护栏把加亮通道堵死

```
ae_ctrl.v   parameter [5:0] LO_GUARD_SHIFT = 6'd2;   // lo_cnt > pix/4 = 25% ⇒ 停止加亮
```
本工程的使用场景（宿舍、只开显示器）整帧 `dk<=8` 占 **65%~95%**，
该护栏恒真 ⇒ **AE 在"本来就暗"的场景里完全不加亮** —— 而那正是最需要加亮的时候。

**修法**：`LO_GUARD_SHIFT` 默认改成 `6'd0`（`>>0` = 自身，永不成立 ⇒ 关闭）。
理由：暗场景加增益正是相机的正确行为；真正要防的高光削顶由 `S_hi_hot` 兜着
（阈值 1/64 ≈ 1.56%，本批 B3 实测 `ov250 = 0.000%`，该侧工作正常）。
若要恢复旧策略，把该参数调回 2 即可（TB CASE 6 会立刻报错提醒）。

## 4. TB 增强（防止同类 bug 再溜过去）

`_analysis/sim/ae/tb_ae_ctrl.v` 从 8 个 CASE 扩到 10 个：

- **补上接口契约**：新增 `ls_x1()`（x1 口径，用于断言）与 `as_stat()`（换算成
  `ae_stat` 的 ×256 口径，用于激励）两个函数，并在文件里写明契约来源
  （`ae_stat.v:66` 注释、`:90-93` 移位加法树、`tb_ae_stat.v CASE 2` 的
  `sum=8153600 = 256×(77×200+150×100+29×50)`）。
  ★旧 TB 直接灌 ΣY，**恰好把这个 256 倍错误遮住了** —— 这是最该记住的教训：
  两个模块各自的 TB 都过，不等于它们之间的接口对。★
- **CASE 9（量纲回归，结果级）**：灌 `TARGET_SUM<<8`，断言 DUT 内部
  `dut.S_lsum == TARGET_SUM`。旧写法会得到 `TARGET_SUM<<8`，立刻报错。
- **CASE 10（板上实测场景回归）**：用 A4 的真实数字（Y 均值 0.98、近黑占 95.4%）
  构造激励，断言**必须加档**。这条用例就是为了让"越开越黑"永远不能再出现。
- **CASE 6 反向重写**：原断言"暗场景不加亮"，现在断言"暗场景必须加亮"（28.6% 近黑仍要加）。

最终结果（`_analysis/out/_tb_ae_ctrl.log`）：
