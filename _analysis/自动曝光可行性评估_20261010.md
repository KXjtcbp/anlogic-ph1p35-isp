## 2. 官方手册依据（逐条原文）

### 2.1 AE 必须由后端做 —— 这是硬结论【手册】§2.2.1 p22
> 「SC500CS 本身没有 AEC/AGC 功能，需要通过后端平台实现 AEC/AGC。在整个 AEC/AGC 过程中，不是独立的调整 sensor 的曝光时间或者增益，调整策略为：**曝光时间优先，曝光时间已经最长无法继续调整时，调整增益**。」
> 「以图像过暗的情况为例：1) 不开启任何增益，直到曝光时间达到上限；2) 曝光时间达到上限后，再开始调用自动增益控制。**需要明确指出的是，增益开启，将直接导致平均噪声呈倍数放大；而曝光时间加大，则有助于提升信噪比。**」
> 「反之，当图像过亮时，则**优先关闭增益**，当所有增益关闭，图像仍旧过亮，则降低曝光时间。」
> 「AEC/AGC 都是基于亮度进行调节的……最终使图像亮度落在**设定亮度阈值范围内**。」

⇒ 手册把控制律都写好了：**先曝光后增益；过亮先关增益再降曝光；要做成"落在设定阈值带内"的闭环**。这正好就是标准 AE 的"积分控制器 + 死区"。

### 2.2 曝光寄存器【手册】表2-2 p23
| 项 | 值 |
|---|---|
| 寄存器 | `{16'h3e20[3:0], 16'h3e00[7:0], 16'h3e01[7:0], 16'h3e02[7:4]}` |
| 单位 | 1/2 行时间 |
| 调节步长 | 1 |
| 最小值 | 3 |
| 最大值 | `2*{16'h326d, 16'h320e, 16'h320f} − 'd10` |

控制说明原文：
> 1) AEC 的调节步长为 1/2 行时间；2) **曝光时间及增益若在第 N 帧写入，第 N+2 帧生效**；3) 曝光时间及增益的写入点：**建议在帧开始之后写入**。

代入本工程【源码】`uics500_cfg\uics500reg_720p60.v:31-33`（`320e=0x03, 320f=0xE8` ⇒ VTS=1000，`326d` 未写=默认 0）：
**最大曝光 = 2×1000 − 10 = 1990**，而当前 init 表 `:66-67` 写的正是 `{3e00,00}{3e01,7c}{3e02,60}` = **0x07C6 = 1990 ⇒ 曝光已经顶满**。
⇒ **任何 AE 在本工程的第一个动作都会是"把它降下来"**（对付"一亮就切白"）。

★ 位宽细节：【源码】`uics500_cfg\uics500regAE.v:63-65` 把曝光拆成 `3e00 ← {4'h0, exp[15:12]}`、`3e01 ← exp[11:4]`、`3e02[7:4] ← exp[3:0]`（共 16 bit）。手册表2-2 的写法是 24 bit，但本工程 `exp ≤ 1990 < 4096` ⇒ `exp[15:12] = 0`、`3e20 = 0`，**16 bit 编码与手册完全等价** ⇒ AE 实现时这张表**一个字都不用改**。

### 2.3 增益寄存器【手册】表2-3 p23
| 寄存器 | 名称 |
|---|---|
| `16'h3e08` | ANA GAIN |
| `16'h3e09` | ANA FINE GAIN |
| `16'h3e06` | DIG GAIN |
| `16'h3e07` | DIG FINE GAIN |

> 「SC500CS AGC 控制方法：**将寄存器 16'h3e03 的 Bit[3:0] 设置为 4'hb**」
> 「一般情况下，**优先调节模拟 gain 值**，模拟 gain 调节到上限时，如果要继续增大图像亮度，可以调节数字 gain 值。」
> 「SC500CS 的 DIG FINE GAIN 的精度为 1/128，表 2-5 以 1/32 的精度为例列出控制方法。」

★【源码】全树 grep 结果：**`0x3e03` 在任何一份官方/本工程寄存器表里都没有写过**（lab_ex1/lab_ex2/lab_ex3 的 720p60、`官方资料\2_Example\32_cs500_mipi_hdmi\src\uics500_cfg\uics500reg.v`、1080p30 表、本工程 init 表都没有）。
⇒ 它的复位默认值显然已经是 `0x0b`（否则官方例程写的模拟增益根本不会生效）；AE 实现时**显式写一次 0x3e03=0x0b 更稳妥**（幂等、无副作用）。

### 2.4 模拟增益表 2-4（p24–25）—— ★这张表决定了 GainTbl 怎么补
我逐行核对了手册表2-4，规律非常干净：**高字节（ANA GAIN）只有 4 个值 0x03/0x07/0x0F/0x1F（基座 ×1/×2/×4/×8），每段内低字节（ANA FINE GAIN）从 0x20 递增到 0x3F**：

| 段 | 寄存器编码 | 增益范围 | 手册行 |
|---|---|---|---|
| 1 | `0x0320` … `0x033F` | 1.000× … 1.969× | p24 |
| 2 | `0x0720` … `0x073F` | 2.000× … 3.938× | p24 |
| 3 | `0x0F20` … `0x0F3F` | 4.000× … 7.875× | p24–25 |
| 4 | `0x1F20` … `0x1F3F` | 8.000× … **15.750×（上限）** | p25 |

⇒ **4 段 × 32 档 = 128 档，正好等于 `I_gain_idx[6:0]` 的满量程 0..127**。也就是说：

> **`SC500GainTbl.v` 只需补上索引 74..95（`0x0F20+(idx−64)`，现有表只写到 73）和索引 96..127（`0x1F20+(idx−96)`，全新一段），端口 `input [6:0] I_gain_idx` 一个字都不用改。**

这是本报告里最"顺手"的一个结论：**原作者的 3 段结构（0x0320/0x0720/0x0F20）与手册逐行一致，只是抄到第 73 行就停了**。

### 2.5 其他相关官方事实
- **数字增益**【手册】表2-5 p26–27：1.000×（`3e06=0x00, 3e07=0x80`）… 32×。本工程**从未写过 `3e06`/`3e07`** ⇒ 停在复位默认。
- **行时间**【手册】§2.5 p30：「一行时间 = 1/(帧率×帧长)」。本工程 VTS=1000、60 fps ⇒ **一行 = 16.67 µs**，曝光步长（1/2 行）= 8.33 µs，曝光满量程 1990 ⇒ 995 行 = **16.6 ms = 整整一帧**。
- **软复位**【手册】表1-3 p13：`16'h0103[0]=1` 软复位，"**此复位模式持续 150ns**"，并会重置所有寄存器。★**手册没有给"复位之后要等多久才能写寄存器"**。
- **上电时序**【手册】p11：T4≥1 ms、T5≥1 ms、T6≥4 ms。
- **I2C 地址**【手册】表1-4 p13：SID 低 → 7'h36（本板如此；【源码】`uicfgcs500_720p.v:33 localparam CAM_ID = 8'h6c;` = 写地址）；消息格式【手册】p14 = 设备地址 + 16 bit 子地址（先高后低）+ 8 bit 数据。

3. **信息面**：手册把寄存器、单位、上下限、步长、生效延迟、控制策略全给了（§2.1–2.5）⇒ **不需要任何猜测、不需要外部论文**。

## 5. 实现方案

### 5.1 总体结构（三个新块，零改动复用旧链路）

```
   [csi_rx_clk 域 ≈100MHz]                       [24MHz 域]
   awb 输出总线 (96bit = 4 像素 × {R,G,B})
        │  (只读监听，不进流水线)
        ▼
   ┌─────────────┐   S_sum_f[29:0]  ┐
   │  ae_stat    │   S_hot_f[19:0]  ├─ 每帧一次的多 bit 稳定值
   │ 逐帧亮度统计 │   frame_toggle   ┘  + 1 根"有效"翻转线
   └─────────────┘
        │ 2-FF 同步 + 沿检测（标准做法，值稳定整帧 16.7ms，余量 >1000×）
        ▼
   ┌─────────────┐
   │  ae_loop    │  ← 端口与旧 ae_set.v 完全一致（同端口替换）
   │ 控制律/死区  │
   └─────────────┘
        │ O_exposure_time[15:0] / O_analog_gain[15:0] / O_ae_req
        ▼
   uicfgcs500_720p.v:80 (I_ae_req)  →  uics500regAE.v  →  uii2c.v  →  SC500CS
   （★这一整段一个字都不用改）
```

### 5.2 `ae_stat.v`（新增，csi_rx_clk 域，只读监听）
- 挂载点：`isp\isp_top.v` 里 `u_awb` 与 `u_my_algo` 之间的 96 bit 总线上（**监听，不插流水线** ⇒ 对视频路径零影响）。
  ★ 为什么必须挂在 `my_algo` **之前**：`my_algo.v:278-303 f_pixel` 有 5 种模式（0 直通/1 灰度/2 伪彩热力图/3 二值/4 卡通），一旦切到 MODE 1/2/3，输出亮度就**不再代表场景亮度**，AE 会失控。挂在 AWB 输出既避开了这个问题，又比挂在 demosaic 输出更接近人眼观感。
- 每拍（4 像素）：`s_i = R_i + G_i + B_i`（各 8 bit ⇒ 10 bit），`I_tvalid` 有效时
  - `S_sum <= S_sum + s0 + s1 + s2 + s3;` （30 bit；满帧上限 = 921600×765 = 7.05e8 < 2^30）
  - `S_hot <= S_hot + (s0>=720) + (s1>=720) + (s2>=720) + (s3>=720);` （20 bit；阈值沿用 `awb.v:154` 已有的 720「过亮/白」判据，与既有设计保持一致）
- 帧末（照抄 `awb.v` 的做法：`I_tuser` 或 `tvalid` 下降沿）把 `S_sum`/`S_hot` 锁存到 `S_sum_f`/`S_hot_f`，并翻转 `frame_toggle`。
- 代价：4 个 10 bit 加法器 + 2 个累加器 + 4 个比较器 ≈ **60~90 LUT / ~62 FF**。

### 5.3 `ae_loop.v`（新增，24 MHz 域，同端口替换 `ae_set.v`）
端口照抄 `ae_set.v`：`I_clk, I_rst_n, I_ae_cfg_done, I_cam_cfg_done → O_ae_req, O_exposure_time[15:0], O_analog_gain[15:0]`（**去掉 `I_btn`**，或保留但只作为"强制 AE 开/关"开关）。

**每帧一次的控制律（严格按手册 §2.2.1 的优先级）：**

```
N      = 921600                    // 1280×720 像素数
TH_DK  = N*3*80  = 221,184,000     // 8bit 均值 80 对应 (R+G+B) 累加和
TH_BR  = N*3*120 = 331,776,000     // 8bit 均值 120
TH_HOT = N/50    = 18,432          // 过亮像素占比 2%

太暗 (S_sum_f < TH_DK)：
    ① 若 exp < 1990        → exp += step          // ★曝光优先
    ② 否则若 ag_idx < 127  → ag_idx += step       // 曝光到顶才加增益
    ③ 否则若 dg 未到顶      → dg += step           // 最后才用数字增益（二期）
太亮 (S_sum_f > TH_BR 或 S_hot_f > TH_HOT)：
    ① 若 dg > 1.000        → dg -= step           // ★优先关增益
    ② 否则若 ag_idx > 0    → ag_idx -= step
    ③ 否则若 exp > 3       → exp -= step
在带内且不过亮 → 不动

step = (|误差| > 2×死区) ? 大步 : 小步        // 远则大步、近则小步
     · exp 大步 = exp>>2 + 1（+25%/帧）、小步 = exp>>3 + 1（+12.5%/帧）
     · ag_idx 大步 = 8（≈+18% 线性增益）、小步 = 2（≈+4%）
死区 = 目标带的 ±15%，配合手册"第 N 帧写、第 N+2 帧生效"的 2 帧延迟，
      这是一个纯积分控制器 ⇒ 不会振荡。
```

- 收敛速度：从最暗到目标带 ≈ 8~25 帧 = **0.13~0.42 s**；光照突变后同样量级 ⇒ 满足"光线剧烈变化时工作正常"。
- 过亮保护用 `S_hot`（≥720 的像素占比）是**必须的**：本工程曝光本来就顶在 1990（= 整帧），场景一亮必切白，只有 AE 能把它拉回来。
- ★ `O_analog_gain` 的数值约定：`uicfgcs500_720p.v:141` 用 `.I_gain_idx(I_analog_gain - 16)` ⇒ **本模块输出的 `O_analog_gain` = 表索引 + 16**。旧代码 `ag_set=80` ⇒ 索引 64 ⇒ `0x0F20` = 4.000×，与此约定一致。补表后：索引 96 ⇒ `0x1F20` = 8.000×（`O_analog_gain`=112），索引 127 ⇒ `0x1F3F` = 15.750×（=143）。
- 代价：一个 16 bit 积分器 + 常数比较 + 一个小步长加法 ≈ **100~130 LUT / ~80 FF**。

### 5.4 跨域传递（关键：**不需要握手**）
统计值每帧（16.7 ms）才变一次，24 MHz 域能看到同一个值超过 400,000 个时钟 ⇒ 用「**多 bit 稳定值 + 1 根翻转线做有效沿**」即可：源域在锁存数据后翻转 `frame_toggle`，目的域 2 级同步 + 异或取沿，在沿那一拍采样 30 bit / 20 bit 数据。数据在整帧内恒定，采样点距离变化点 ≥ 一个帧周期 ⇒ **余量 >1000×**，比常规握手更简单且更安全。
（这与工程里 `hdmi_mixer.v:1252-1298` 已经在用的"翻转线 + 3 级同步 + 异或取沿"套路完全同构，风格统一。）

### 5.5 分阶段落地
| 阶段 | 内容 | 验证判据 |
|---|---|---|
| **P0** | 只补 `SC500GainTbl.v` 到索引 127 + 修 init 表软复位后的等待 + 本次按键改造，一起编译 | 屏上 MODE 默认 0；ChipWatcher 抓 `0x3e08/0x3e09` 回读 = `0x1F2D` |
| **P1** | `ae_stat.v` + `ae_loop.v`（只做曝光 + 模拟增益闭环，目标带 8bit 均值 80~120） | ①暗→亮、亮→暗切换后 <0.5 s 收敛；②连续 30 s 无持续振荡（`S_sum_f` 在带内波动 <±15%）；③ChipWatcher 抓到的曝光值随场景变化 |

### 6.1 `SC500GainTbl.v` 补表（**必做**）

## 7. 关于"下载后几分钟变暗 ~10 倍"（对 AE 方案的影响）

【实测】同灯同朝向下，19:34（刚下载完）RAW10 均值 436.4、中位 323、14.4% 样本顶在 1023；20:09 均值 101.4、中位 98、max 155、0% 削顶；黑基座两次都是 66~67 不变 ⇒ **变的是"有效增益 × 有效曝光"，不是黑电平**。
扣掉黑基座后的有效信号 369.4 → 35.4（**÷10.4**）；而 init 表写的模拟增益是 **11.25×**（`0x1F2D`），若它掉回复位默认 `0x0320` = 1.000×，则比值正好 **11.25**，与实测 10.4 在同一量级。
⇒ **最可能：传感器侧发生过一次复位/掉电/时钟抖动，寄存器掉回上电默认，而工程只在开机配置一次，没有人重新写回去。**（手册已排除"传感器自带 AEC"这一可能，见 §2.1。）

这件事对 AE 方案的意义有两点：
1. **AE 恰好能自动纠正这类漂移**（每帧闭环，0.2 s 内拉回目标带）——这是做 AE 最直接的理由之一；
2. §6.2 的"软复位后无等待"是**另一个独立的可疑点**（它会让"开机那次配置"本身不完整），但它解释不了"几分钟后才变暗"，所以两条都要做、分开验证。

**验证判据（沿用之前给你的四步）：**
1. 盖住镜头盯屏 1~2 min，看画面是否自己变亮（若变亮 ⇒ 是增益掉档而不是场景变化）；
2. 变暗后按 R10 复位（或重下载，不重编译）：立刻变亮 ⇒ 佐证"寄存器被重置且没人重写"；
3. 把 `uii2c.v:181` 的读回通路接出来（`uicfgcs500_720p.v:127 .O_rd_data()` 目前悬空）读 `0x3e00/0x3e01/0x3e02/0x3e08/0x3e09`，**直接看增益和曝光是否掉了**——这是唯一能一锤定音的读数；
4. 若确认掉档，检查摄像头模组供电与 24 MHz 时钟的稳定性（`O_cam_24m=L3`、模组供电脚）。
