## 二、数据内容分析：**ISP 链路是健康的，「异常现象」全部有解释**

### 2.1 传感器侧（RAW10）实测结论

- 盖住镜头时 RAW10 落在 **[57..79]、均值 67.0** ⇒ **传感器的光学黑电平基座 ≈ 57~67 LSB(10bit)**，暗噪声幅度约 ±10 LSB。
- 室内常光时均值 436.4、**14.4% 的采样已经到 1000 以上、最大 1023** ⇒ 这一行像素里扫到了很亮的东西（灯/窗/白墙）。

### 2.2 ISP 输出侧逐字节结论（关键）

把每个有效 ISP 字的 128bit 按 MSB 先切成 16 个字节后可以看到**严格的 24bit 像素格**：

```
全黑 #0  00 00 46 | 00 00 4b | 00 00 4b | 00 00 4b | 00 00 50 | 00
全黑 #1  00 4b 00 | 00 4b 00 | 00 4b 00 | 00 4b 00 | 00 4b 00 | 00
全黑 #2  46 00 00 | 46 00 00 | 46 00 00 | 4b 00 00 | 4b 00 00 | 4b
```

- 非零字节**每 3 个字节出现 1 个**（全黑上恰好 1/3 的字节非零），相邻字之间格点整体移 1 个字节（128 mod 24 = 8bit）⇒ 每个像素就是 **24bit = {R,G,B}**，只是**其中只有 1 个通道有值**。
- ★★ **两份采集里所有非零字节的值全部是 5 的倍数**（全黑 65/70/75/80；室内常光 255/50/145/95/125/140/85/70/80/230/…）。真实图像产生这种规律的概率为零。

### 2.3 ★与 RTL 的逐条闭合（这就是答案）

`hdl_source\my_algo\my_algo.v`（自研点运算算法模块）的伪彩热力图分支恰好就是「5 的倍数」：

```
:170-224  function [23:0] f_heat;   // d*5 写成 ({1'b0,d} << 2) + {1'b0,d}
            y <  51 : r=0,    g=0,    b=5y        ← 只有 B 通道
            51≤y<102: r=0,    g=0,    b=255-5d
            102≤y<153: r=0,   g=5d,   b=255
            153≤y<204: r=5d,  g=255,  b=0
            y ≥ 204 : r=255,  g=255-5d, b=0
:278-303  function [23:0] f_pixel;  case(mode) 3'd2 → f_heat(y)   // 伪彩热力图
:139-159  function [7:0]  f_luma;   // y = (77R+150G+29B)>>8
```

- **全黑帧**：ISP 值 65/70/75/80 = 5×{13,14,15,16} ⇒ y = 13~16 ⇒ 全部落在 `y<51` 段 ⇒ **r=g=0、b=5y** ⇒ 与实测「每像素只有 1 个字节非零、且只有 4 个电平」**完全一致**。
- **室内常光帧**：出现 **255（=5×51，正是热力图的段边界/饱和值）** 以及 50/95/105/…/145 等 ⇒ 说明像素分布在多个色段（其中青/绿/黄/红段有 2 个非零通道，所以非零字节占比从 1/3 升到 0.489）⇒ 与实测完全一致。
- ⇒ **两次采集时算法模式 = MODE 2（伪彩热力图），也就是设计的上电默认模式**（`hdl_source\hdmi_mixer.v:1285 S_algo_mode <= 3'd2; // 与 my_algo.MODE_INIT 保持一致`）。

**因此：「每个 24bit 像素只有 1 个字节非零」不是缺陷，而是热力图第 0 段的正常输出。**（我此前一度把它当成缺陷，此处按数据更正。）

### 2.4 由此得到的两条对现象的解释

1. **「无光时暗、有光时部分恢复颜色」「热力图只反映光源强度」「只有光源处才出现色块」** —— 这三条正是热力图的固有行为：`y<51`（8bit 灰度 < 51，即 RAW10 < 204）时**全画面恒为蓝色 5y**，只有亮到超过这个门限的地方才会依次进入青→绿→黄→红段。**这是模式选择与算法设计问题，不是 ISP 通路故障。**
2. **「画面太灰」** —— 有一个真实的、有数据支撑的成因：**传感器黑电平基座 64 LSB 从未被扣除**（`hdl_source\isp\raw10_unpacket_2lane.v:178-181` 里那段 `(… - I_camera_black_level) >> 2` 处于注释区、且 `I_camera_black_level` 在 `design_top_wrapper.v:571` 悬空）。10bit 的黑会原样进 8bit 链路变成 **64>>2 = 16**，等于给整幅画面垫了 **16/255 ≈ 6% 的灰雾**，暗部对比度被压缩。
