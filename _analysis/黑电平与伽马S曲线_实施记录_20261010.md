```
:101     wire [9:0] S_blk_f0 = I_blk_bypass ? I_raw_tdata[ 9: 0] : (((I_raw_tdata[ 9: 0] > S_blk_level) ? (I_raw_tdata[ 9: 0] - S_blk_level) : 10'd0) + ROUND_ADD);
:102     wire [9:0] S_blk_f1 = I_blk_bypass ? I_raw_tdata[19:10] : (...)
:103     wire [9:0] S_blk_f2 = I_blk_bypass ? I_raw_tdata[29:20] : (...)
:104     wire [9:0] S_blk_f3 = I_blk_bypass ? I_raw_tdata[39:30] : (...)
```

- **不改任何数值**：`BLACK_LEVEL=56`、`ROUND_ADD=2` 与 2026-10-09 版本逐位一致；
  不传参数时行为与旧版完全相同（`S_blk_f*` 的 else 分支就是旧表达式）。
- 取值理由（保留现场实测结论）：盖住镜头时 ChipWatcher 抓到 RAW10 值域 **[57..79]、均值 67.02**，
  取 **56 = 实测最小值 −1**，因此在数学上**不可能钳掉任何一个真实像素**（"绝不影响效果"）；
  同时扣掉 56/66 ≈ 85% 的基座，8bit 域残留 ≈2 个码值（0.8%），肉眼不可见。
- 旁路时 `S_blk_f* = 原值`，高位取 8 位 ⇒ **完全等于改动前的数据通路**。

**为什么不用 `$readmemh`（重要教训）**：TD 综合时的工作目录是 **run 目录**
（`...\camera_to_dsi_display_Runs\syn_1`），而不是 HDL 所在目录或工程目录。
`$readmemh("gamma_lut_p118_k125.hex")` 会**静默地**读不到文件——表全 0 ⇒ 画面全黑，
而且综合/布线/时序报告**全部正常**，属于最难查的一类失效。因此改成**把 256 个初值直接内联进 RTL**：
不依赖工作目录、不依赖仿真器、不依赖任何相对路径。
（仿真与 Python 侧的表仍在 `E:\FPGA\_analysis\gamma_lut_p118_k125.{hex,mif,coe,vh,txt}`，
供 TB 与将来换档时重新生成：`python E:\FPGA\_analysis\gen_gamma_lut.py --all`。）

**曲线定义与数值（`E:\FPGA\_analysis\gen_gamma_lut.py` 生成并自校验）**：

```
x <= 118 :  y = 118 * (x/118)^1.25
x >  118 :  y = 118 + 137 * (1 - ((255-x)/137)^1.25)
```

- 锚点：`0→0, 16→10, 64→55, 118→118, 128→130, 200→211, 255→255`
- 单调不减；**可用级数 235/256、丢失 21 级、最长平台 2 级**（不会出现可见的色带/断层）
- 暗部 64 码值 → 55（压 −9），高光 200 → 211（提 +11），中间调 118 不动 ⇒ 正是"压暗部、提亮高光"的 S 形
- **A=B=1 时退化为恒等**（bypass），所以"关掉 S 曲线"等价于"这条支路不存在"

  均为 `IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP;`

**电平约定（已查手册 `新HX1P35A开发板手册-HDL版2604.pdf:396-404`）**：SW1–SW4 **拨上 = "1"，拨下 = "0"**。

| 开关 | 引脚 | 拨上（1） | 拨下（0） |
|---|---|---|---|
| SW1 | A4 | 黑电平扣除**直通**（= 改动前行为） | **启用**黑电平扣除（当前优化状态） |
| SW2 | B4 | S 曲线**直通**（= 改动前行为） | **启用** S 曲线 |
| SW3 | E11 | 保留（已声明未用） | 保留（已声明未用） |
| SW4 | D11 | 保留（已声明未用） | 保留（已声明未用） |

- 两个开关都带 **PULLUP**，且顶层做了两级同步（`S_sw1_sync0/sync1`、`S_sw2_sync0/sync1`），
  所以**悬空/未焊接读作 1 = 旁路 = 旧行为**，是安全的默认值。
- **SW1/SW2 与 K1–K4 完全解耦**：K1–K4（D5/A9/B9/C7）继续只管算法模式 MODE 循环，
  因此"多算法切换与状态显示"这个高阶评分点**不受影响**；卡通化 MODE 仍然一键可达。

- **结论：不是新增逻辑的时序问题。** 10-09 基线本来就只有 **+3 ps**（等价于"零余量"），
  本次 slice 83.57% → 84.33%、线长 +6% 把这条**既有**临界路径挤到 -80 ps。
- **风险判断**：75 MHz 下 80 ps ≈ 周期的 0.6%，且是在 `slow_m40c` 最坏角、含 0.127 ns default uncertainty；
  常温实物大概率仍可用。若真出问题，表现为 HDMI 混合输出的**偶发单像素错色**，
  不影响本次要验收的画质特征（灰雾/对比度/暗部）。
- **可选收尾（尚未执行）**：① 重跑 P&R（换努力度/种子）追赶这 80 ps；
  ② 用 `settings.cfg` 的 `set phyWildParams { … }` 注入 `set_param`（`DefaultFlow.tcl:74-78` 支持）；
  ③ 若上板后确有偶发错色，先把 SW1/SW2 都拨上（旁路）确认是否与本次改动相关。
