一、这一版加了什么
--------------------------------------------------------------------
新增 isp/lsc.v —— 镜头色彩暗角校正。插在 isp_top.v 的 data128_96 与 ae_stat 之间，
ae_stat 与 awb 改吃 lsc 的输出（AE / AWB 的"整帧均值"全局含义不变）。

只校 R 和 B，G 不动：
  灰世界要求 R/G = B/G = 1，实测这两个比值在画面中心同向偏低、剖面形状几乎重合，
  所以给 R、B 施加同一个增益 (1 + k/64) 就能同时把两个比值拉平。
  G 不动 ⇒ 屏幕整体亮度不变，AE 目标均值含义不变。
  亮度暗角（中心本来亮约 7%）刻意保留：它在人眼里读作立体感，色彩暗角才读作脏。

算法：g = 1 + (KH[x] + KV[y]) / 64，k 取 0..7，最大 +10.94%
  表：水平 20 节点（每 64 像素）、垂直 24 节点（每 30 行）
  表由 _analysis/scripts/fit_lsc.py 从干净靶面自动拟合，换表不动逻辑。

三、这一版修掉的两个坑
--------------------------------------------------------------------
1) 假成功：TD 命令行流程读的是 run 目录的 .prj，不是 td_project/*.al。
   TD 跑完会把 .al 按自己的内部状态回写，我加进去的 lsc.v 条目被抹掉，
   结果 syn_1 报 HDL-8007 "lsc is a black box"，而 phy_1 又用旧 DB 产出
   一份数字与前一轮逐位相同的假成功。
   对策：_analysis/scripts/patch_prj_add_lsc.py 直接写两个 run 的 .prj。

2) 唯一一条时序违例不在功能逻辑里：
   Begin debug_hub_top/U_0_register/ip_ctrl_reg[35]   (JTAG cwc_tck, 100ns)
   End   debug_hub_top/slave_0_control_reg[32]        (MIPI_RX_BYTE_CLK)
   Data Path Delay 1.167ns（cell 18% / net 82%），Logic Level 0 —— 纯布线+时钟偏移。
   已在 camera_to_dsi_display.sdc 末尾加 set_false_path -from [get_clocks {config_inst.cwc_tck_o}]
