## 2. 芯片要点（PH1P35MDG324，全部来自 Datasheet 取证）

完整资料见 `E:\FPGA\proj\reports\芯片PH1P35MDG324_完整资料.md`（20,064 B / 362 行）。要点：

**型号解码**：`PH1 P 35 MDG324` = SALPHOENIX®1P 系列 / 逻辑器件 / 35K LUT / 15×15mm 0.8mm pitch 324 脚。速度等级 **3（中速）**，温度等级字母**在工程与文档里都没出现 → 待确认**。

| DSP / `#dsp` | 40 | 40 | 一致 |
| PLL / `#pll` | 6 | 6 | 一致 |
| MIPI DPHY（组） | 2 | `#mipi_rx` / `#mipi_tx` 各 2 | |

| MCU 硬核 | 1（RISC-V RV32 I/M/A/F/C/P/B，300MHz core） | — | **当前设计未使用**。★若用 MCU，`CCLK` 不能再复用为普通 I/O |
| ADC | **无** | — | |

⚠️ 官方 PPT《赛题解析二》写「LUT 38,184」，与 Datasheet 的 38,189 **差 5，以 Datasheet 为准**。

**关键外设**：
- **MIPI D-PHY**：2 组硬核，每组最大 4 Lane，可配 CSI-2/DSI，支持 HS/LP 动态切换、自动 Skew 校准。TX 支持 8:1/16:1 并串，RX 支持 1:8/1:16 串并。手册**没有单独的「最大 Gbps」行**，只以 1.5 Gbps 为分界给两套阈值 ⇒ 支持超过 1.5 Gbps，具体上限手册未标注（本项目速率远低于此，不受影响）。
- **存储**：外挂 DDR2 走 **External Memory Interface**（800 Mbps，BL8，最大 2 Rank）——这是 lab3 在用的。另有 MDG324/MHG324 独有的 **Integrated Memory Interface**（合封内存，512Mb x16，**1066 Mbps**）**当前完全没用上**，属「扩展要求(4) 系统性能优化」的现成素材，但**是否布通、TD 有无对应 IP = 未确认**。
- **HR I/O 支持 TMDS33**（HDMI 用），**HD I/O 不支持 TMDS、不支持 SERDES**。

**完整时序约束相关**：`pll_clk_24m` 与 `HDMI_PIXEL_CLK` 在原厂 SDC 里被放进**同一个 `set_clock_groups -asynchronous` 组**，所以两者之间仍会被做时序检查 —— 这是那个 −4.416 ns 违例能被报出来的原因。

### ★★ SHOW_DEBUG 的完整说明（用户已在板上看到它的效果，别再让用户困惑）

`SHOW_DEBUG = 1` 时，画面**左上角**会画出 6 像素宽、480 行高的 4 段彩色条：

```verilog
if(SHOW_DEBUG != 0 && S_video_de_2d && (S_x_2d < 12'd6)) begin
    if(S_y_2d < 12'd120)      O_hdmi_data <= I_debug_status[0] ? 24'h00ff00 : 24'h401010;
    else if(S_y_2d < 12'd240) O_hdmi_data <= I_debug_status[1] ? 24'h00ff00 : 24'h401010;
    else if(S_y_2d < 12'd360) O_hdmi_data <= I_debug_status[2] ? 24'h00ff00 : 24'h401010;
    else if(S_y_2d < 12'd480) O_hdmi_data <= I_debug_status[3] ? 24'h00ff00 : 24'h401010;
    else                      O_hdmi_data <= S_video_data_2d;
end
```

- `24'h00ff00` = **纯绿 = 该诊断位为 1**；`24'h401010` = **暗红 = 该位为 0**
- 4 段从下往上对应 `design_top_wrapper.v:411` 的 4 位：

### ★★ 四条必须背下来的硬规矩 ★★

1. **数据格式一个字都不能改**：`96 bit = 4 像素 × 24 bit`，`pix0=I_tdata[95:72]`…`pix3=I_tdata[23:0]`，每像素 `[23:16]=R [15:8]=G [7:0]=B`。依据三处源码交叉验证：`isp/data128_96/data128_96.v:16`、`isp/edge_detect_96.v:22-25`、`isp/data96_128/data96_128.v:96`。一个 beat 只有 4 个像素。

2. **端口方向是反的**：`I_tready` = output，`O_tready` = input。

3. **★ 绝对不要写 `a * 常数` ★**。TD 会把**每个常数乘法推断成一个 DSP 硬核**。实测：写成 `r*77`、`g*150`、`b*29`、`d*5` 时，整机 DSP 从 9 顶到 **40/40 用满**；DSP 用满后 `hdmi_mixer` 里原本用 DSP 的乘法路径被迫退化成 LUT+加法（13~15 级逻辑），引出 5 个像素域违例。改成移位加法后回到 9/40。
   - `×77` → `{r,6'd0} + {2'd0,r,3'd0} + {4'd0,r,2'd0} + {8'd0,r}`
   - `×150` → `{g,7'd0} + {3'd0,g,3'd0} + {5'd0,g,1'b0} + {7'd0,g,1'b0}`
   - `×29` → `{3'd0,b,4'd0} + {6'd0,b,2'd0} + {8'd0,b}`
   - `×5` → `({1'b0,d} << 2) + {1'b0,d}`
   - 中间和最大 `255×256 = 65280 < 2^17`，用 17 bit 承接安全。

4. **★ 函数体里绝对不要"占位预读"变量 ★**。曾因此整模块降级成 black box，综合致命错误原文：
   ```
   HDL-7215 CRITICAL-WARNING: use of 'd' without initialization in static subprogram 'f_heat'
   HDL-5369 WARNING: latch inferred for net 'f_heat.d[7]' in my_algo.v(156)
   HDL-8007 ERROR: net 'f_heat.d[7]' is constantly driven from multiple places in my_algo.v(156)
   HDL-1007 : module 'my_algo' remains a black box due to errors in its contents
   ```
   **每个分支都要独立、完整地给所有局部变量赋值，一次都不预读。**
   ★ **`open_project` 的语法分析查不出这个错，只有真正综合才暴露。** ⇒ 别指望离线验证，必须用户在 GUI 编。

5. **加流水线级数时，`O_tdata/O_tlast/O_tuser/O_tvalid` 四个必须一起延**（现在都是 1 拍，与 `edge_detect_96.v` 相同）。
