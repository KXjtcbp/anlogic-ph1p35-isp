## 1. 系统在干什么（一张图看懂）

```
   SC500CS 摄像头
        │  ① 摄像头用 MIPI D-PHY 差分信号送数据（2 条数据 lane + 1 条时钟 lane）
        ▼
  ┌─────────────────────────────────────────────────────────────┐
  │  mipi_dphy_rx  …  硬核，把高速差分信号还原成并行数据         │  ② 硬件模块，我们不管
  │  csi_unpacket_2lane → raw10_unpacket_2lane → uial2axis      │     出来是 AXI-Stream 40bit
  └─────────────────────────────────────────────────────────────┘
        │  ③ 40bit RAW10（还没做彩色插值，每个像素只有 10 bit 一个颜色分量）
        ▼
  ┌─────────────────────────────────────────────────────────────┐
  │  isp_top  （图像信号处理流水线）                             │
  │                                                             │
  │   demosaic ──► data128_96 ──► awb ──► ★ my_algo ★ ──► data96_128 │
  │   彩色插值      128→96        自动      ← 我们的算法      96→128   │
  │   出 RGB888     位宽转换      白平衡       插在这里                 │
  └─────────────────────────────────────────────────────────────┘
        │  ④ 128bit AXI-Stream（一带 4 个像素）
        ▼
  ┌─────────────────────────────────────────────────────────────┐
  │  video_in   ── FIFO 跨时钟 ──► mc_to_user_interface ──► DDR2   │  ⑤ 写进内存
  │  （摄像头时钟域）              （DDR 时钟域）                   │     为了解耦两个时钟
  └─────────────────────────────────────────────────────────────┘
        │  ⑥ 存进外挂 DDR2 颗粒（4 帧乒乓，写满一帧换一个基址）
        ▼
  ┌─────────────────────────────────────────────────────────────┐
  │  video_out  ──► uivtc ──► hdmi_mixer（叠加 OSD）──► hdmi_tx   │  ⑦ 读出来显示
  │  （按显示器时序从 DDR 读像素）  ▲                            │
  │                                  └ OSD：安路 Logo + "安路 CNT:"  │
  │                                     + 我们加的 "MODE n" 状态行   │
  └─────────────────────────────────────────────────────────────┘
        │  ⑧ TMDS 差分信号
        ▼
     HDMI 显示器
```

**为什么要中间存 DDR**：摄像头出数据的节奏由摄像头自己的时钟决定，显示器要数据的节奏由 HDMI 像素时钟决定，两者不同频。用一块内存做缓冲，写和读各按自己的节奏走，叫"跨时钟域解耦"。**这是原厂框架干的事，我们不改。**

## 4. 三条"接口铁律"（踩过的坑，别再踩）

### 铁律 1：96 bit = **4 个像素 × 24 bit**，不是 3 个

```
一个 beat 的 96 bit 里装着 4 个像素：
  像素0 = [95:72]   像素1 = [71:48]   像素2 = [47:24]   像素3 = [23:0]
每个像素 24 bit = {R[7:0], G[7:0], B[7:0]}     ← 高 8 位是 R
```

⚠️ **注意**：网上和旧文档里有说"3 像素 × 32 bit"的，**那是错的**。三处源码交叉验证：
- `isp\data128_96\data128_96.v:16`　`O_tdata = {I_tdata[23:0], I_tdata[55:32], I_tdata[87:64], I_tdata[119:96]}`
- `isp\edge_detect_96.v:22-25`　pix0=[95:72] … pix3=[23:0]
- `isp\data96_128\data96_128.v:96`　`{{8'd0},I_tdata[95:72], …, {8'd0},I_tdata[23:0]}`

### 铁律 2：`my_algo` 的 `tready` 端口方向是**反的**

```verilog
input  I_tready,   // 名字像输出，其实是输入
output O_tready,   // 名字像输入，其实是输出
...
assign O_tready = I_tready;   // 内部就是个直通
```

这是原厂例程的书写习惯。**照抄，不要"纠正"**，否则 `isp_top` 里所有 wire 连接全部对不上。

### 铁律 3：`my_algo` 有 **1 拍输出延迟**，三个标记必须跟着它走

`my_algo` 内部有一级输出寄存器，所以它的 `O_tlast` / `O_tuser` / `O_tvalid` 比输入**晚 1 拍**。
`isp_top` 里必须取 **`algo_O_*`**，**不能**取 `awb_O_*`，否则数据和"帧开始/行结束"标记错位 1 拍，画面会整体斜移或撕裂。

（这一条已经改好了，见 `isp_top.v:54-56`，**别改回去**。）

## 5. 六个时钟域（为什么"跨时钟域"是麻烦事）

| 时钟 | 频率 | 干什么 |
|---|---|---|
| `S_100m_clk` | 100 MHz | MIPI D-PHY 的低功耗状态机 |
| `S_24m_clk` | 24 MHz | 驱动摄像头 I2C 配置 + 曝光控制；**按键 key_mode_ctrl 也在这个域** |
| `S_hdmi_pixel_clk` | ~75 MHz | HDMI 像素时钟，按它从 DDR 读像素 |
| `S_hdmi_serial_clk` | 375 MHz | HDMI 串行时钟，**全工程最紧的时序路径在这里** |
| `S_csi_rx_clk` | D-PHY 恢复出来的 | ISP 流水线的工作时钟 |
| `S_ddr_clk` | DDR PHY 输出 | DDR 读写 |

**为什么重要**：一个信号从 A 时钟域直接拿到 B 时钟域用，会偶发亚稳态（时好时坏，最难查）。
正规做法是加"两级同步器"。工程里 `design_top_wrapper.v` 的 `S_dbg_*_seen_sync` 那一批就是这个用法。

> **对你的直接含义**：按键（`S_24m_clk` 域）要控制算法模式，算法在 `S_csi_rx_clk` 域 ——
> 中间必须同步。如果你要改用按键控制别的功能，记得走同样的路子。

## 6. 怎么验证你的改动（三个层次，从便宜到贵）

### 第 1 层：仿真（不用上板，几分钟）

`my_algo.v` 是**纯 RTL**，不含任何安路器件原语，所以可以独立仿真。

- **工具**：本机有 `ModelSim Altera Starter 10.3c`（在 PATH 里，`vsim` 直接能调）；
  IC Coder 插件也自带 `iverilog`。两个都能跑**行为仿真**。
- ⚠️ **限制**：这两个都**不能仿真安路器件原语**（PLL / DDR / MIPI / TMDS）——那些是加密 IP。
  所以**只能仿真 my_algo / key_mode_ctrl 这类纯逻辑模块**，整机仿真做不了。
- **做法**：给 my_algo 喂几个已知像素（比如 R=255,G=0,B=0），看输出是不是预期的灰度/二值值。
