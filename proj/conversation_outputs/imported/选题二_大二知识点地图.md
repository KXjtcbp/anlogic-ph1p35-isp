## 2. 知识点详解

### K1 · Verilog 可综合子集与 RTL 风格 ★★★

**要掌握到什么程度**
- 组合逻辑用 `always @(*)`，时序逻辑用 `always @(posedge clk)`，**两类绝不混用**。
- **阻塞赋值 `=` 只用于组合逻辑，非阻塞赋值 `<=` 只用于时序逻辑**，能说清为什么。
- `parameter` / `localparam` / `` `define `` 的区别与使用场景；`generate` 做参数化结构。
- 复位策略：同步复位 vs 异步复位，**本项目统一用一种并写进接口手册**；异步复位同步释放。
- 可综合子集边界：`#延时`、`initial`（除 ROM 初始化）、`real`、动态数组、`while` 不可综合。

**为什么这个选题需要它**：整个项目几千行 RTL 都建立在这些基本约定的正确性上，混淆阻塞/非阻塞是最常见的低级却致命的错误。

**自测**
1. 写出一个参数化 `N` 位、带同步复位的移位寄存器。
2. 写出一个按键消抖模块（含边沿检测，输出单周期脉冲），要求说明消抖时间的计算依据。
3. 解释：为什么在时序逻辑里写 `a = b; c = a;` 会得到错误结果？

### K2 · FPGA 内部结构与资源类型 ★★★

**要掌握到什么程度**
- 知道 LUT4、FF、进位链、**ERAM（20Kb 真双口块）**、DSP（27×18 / 9×9）、PLL、IO 单元各自适合做什么。
- 会用 TD 的资源报告，会填主文档 §2.4 的资源预算表。
- 会做粗估：一个 N bit × M 深的 FIFO 用几块 ERAM？一个 3×3 窗口寄存器组用多少 FF？

**为什么这个选题需要它**：PH1P35 只有 **38,189 LUT / 108 块 ERAM（270 KB）/ 40 DSP**。ERAM 存不下整帧图像（720p RGB888 一帧 = 2.76 MB），这一条直接决定了你的架构必须是"行缓存 + 片内 DDR 帧缓存"。

**自测**
1. 108 块 20Kb 的 ERAM，总共多少 KB？720p 一行的 RGB888 数据是多少字节？能存几行？
2. 为什么卷积运算要用 DSP 或移位加法，而不是写 `a * 0.375`？
3. 用一行代码说明什么情况下综合器会把逻辑放进 ERAM 而不是寄存器。

### K3 · 时序逻辑与状态机 ★★★

**要掌握到什么程度**
- 三段式状态机（状态寄存 / 次态组合 / 输出组合或寄存）；Moore 与 Mealy 的区别与选用。
- 状态编码（二进制 / 独热）对资源和时序的影响。
- **默认分支处理非法状态**（`default: next_state = IDLE;`），避免死锁。
- 复杂流程用状态机表达：如"上电等待 → I2C 写配置序列 → 校验 → 运行 → 出错重试"。

**为什么这个选题需要它**：I2C 摄像头配置、DDR 读写调度、帧缓存乒乓切换、按键交互、CSV/串口协议，全都是状态机。

**自测**
1. 写一个 I2C 主机的写时序状态机（START → 地址 → ACK → 寄存器 → ACK → 数据 → ACK → STOP），并说明时钟分频怎么算。
2. 用状态机描述帧缓存的"写第 N 帧 / 读第 N−1 帧 → 消隐期交换"的乒乓逻辑。

### K4 · 跨时钟域（CDC）与亚稳态 ★★★（**本选题第一号技术风险**）

**要掌握到什么程度**
- 说清什么是亚稳态、为什么会有、MTBF 与什么有关。
- **单 bit 电平信号**：两级（或三级）同步器跨时钟。
- **单 bit 脉冲**：脉冲展宽 + 同步 + 边沿检测，或握手。
- **多 bit 数据总线**：**绝对不能用两级同步器**，必须用：
  - 异步 FIFO（读写在各自时钟域，空满标志用格雷码指针跨域），
  - 或双口 RAM + 握手，
  - 或乒乓缓冲 + 帧同步信号。
- 格雷码为什么能安全跨域（每次只变 1 bit）。
- **复位也要跨域**：异步复位同步释放（reset synchronizer）。

**为什么这个选题需要它**：本项目至少有 4 个时钟域（MIPI 采集、DDR 用户时钟、视频像素时钟 74.25 MHz、控制时钟）。**"偶发花屏、几秒一次"这类最难查的故障，90% 是 CDC 问题。**

**自测**
1. 解释为什么多 bit 总线不能只用两级触发器同步（用时序图说明）。
2. 写出异步 FIFO 的"满"判断逻辑，并解释为什么要把读指针同步到写域、把写指针同步到读域。
3. 为什么异步复位需要"同步释放"？画出电路。
4. 你的工程里有几处跨时钟边界？分别用什么手段？（**这题必须能答，答辩会问**）

### K5 · 时序约束与静态时序分析（STA）★★★

**要掌握到什么程度**
- 会写：`create_clock`、`create_generated_clock`、`set_input_delay` / `set_output_delay`、`set_clock_groups -asynchronous`、`set_false_path`、`set_multicycle_path`。
- 理解建立时间（setup）/保持时间（hold）、时序余量（slack）、WNS / TNS / WHS。
- **会读时序报告**：找到关键路径（最差路径），看懂它经过哪些逻辑级，判断是"逻辑太深"还是"布线太长"。
- 会修时序：插流水线寄存器、减少组合逻辑级数、复制高扇出寄存器、调整代码结构让工具更好优化。
- 知道**未约束的时钟路径会被工具优化掉，结果上板随机错**。

**为什么这个选题需要它**：像素时钟 74.25 MHz、DDR 时钟更高，不写约束就是"靠运气"。这也是**答辩时的常见提问点**。

**自测**
1. 为 74.25 MHz 像素时钟写一条 `create_clock`。
2. WNS = −1.2 ns 是什么意思？你会怎么修？
3. 你项目里哪两个时钟是异步的？该怎么约束？
4. 为什么 `set_false_path` 不能乱用？（答：会掩盖真实的时序问题）

### K6 · 验证方法与 testbench ★★★

**要掌握到什么程度**
- testbench 结构：时钟/复位生成、DUT 例化、激励 `task`、结果检查、结束条件（`$finish`）。
- 文件 IO：`$readmemh` / `$readmemb` 读激励，`$fopen` / `$fwrite` 导出结果。**这是像素级比对的基础。**
- 自检（self-checking）：在 testbench 里直接判 PASS/FAIL，而不是靠人眼看波形。
- 边界用例设计：图像模块必须测**四个角、四条边、最窄宽度、非 2 的幂宽度、全黑、全白、棋盘**。
- 简单断言（`assert`）的使用。
- 覆盖率概念（行/条件/状态机覆盖），不必追求工具覆盖率，但要有"边界是否都测到"的意识。

**为什么这个选题需要它**：图像算法模块的 bug 大多在边界，靠上板肉眼几乎不可能发现（黑边、错位一像素）。**没有自检 testbench，就没有可回归的工程。**

**自测**
1. 给 `line_buffer_3x3` 写一个自检 testbench，要求自动检测四角与四条边的窗口值并报 PASS/FAIL。
2. 设计一组测试图案（至少 8 种），说明每种图案是为了抓什么 bug。
3. 解释：为什么 testbench 里可以用 `#10` 延时，而 RTL 里不能？

### K7 · 视频与图像基础 ★★★

**要掌握到什么程度**
- 概念：像素、分辨率、帧率、像素时钟、帧/行总周期、消隐区（front porch / sync / back porch）、`HS`/`VS`/`DE` 的极性。
- **能独立查表并写出 720p60 的完整时序参数**（HActive=1280、HFP、HSync、HBP，VActive=720、VFP、VSync、VBP），并算出像素时钟 = 74.25 MHz。
- 颜色格式：RGB888 / RGB565、YUV / YCbCr 4:4:4 与 4:2:2、RAW Bayer（RGGB/BGGR 相位）、灰度的来源（Y 或 G 通道）。
- **量化范围**：limited range（16–235）vs full range（0–255）——搞错会导致画面发灰或过曝。
- Gamma、对比度/亮度调整的基本概念。

**为什么这个选题需要它**：所有时序参数、颜色问题（偏色/发灰/发白）都源于这些基础没搞清。这是**投入产出比最高的知识点**。

**自测**
1. 写出 720p60 的全部时序参数并算出像素时钟；算出每 Lane TMDS 速率。
2. 摄像头输出 RGB 数据，显示出来整体发灰发白，最可能是什么原因？
3. Bayer RGGB 阵列中，第 (0,0) 像素是什么颜色？如果你按 (0,0)=R 去解，图像会怎样？
4. 为什么"只处理 Y 通道"能把算法资源降到 1/3？

### K8 · 视频接口协议（MIPI CSI-2 / D-PHY / HDMI / I2C）★★

**要掌握到什么程度**（不用精通，但要能和代码对上）
- **D-PHY**：差分对、Clock Lane + Data Lane、HS（高速）与 LP（低功耗）模式、字节时钟。**PH1P35 有 2 个 D-PHY v2.0 硬核，物理层不用你做。**
- **CSI-2**：长包 / 短包结构、包头（数据类型 + 虚拟通道 + 字数）、ECC/CRC、RAW10 打包方式（一个像素 10 bit，怎么塞进字节流）。**重点是理解官方 IP 输出的信号含义。**
- **HDMI / TMDS**：8 bit → 10 bit 编码、DC 平衡的作用、三路数据 + 一路时钟、为什么速率是像素时钟 ×10。
- **I2C**：起始/停止条件、7 位从地址、ACK、寄存器写序列、时钟频率（通常 100/400 kHz）。**这是你唯一必须自己写的外设协议。**

**为什么这个选题需要它**：MIPI 和 HDMI 你主要靠官方 IP/例程，但**必须理解它们的接口语义**才能对接；I2C 是你自己要写的。

**自测**
1. 说出 CSI-2 一个长包从包头到包尾的字段。
2. TMDS 为什么要做 DC 平衡？不做会怎样？
3. 写一个 I2C 主机模块的接口定义（端口列表）并说明时钟如何产生。

### K9 · 存储、带宽与数据流缓冲 ★★★

**要掌握到什么程度**
- 带宽计算：分辨率 × 帧率 × 位宽；写 + 读的总和；与 DDR 可用带宽对比；留 ≥30% 余量。
- DDR 访问特性：突发传输、行列管理；**连续地址访问效率远高于随机访问**。
- 帧缓存方案：单缓冲（会撕裂）/ 乒乓双缓冲 / 三缓冲；**切换必须发生在帧消隐期**。
- 行缓存与窗口生成：用 `N-1` 个行缓存（或 N 个）+ 移位寄存器组成 `N×N` 窗口；算清每级需要多少存储。
- 异步 FIFO 深度计算：按"生产者/消费者的速率差 × 最大突发长度"来定，不是拍脑袋填 512。
- 双口 RAM 的应用场景（跨时钟 + 随机访问）。

**为什么这个选题需要它**：这是"通路能不能通、画面会不会撕裂、帧差法能不能做"的关键。也是**大二学生最缺的一环**。

**自测**
1. 算 720p60 RGB888 乒乓双缓冲的 DDR 读写总带宽，与片内 DDR（1066 Mbps × 16）对比，余量多少？
2. 生成 3×3 窗口需要几行缓存？每个行缓存多少 bit？总共占多少 ERAM？
3. 帧缓存乒乓切换如果发生在有效像素区，屏幕会看到什么？
4. 摄像头 60 fps、显示 60 fps 但两者时钟异步，为什么仍需要 FIFO/缓存？（答：瞬时相位差会累积）

### K10 · 图像算法及其硬件化 ★★★

**要掌握到什么程度**
- 算法原理（能写出公式、能手工算一个小例子）：灰度变换、阈值二值化、Sobel/Prewitt/Laplacian 边缘检测、均值/高斯/中值滤波、形态学腐蚀膨胀、帧差法、直方图统计与均衡、RGB↔YCbCr/HSV、颜色阈值分割、投影法/连通域、包围盒。
- **硬件化思维**（这才是重点）：
  - 能流式处理就流式处理（点操作、3×3 邻域），不要整帧迭代。
  - 用窗口 + 流水线，让每个时钟出一个像素。
  - 系数对称/常量可以复用乘法器或用移位加法（**Sobel 完全不需要乘法器**）。
  - 需要全局统计的（直方图、自适应阈值、大津法）→ 用"上一帧统计结果指导当前帧"，避免整帧延迟。

**为什么这个选题需要它**：这是 F3/F6/F7/H2/H4/H5 的全部内容。

**自测**
1. 手算 3×3 图像经 Sobel 后的中心像素输出值。
2. 说明 Sobel 为何无需乘法器，并写出硬件结构。
3. 自适应阈值（局部均值）需要用到什么资源？怎么避免整帧缓存？
4. 帧差法需要几帧缓存？为什么？运动区域的"计数"怎么用硬件统计（提示：投影/连通域/计数）？
5. 颜色阈值分割在 RGB 空间做和在 HSV 空间做，各有什么优缺点？

### K11 · 定点数、位宽与溢出 ★★★

**要掌握到什么程度**
- Q 格式（Qm.n）表示与范围/精度计算。
- **位增长**：加法位宽 +1、乘法位宽 = 两者之和；知道每一步该保留多少位。
- **饱和（saturate）而非回绕（wrap）**：图像处理里回绕会产生刺眼的黑白点。
- 用移位代替除法、用 `>>>`（算术右移）处理有符号数、舍入方式的影响。
- **误差评估**：与 Python 浮点参考模型比对，给出最大误差与平均误差，并说明是否可接受。

**为什么这个选题需要它**：溢出/截断是"仿真看不出、上板一眼看出（异常条纹/黑点）"的典型问题；同时位宽是资源优化的主要抓手。

**自测**
1. 为 3×3 高斯滤波（系数 1,2,1 的行列可分核）设计完整位宽方案，从 8 bit 输入推到 8 bit 输出，说明每一步的位宽与误差。
2. 说明"饱和"和"回绕"分别会产生什么样的图像缺陷。
3. 计算 `255 * 1.375` 用 Q8 定点怎么表示、怎么算、误差多少。

### K12 · OSD 与字库 ★★

**要掌握到什么程度**
- 点阵字模的来源与格式（16×16 汉字、8×16 英文）、位序（MSB 还是 LSB 在前）——**这是最容易搞错的地方**。
- 把位图/Logo 转成 ROM 初始化文件（`.mif` / `.hex` / `$readmemh` 格式）的流程；写一个 Python 小工具自动化。

- **Alpha 混合**：`out = (fg × α + bg × (255 − α)) >> 8`，注意除 256 用移位、α 的范围。
- OSD 位置/透明度寄存器化，方便按键或串口调整。
- Logo 素材来源与使用规范（用赛事/厂商提供的素材，注明出处）。

**自测**
1. 把一张 128×64 的单色 PNG 转成 ROM 初始化文件，说明你的位序约定与验证方法。
2. 写出 8 bit Alpha 混合的一行 Verilog，并说明最大误差。

### K13 · 工具链（TD / FD / 仿真器）★★★

**要掌握到什么程度**
- **TD（逻辑设计主力）**：新建工程（选对器件 PH1P35MDG324 / 324 封装）、添加源文件、综合、约束（引脚 + 时序）、布局布线、生成位流、下载（SRAM 调试 / Flash 固化）、**在线逻辑分析/调试工具**、IP 生成器（FIFO / PLL / ROM / 存储控制器）、时序报告与资源报告解读。
- **FD（FPSoC 开发）**：PH1P35 平台的 RISC-V 工程创建、编译、调试（用于摄像头 I2C 配置与控制逻辑）。
- **仿真器**：ModelSim/QuestaSim 与安路器件库的对接、`.do` 脚本批处理仿真。
- **版本与兼容性**：记录 TD/FD 版本号；不同版本的综合结果可能不同。

**为什么这个选题需要它**：工具不熟，所有工作都卡在"点哪个按钮"。**P0 阶段必须把这条链路走通 3 遍以上，形成肌肉记忆。**

**自测**
1. 不看教程，从零新建一个工程并让板上 LED 闪起来。记录全过程步骤。
2. 在 TD 里找到资源报告与时序报告，说出你的关键路径在哪。
3. 用 TD 的 IP 生成器生成一个异步 FIFO 并例化。

### K14 · 脚本与自动化 ★★★（**大二最容易被忽略、收益却最大**）

**要掌握到什么程度**
- Python + NumPy / OpenCV / Pillow：
  - 生成测试激励（各种边界图案）并写成仿真可读的文本；
  - 用同一算法生成"期望输出"；
  - 读仿真输出、逐像素比对、输出最大误差与 PASS/FAIL；
  - **把上板抓取的一帧像素数据还原成 PNG 图片**（调试神器）。
- 批量仿真脚本（ModelSim `.do` + 批处理/Python 一键回归）。
- 位图转 MIF/HEX 的小工具。
- （进阶）用 Python 生成时序参数表、自动解析综合报告提取资源数据。

**为什么这个选题需要它**：它把"一晚看波形找一个 bug"变成"一条命令定位到第 37 个像素错了"。这是本流程里**投入产出比最高的技能**，而且和图像算法天然契合。

**自测**
1. 用 Python 读一个文本格式的灰度图矩阵，做 Sobel，写出结果文件。
2. 写一个比对脚本：输入 `out.txt` 和 `expected.txt`，输出最大误差、误差像素数与 PASS/FAIL，并以退出码反映结果。
3. 用 Python 把 64×64 的像素文本还原成 PNG 看一眼。

### K16 · 软硬件协同（RISC-V 硬核）★★

**要掌握到什么程度**
- PH1P35 内有 1 个 **RISC-V 硬核**，用 FD 开发，不占 FPGA 逻辑资源。
- FPGA 逻辑与 MCU 的交互方式：寄存器组映射 / 总线接口（AXI-Lite 或厂商自定义总线）/ 中断 / 共享 RAM。
- 外设使用：I2C（配置摄像头）、UART（输出识别结果给上位机）、PWM（驱动舵机）、GPIO（LED/蜂鸣器）。
- 分工原则：**慢速、有分支、要频繁改参数的事交给 MCU；高速、流式、确定性的信号处理交给逻辑。**

**为什么这个选题需要它**：扩展要求 3（机电联动）、H5（自动曝光/白平衡需要动态改摄像头寄存器）、F8 的应用场景，都靠它，而且不消耗宝贵的逻辑资源。

**自测**
1. 用 MCU 通过 I2C 配置摄像头并读回 ChipID，打印到串口。
2. 设计一个"逻辑侧检测到目标 → 中断通知 MCU → MCU 通过 UART 输出坐标"的交互流程。

### K18 · 系统集成、故障定位与技术表达 ★★★

**要掌握到什么程度**
- **分步点亮法**：每次只在"上一个确定可工作的状态"上加一样东西。
- **二分定位法**：用 `test_pattern` 替换前半段通路，快速判断故障在哪一侧。
- **可观测性设计**：把 `frame_cnt` / `line_cnt` / `fifo_overflow_cnt` / `crc_err_cnt` / `pll_locked` / `state` 暴露出来（OSD 仪表盘、串口打印、寄存器读回）。**没有可观测性就没有调试。**
- **老化与异常测试**：连续运行、光照突变、热插拔、反复上电、Flash 自启。
- **数据记录习惯**：每个问题记录"现象 / 定位方法 / 根因 / 解决 / 验证"，直接变成报告素材。
- **技术表达**：用框图和表格说话；用数据证明"实时"和"稳定"；PPT 少字多图。

**为什么这个选题需要它**：评分标准里"系统稳定性""现场展示效果"权重很高，而这两项完全靠这一条。

**自测**
1. 面对"系统运行 3 分钟后偶发花屏"，写出至少 6 步排查计划。
2. 设计一个"连续运行 2 小时"的测试记录表（列名 + 记录频率 + 判据）。
3. 用三句话向不懂 FPGA 的人解释你的系统做了什么。

## 4. 大二最容易低估的 5 件事（请反复读）

1. **CDC 不是"加两级触发器"就完事**。多 bit 总线必须用异步 FIFO 或握手。项目里"偶发花屏"的根源，90% 在这里。
2. **仿真不是"跑出波形"，而是"自动判 PASS/FAIL"**。没有自检与自动化比对的仿真，等于没做仿真。
3. **资源不是"够不够"，而是"还剩多少余量"**。没有余量的设计，换个批次芯片或温度升高就崩。项目里要始终留 ≥20% 余量。
4. **稳定性不是"能跑起来"，而是"连续 2 小时 + 光照突变 + 断电重上电 10 次都对"**。这三条直接对应评分标准里的话。
5. **数据和文档必须边做边记**。周五录像、周日更新数据表。等到最后一周再补，一定补不出来。
