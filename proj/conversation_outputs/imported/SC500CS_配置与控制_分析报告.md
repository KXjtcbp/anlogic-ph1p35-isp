# SC500CS 摄像头配置与控制 · 工程事实报告

对象：安路 PH1P35MDG324 + SC500CS。标注【确认】= 代码直读；【推测】= 推断。
证据统一简写：A=`uics500reg_720p60_v.txt`、B=`uicfgcs500_720p_v.txt`、C=`uics500regAE_v.txt`、D=`ae_set_v.txt`、E=`uii2c_v.txt`、F=`uics500reg_1080p30.v`、G=`design_top_wrapper.v`(lab_ex1)、H=`pin.adc`、I=`ddr2.adc`、J=`ddr2.v`。

## 1. 摄像头配置流程【确认】
- 从机地址 `CAM_ID=8'h6C`（B:17），7bit 即 0x36；每次写 4 字节：dev+16bit 寄存器地址+8bit 数据（B:79-82）。
- I2C 时钟：顶层 `CLK_DIV(24000000/100000-1)`（G:518）→ SCL=24MHz/240=**100 kHz**（E:72,110-116）。
- 序列条数：720p60 表 `REG_SIZE=116`（A:13），index 0..115。
- 延时：写 index 115（0x302d=0）前强制等 `POST_STREAM_DELAY=240000` 个 24MHz 周期=**10 ms**（B:18,56-58），即 0x0100=1 与 0x302d=0 之间。
- 复位：`O_cam_rst` 恒接 `1'b1`（G:482）→ 摄像头复位**不受控、常释放**。`S_rst_n=S_pll_lock`（G:217），PLL 锁定后才输出时钟并启动 I2C；`uicfgcs500_720p` 内 `rst_cnt[7]` 再延 128 拍≈5.3µs（B:20,38-39,108）。
- 24MHz MCLK：PLL clk1_out（G:493）→ `O_cam_24m`（G:483），引脚 L3/LVCMOS33（H:7）。
- 无寄存器回读、无 ACK 校验（E 有 `O_iic_bus_error` 但未接出）。

## 2. 720p60 寄存器表要点
1280×720（0x3208/09=0x0500、0x320a/0b=0x02d0，A:27-28）；HTS=0x0640=1600（A:29）、VTS=0x03e8=1000（A:30）→60fps；2-Lane、RAW10、480Mbps/lane（0x4837=0x42，A:70）；曝光初值 **1990**=0x7C6（0x3e00/01/02=00/7c/60，A:63）；增益初值 0x3e08/09=**0x0F20**≈4x（A:74）；0x3220=0x01 启用 VBIN+HSUB 片内裁剪（A:33）。
前若干条：`0:0x0103=01`(软复位) `1:0x0100=00` `2/3:0x36e9/36f9=80`(PLL) `4:0x36ea=3c` `5:0x36ec=1b` `6:0x36fd=14` `7/8:36e9/36f9=04` `9/10:0x3016/17=10/0e` `11:0x301f=04`（A:16-21）。

## 3. 1080p30 vs 720p60 差异
| 项 | 720p60 | 1080p30 |
|---|---|---|
| 条数 | 116（A:13） | 121（F:35） |
| 分辨率 | 1280×720 | 1920×1080（F:71-74） |
| HTS/VTS | 1600/1000 | 2852/1127（F:75-78） |
| MIPI 0x4837 | 0x42 | 0x21（F:156） |
| PLL | 36ec=1b,36fd=14,301f=04 | 36ec=0b,36fd=24,301f=50,3031=0a（F:45-61） |
| 曝光/增益初值 | 1990 / 0x0F20 | 2246 / 0x085F（F:142,159-160） |
| stream on | index 114 | index 120 |

关键差别：720p60 靠 VBIN+HSUB 行内裁剪+短 HTS 拿 60fps；1080p30 全幅直出。注释明确警告**不能只换寄存器表**，MIPI/ISP/DDR/VTC/HDMI 必须同步（F:16-20）。

## 4. AE/AG
`ae_set` **没有亮度统计输入**，只有按键 → **开环手动，不是闭环自动曝光**（D:33-43）【确认】。
- 默认 `r_ae_set=1990, r_ag_set=80`（D:76,81,112-113）。
- AE 范围 3..1989、步进周期 1ms；AG 范围 17..88、步进周期 32ms（D:61,66-67,89-96）。
- I_btn[0]/[1] 减/加曝光，[2]/[3] 减/加 AG（D:88-96）；顶层只接 `{I_button,2'b11}`（G:509），即仅 2 个按钮可用。
- 写入：`I_AE[15:12]→0x3e00[3:0]`、`I_AE[11:4]→0x3e01`、`I_AE[3:0]→0x3e02[7:4]`（20bit 曝光）；`I_AG→0x3e08/0x3e09`（C:47-51）。
- 增益表：索引 `I=I_ag-16`，7bit（0..73）（B:127-132）。三段 0-31→0x0320~033F、32-63→0x0720~073F、64-73→0x0F20~0F29；高字节 03/07/0F 对应 1x/2x/4x 模拟增益档、低字节细调（高字节档位归属【推测】）。
- ⚠️ D:74 注释"AG=48 → 0x0f20"有误：48-16=32→0x0720；0x0F20 对应 AG=80（正是默认值）。

## 5. mipi_rx_error_detect
检测**每帧行数异常**：data_valid 下降沿累加 `S_line_cnt`，`I_frame_end` 时若 `!=12'd832` 置 `O_mipi_rx_error=1`，data_valid 期间清零；另有 h_cnt（帧内有效拍）/c_cnt（帧计数）。**读出靠在线逻辑分析核 `cwc1`**（非寄存器）。832 为硬编码常量【其物理含义为推测】。该模块在本例程**未例化**。

## 6. ddr2.adc 内容与判断
列出：`ddr_ck_p/n`(X0Y44Z2/Z3, DIFF_SSTL15)、cke、cs_n、odt、we_n、cas_n、ras_n、ba[1:0]、addr[12:0]、dq[15:0]、dqs_p/n[1:0]、dm[1:0]（均 SSTL15，I:1-50）；另列硬核 IP 位置 mlclk/pll0/pll1/ioclk[0:1]/ac_byte[0:3]/dx_byte[0:1]/bkref[0:1]（I:52-73）。
**判断：板上外置独立 DDR 芯片，非片内集成**【推测，依据充分】：
1. ddr_* 是**用户顶层端口**（G:25-38），必须引出到引脚；
2. 约束写死**封装焊球号**（#pl44c/#pl53a…），是真实球位；
3. 板级 `pin.adc` 里**完全没有 ddr_\***（仅 I2C/HDMI/按键/时钟），DDR 约束只由 IP 提供；
4. 信号集是标准独立器件接口（CS/CKE/ODT + /RAS//CAS//WE + 13 行/2 bank/10 列 = 512Mb×16）；
5. SSTL15/DIFF_SSTL15 只对片外存储器总线有意义。
补强：`tCK=1876ps`→533MHz→**1066 MT/s**，CL7/CWL6，DX_NUM=2(16bit)，用户侧 128bit AXI（J:61,63-72,81-82,97）。
⚠️ **与工作区备赛文档冲突**：`选题二_备赛工作流程.md:43,60` 称"512Mb 片内集成 DDR、不需外部芯片"。容量/速率吻合，但引脚证据指向外置——**须查开发板原理图定论**（该文档自己把"原理图+引脚分配表"列为最关键且仍未取得，见 `选题二_执行清单与排错手册.md:38`）。
另：文件夹名 ddr2，但 CL7/CWL6 + 1066MT/s 更像 DDR3-1066【推测】。

## 7. 其余模块
- **key_remove_shakes**：按键消抖。4 级同步+下降沿，维持 `100000` 拍，期满且键仍低出**单周期脉冲**。挂 HDMI 像素时钟域（`hdmi_tx.v:142-145`）；例程 `I_key_in` 恒 0，**实际未启用**（G:840）。
- **signal_delay**：AWB 行内固定延迟线。参数 IMG_H/W、DATA_WIDTH=96、DELAY_CYCLE=50（`awb.v:186-190`）。双口 BRAM，每行 `IMG_WIDTH>>2` 个 96bit 字（3 像素×32bit），读地址延后 50 拍启动，`O_tuser = v_cnt==0 && rd_cnt==1`。
- **video_cutting**：固定窗口裁剪，行 126..727 且列 100..357 才放行，frame_start/end 延迟一拍直通。**例程未例化**。
- **uial2axis**：native→AXIS。参数 1280×720、INPUT_DATA_WIDTH=40（G:610-613）。`IMG_WIDTH_4X=IMG_WIDTH>>2`=320；tlast 在 hcnt==319，tuser 在 vcnt==0&&hcnt==0。**`I_data_end` 有端口但未使用**（坑）。
- **ps_wrapper**：硬核 MCU（RISC-V）封装。JTAG 4 线 + APB 主机（paddr 20bit/pwdata 32bit）+ 2×UART + 8 路双向 GPIO。⚠️ **:92/:95 有 bug**：`IO_gpio3/4` 三态误用 `S_gpio5_out/S_gpio6_out` 而非各自 `_dir`，正确写法被注释在 :86-90。例程未例化。

## 8. 可复用结论与坑
**可直接复用**：从机 0x6C、SCL 100kHz、116 条 720p60 表、曝光 1990、增益 0x0F20、stream-on 后等 10ms 再写 0x302d=0、24MHz MCLK。
**坑**：
1. `O_cam_rst` 恒 1 → 无真实上电复位时序，换板/换头要自己加。
2. AE/AG 是**开环手动**，不会自动收敛；要做真 AE 须自建亮度统计回路。
3. `ae_set` 注释 AG=48 与代码默认 80 不一致。
4. 参数强耦合：换分辨率必须同步 MIPI(LANE_NUM/BYTE_NUM)、uial2axis 尺寸、ISP、DDR 帧缓存、VTC、HDMI（F:16-20）。
5. 多处依赖 `IMG_WIDTH>>2`（每拍 4 像素）假设，改位宽会错 tlast 周期。
6. `mipi_rx_error_detect` 的 832 硬编码，换分辨率即失效。
7. DDR 片内/片外必须查原理图，勿照抄工作区文档的"片内集成"结论。
