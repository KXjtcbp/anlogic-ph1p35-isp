## 二、最关键的结论：算法插在哪里，接口是什么

我逐行读了 `isp_top.v`（lab2 版 141 行、lab3 版同结构），**整条 ISP 流水线是这样接的**：

```
I_tdata[39:0] (RAW10)
   │
   ▼
demosaic  (BGGR, 1280×720)   → m_aixs_tdata[127:0]
   │
   ▼
data128_96                    → m_aixs_tdata_96[95:0]   ← 3 像素 × 32bit RGB888
   │
   ▼
awb  (自动白平衡)              → awb_O_tdata[95:0]
   │
   ▼
edge_detect_96  ★ ← 官方算法在这里（要换掉的就是它）
   │
   ▼
data_96bit_to_128bit          → O_tdata[127:0]
   │
   ▼
isp_top 输出 → video_in → DDR2 → video_out → uivtc → hdmi_mixer(+OSD) → hdmi_tx
```

### 对你的直接含义（这条最值钱）

**要换掉算法，只需要动 `isp_top.v` 里一个例化块（第 102–119 行），并新增你自己的算法模块。**

- 插入位置的输入：`awb_O_tdata[95:0]`
- 插入位置的输出：`edge_O_tdata[95:0]` → 送给 `data_96bit_to_128bit`
- **位宽 96 bit = 3 像素 × 32 bit RGB888**（每像素 8bit R + 8bit G + 8bit B）

也就是说：**你不需要懂 MIPI、不需要懂 DDR、不需要懂 HDMI。你只要写一个"96 位进、96 位出"的模块。** 这是整个项目里唯一真正需要你写代码的地方。

### 必须遵守的接口（照抄这个端口表就不会接错）

```verilog
module my_algo (
    input              I_clk    ,
    input              I_rst_n  ,
    input              I_tlast  ,
    input              I_tuser  ,
    input      [95:0]  I_tdata  ,
    input              I_tvalid ,
    output             I_tready ,   // 注意：这是输出口，名字却叫 I_tready（原例程就这么写的）
    output     [95:0]  O_tdata  ,
    output             O_tlast  ,
    output             O_tuser  ,
    output             O_tvalid ,
    input              O_tready
);
```
> 抄的时候直接对着 `edge_detect_96.v` 的端口抄，**一个字母都不要改**。改名字会导致 `isp_top.v` 里例化处编译不过。

### 三个"必须同时打拍"的信号（最容易错的地方）

`O_tdata` / `O_tlast` / `O_tuser` / `O_tvalid` **必须和算法数据处在同一拍**。
如果你在数据路径上插了 N 级寄存器，那么 `tlast`/`tuser`/`tvalid` 也必须跟着延迟 N 拍。否则行结束/帧开始标记会错位，表现为**画面整体偏移几个像素或整行错位**。

原例程的做法（`edge_detect_96.v` 第 110–112 行的注释）已经替你验证过一件事：
```verilog
// Do not clear line memories here.  A reset loop turns the 10-Kbit
// buffers into slice registers on this device.  The first two rows
// are masked by window_valid and naturally initialize both buffers.
```
**行缓存绝不要放进复位分支**——在这颗器件上会把 ERAM 变成普通寄存器，资源直接爆掉。前两行用 `y_pos >= 2` 这类条件屏蔽掉即可。

## 三、算法怎么选（带资源账，按风险从低到高）

### 先看余量（这是硬约束）

lab3（带 OSD）的后布线数据：**slice 14,852 / 21,216 = 70.00%**，**Setup WNS 只剩 +0.103 ns**。
可用的余量：LUT6 约 11,351、DSP 32 个、ERAM 68 块、触发器约 29,119。
**但 WNS 只有 0.1 ns——这是真正的瓶颈，不是资源数量。**

> 把这句话贴在显示器上：**lab3 已经 70% 且时序擦边，任何新逻辑都会先撞时序，不是先撞资源。**

### 三个候选

| 方案 | 怎么算 | 增量资源 | 与 Sobel 区分度 | 一眼能看出来吗 | 风险 |
|---|---|---|---|---|---|
| **A. 伪彩映射 / 热力图** | 先算灰度 `(R×77+G×150+B×29)>>8`，再查表映射成彩虹色 | 极低（几十 LUT + 一张小 ROM） | **很高**（官方例程全是黑白/原色，你出彩色伪影） | ✅ 一眼可见 | 🟢 低 |
| **B. 颜色空间变换 + 色调旋转** | RGB→YCbCr，对 Cb/Cr 做旋转/偏移，再转回 RGB | 中（几次乘加，可用 DSP） | **很高** | ✅ 明显 | 🟡 中 |
| **C. 3×3 中值滤波** | 排序网络取 9 点中值 | 中高（**+2 行行缓存**，约 2 块 ERAM + 排序逻辑） | 中高 | ✅ 噪点明显减少 | 🟠 中高（要吃 ERAM，且时序更紧） |

### 建议路线（两步走，不要一步到位）

**第一步（先做，稳）**：方案 A —— **灰度 + 伪彩映射**，同时保留一个"原图/算法"的对比开关（按键或拨码切换）。
理由：
1. 点运算级，不碰行缓存 → 时序压力最小，几乎必然收敛；
2. 画面差异极大，评委看 3 秒就能分辨，且**天然不同于 Sobel 边缘检测**；
3. 顺带就能满足扩展要求 (1)「视频图像风格化处理或视觉增强」。

**第二步（有余力再做）**：在方案 A 之上叠 **3×3 中值滤波**（变成"伪彩 + 降噪"），或者做"多算法切换"（原图/灰度/伪彩/二值化 循环），后者直接命中进阶要求 (1)。

**如果时间紧**：只做第一步就够合规（基础第 2 条 + 扩展至少 1 条）。**不要为了炫技去啃帧差法**——帧差需要存整帧，ERAM 和带宽都会被吃掉。

### 阶段 3 · 加"算法开关"（半天）

**做什么**：用一个按键（板上有 `I_button[0]`=N2、`I_button[1]`=J14）做模式切换：原图 ↔ 你的算法。
**注意**：官方例程里这两个键**只用来调摄像头采样延时**（`ae_set.v:71` 的注释 `I_button[0]:IncDatDly, [1]DecDatDly`），**没有任何算法切换逻辑**。所以你要自己加：
1. 按键消抖（参考工程里的 `key_remove_shakes.v`，lab3 里就有这个文件）；
2. 一个切换状态机/计数器；
3. 在算法模块里根据状态选择输出原像素还是处理后像素。

**为什么值得做**：它同时满足两件事——评委能**当场看到对比**（比只展示结果有说服力得多），而且直接命中进阶要求 (1)「多算法切换与状态显示」。

**验收物**：一段能看出"按一下画面就变"的屏摄。
**降级**：按键调不通就把切换键做成"拨码"或用 OSD 里现有的帧计数区域显示当前模式编号。

### 阶段 4 · 加 OSD 状态显示（半天，可选但很划算）
