**净增量（★ 做资源估算时的锚点）**

| 模块 | LUT6 | slice | DSP | ERAM | 判断 |
|---|---|---|---|---|---|
| `edge_detect_96`（3×3 Sobel，半分辨率，移位实现，无乘法器） | **+557 (2.62%)** | +568 | 0 | **0** | **极便宜**，3×3 邻域类算法可放心做 |
| OSD（`anlogic_logo_rom` + `osd_char_lib` + mixer 常量除法） | **+2,804 (13.2%)** | +2,494 | +1 | **0** | **贵 5 倍**，且 ERAM 未增 → **Logo ROM 被综合成 LUT 了** |

> **两条关键结论**
> ① **`edge_detect_96` 的行缓存没有增加 ERAM 计数**（仍为 40）→ 说明小容量数组被**打包进已有块**，行缓存成本比预想低得多（但也说明它没用上独立 ERAM，是"塞进去的"）。
> ② **OSD 的 ERAM 增量 = 0** 而 LUT 增量 = +2804 → `anlogic_logo_rom.v`（6400 行 `always @(*) case`，15 bit 地址 × 25 bit 输出）**是纯组合 LUT**。改成 ERAM 可直接回收上千 LUT。这是 P2 的首要任务。

### 3.3 资源预算与熔断线（**P2 之后按此表管控**）

| 阶段/项目 | LUT6 增量 | 累计 LUT6 | 累计占比 | Guard |
|---|---|---|---|---|
| 空壳通路基线（实测） | — | 9,865 | 46.50% | 已知 |

|---|---|---|---|
| `sys_clk_50m` | **50 MHz**（20 ns） | 板载 50M 有源晶振 → 引脚 **C4** | 系统输入 |

### 3.5 DDR 与带宽账

| 项 | 值 | 说明 |
|---|---|---|
| 类型 | **Integrated（片内封装 SiP）** | IP 配置选项与 DDR2/3/4 并列，工程选的是 Integrated；几何 13×10×2×16 bit = **512 Mb = 64 MB**；板卡硬件表**未列任何 DRAM**；`pin.adc` 无 `ddr_*`（由 IP 自带 `ddr2.adc` 提供） |
| 工作模式 / 时序 | DDR2，**CL=7**，tCK = **1876 ps** → 533.3 MHz / **1066 MT/s** | |
| 用户接口 | MC 地址 **25 bit**、数据 **128 bit**（AXI 26 bit / 128 bit，本设计用 MC 原生口） | |
| 引脚约束 | `ddr2.adc` 50 条，pad 坐标 + **SSTL15 / DIFF_SSTL15**，含 `mlclk/pll0/pll1/ioclk/ac_byte/dx_byte/bkref` 硬核位置 | 不是外置 DRAM 的板级走线约束 |
| IP 自检 | `ddr2_drc_check.log` 无违例；`ddr2_proc.log` 全 success | |
| 帧缓存 | **4 个**，基址 `0 / 7,000,000 / 14,000,000 / 21,000,000`（16-bit 字地址）→ **每帧 14 MB，共 56 MB ≤ 64 MB** | 余量 8 MB |
| 缓冲语义 | 写指针 `wp`，读指针 **`rp = wp + 2 (mod 4)`** → **三缓冲（读落后 2 帧）** | 帧差法的存储基础已具备 |
| 突发 | **240 拍 × 128 bit = 3840 字节 = 1280 px × 3 B = 一整行 RGB888** | |
| FIFO | 128 bit × **512 深**（可用 510）；注释警告**单次突发不要到 256**，余量需 > 突发长度 + DDR 读延迟（~10–20 拍） | |
| **仲裁** | **写只在 `!rd_busy` 时启动，读只在 `!wr_busy` 时启动 → 读写互斥，非并发** | 🔴 帧差法需"多读一路"，**必须重算仲裁与带宽**，不能想当然 |
| 带宽 | 峰值 **2.13 GB/s**（128 bit × 133 MHz）；720p60 RGB888 读写实测需 **~0.45 GB/s** | 带宽充足，瓶颈在仲裁互斥 |
| 错误容错 | `I_mipi_rx_error` 有效时**不推进写指针**，下一帧仍写回上一缓冲（覆盖损坏帧）→ 掉帧不撕裂 | 现成的好东西，**不要动** |
| 🔴 已知风险（源码注释） | *"With a continuous 1080p stream that kept `wr_busy` permanently asserted and starved `video_out`, so no DDR read request could ever start."* → **连续高分辨率流下写通路会饿死读通路** | 例程已修（720p60 下无问题），但**任何提高像素吞吐的改动都要重新验证这一点** |

**最容易写错的一段（`video_out.v` 位拼接）**

- 在该周期第 **0、5、10** 拍各读一次 FIFO
- 第 **5、10** 拍跨字拼接：`{fifo_data_1d[7:0], fifo_data[127:112]}`
- 🔴 **全工程最容易写错的一段。改分辨率/像素格式前必须先仿真这段。**

### 5.1 禁区：参考实例是"整条链"，不是单个模块

`edge_detect_96` 的实现链（**源码确证**）：

```
RGB → 灰度化 R/4+G/2+B/4 → 2 个 16bit×320 ERAM 行缓存（两行灰度）
    → 3×3 Sobel（移位实现，signed 13bit，无乘法器）→ mag = |Gx| + |Gy|（14bit）
    → 阈值判决 EDGE_TH（源码 80）→ 多数表决滤波 → 边缘白/背景黑
    （另有：每拍 4 像素两两平均 → 水平分辨率减半，1280 只出 640 个边缘样本；
      每拍算 2 个窗口，结果复制 {out0,out0,out1,out1}）
```

> 🔴 **判定规则**：**不能只是"换个阈值""换个灰度公式""换 Prewitt"** —— 那还是同一条算法链。必须做到以下至少两条实质差异：
> ① 算法原理不同（非梯度类）② 处理的信息不同（如用色度/多帧/统计量）③ 输出的语义不同（如区域、坐标、分类而非边缘图）④ 自适应/闭环机制

### 5.2 安全算法库（按与参考实例的距离排序）

| 档 | 算法 | 与参考的距离 | 硬件成本 | 实测/估算依据 |
|---|---|---|---|---|
| **A 便宜** | **自适应阈值二值化**（局部均值/局部方差） | 远（无梯度、有自适应） | 低 | 需一个均值窗口（可复用行缓存），逻辑 ~800–1,500 LUT6 ⚠估算 |
| **A 便宜** | **中值滤波 3×3** | 中（非同算法，但同 3×3 窗口框架） | 低 | 排序网络 ~1,200–2,000 LUT6 ⚠估算；**建议与 A 组合使用以拉开差异** |
| **A 便宜** | **颜色空间变换 / 颜色量化（查表）** | 远 | 低 | 查表走 ERAM + 少量逻辑，~500–1,000 LUT6 ⚠估算 |
| **A 便宜** | **帧差运动检测** | 远（多帧信息） | 低–中 | 复用 4 缓冲 + 减法/阈值 ~300–800 LUT6；🔴 但需**多读一路 DDR**，仲裁要重算 |
| **B 中** | **直方图均衡**（全图 or 分块） | 远（统计类） | 中 | 256 bin 双口统计 + CDF 映射，~1 ERAM + 800–1,500 LUT6 ⚠估算 |
| **B 中** | **形态学（腐蚀/膨胀/开闭）** | 中（3×3 邻域，但非线性、非梯度） | 中 | ~1,000–1,800 LUT6 ⚠估算；**建议叠加在 A 之后构成完整算法链** |
| **B 中** | **卡通化 / 风格化**（中值去噪 + 量化 + 轮廓增强） | 远（复合链路，输出语义不同） | 中 | E1 主推；组合 A 档模块，复用前级 |
| **C 高** | **颜色/几何形状目标检测**（阈值 → 连通域/投影 → 包围盒 → 坐标） | 远（输出目标而非像素） | 中–高 | E2 主推；连通域/投影 ~500–1,500 LUT6 + 行缓冲 ⚠估算 |
| **C 高** | **运动目标检测 + 区域计数** | 远 | 中 | H4；基于帧差扩展 |
| — | ❌ Sobel / Prewitt / Roberts 梯度边缘检测链 | **禁区** | — | 与 `edge_detect_96` 同链 |
| — | ❌ 单帧固定阈值二值化（无自适应） | 危险（太接近） | — | 逻辑上仍在参考链的"阈值判决"一步 |

### 5.3 推荐组合（在 30% slice 预算内的最优解）

```
F3 基础算法  = 自适应阈值二值化（局部均值）   ← 便宜、与参考实例距离远
     +
E1 风格化    = 中值滤波去噪 + 颜色量化 + 轮廓增强 → 卡通化   ← 与 F3 共用行缓存与窗口逻辑
     +
E2 目标检测  = 对二值化结果做投影/连通域 → 包围盒 → OSD 叠加  ← 输出语义完全不同，技术难度高
     +
H1 多算法切换（按键）+ H3 延迟可视化 + H4 帧差运动检测（视余量）
```

### 9.2 答辩问答 v2（每题 30 秒 + 一份数据/图）

| 问题 | 回答要点 |
|---|---|
| **🔴 你们的算法和参考例程有什么不同？** | 拿出 §5 的**结构对比图**：参考例程是"灰度 → Sobel 梯度 → 固定阈值 → 多数滤波"；我们是"自适应局部阈值二值化 → 形态学 → 颜色量化 → 轮廓增强"，**原理、信息来源、输出语义三个维度都不同**。再补一句："我们特意绕开了参考实例的算法链" |
| **为什么用 1280×720 而不是 1024×600？** | 例程与摄像头寄存器表已全面对齐 720p60（HTS 1600 × VTS 1000 = 60 fps，2 lane × 480 Mbps = 960 Mbps 自洽）；赛题要求 ≥1024×600，720p 更优 |
| 空壳通路为什么占 58%？ | 数据表：LUT6 9,865 / slice 12,358；模块级归因（MIPI RX + DDR 控制器 + HDMI 发送核 + ISP） |
| **你们怎么保证时序？** | ① 发现官方例程 STA 覆盖率仅 95.6%，**补全约束到 ≥98%**；② 定位 OSD 常量除法为关键路径根因，改查表后 WNS 从 103 ps → X ps；③ 熔断线机制（>70% 停止加功能） |
| DDR 是片内还是片外？ | **片内集成（SiP）512 Mb**：IP 配置 `PH1P_DDR_TYPE=Integrated`；几何 13×10×2×16 = 512 Mb；板卡硬件表无 DRAM；`pin.adc` 无 `ddr_*` |
| 稳定性怎么证明？ | 连续运行 ≥2h 录屏（无花屏/无溢出）+ 光照突变测试录屏 + 断电重上电 10 次录屏 + 调试日志 |
| 你们怎么处理 MIPI 掉帧？ | 例程内置容错：`I_mipi_rx_error` 有效时不推进写指针，下一帧写回同一缓冲覆盖损坏帧 → 掉帧不撕裂。我们保留并验证了这条路径 |
| 有没有做低功耗？ | 资源瘦身（Logo ROM 从 LUT 改 ERAM 省 X 个 LUT）、时钟域使能、未用模块不例化 |
| 12 周够吗？ | 诚实说明：例程已提供 80% 通路，真难点是 ① 时序余量只有 103 ps ② 算法必须绕开参考 ③ 例程带 8 处缺陷。我们的做法是先瘦身再加功能 |
| 额外处理器可以加吗？ | 赛题二**扩展要求三原则上可用额外处理器**控制小车/机械臂等复杂外设，但**赛题指标要求部分必须在 FPGA 上实现**；我们**优先用片内 RISC-V 硬核 + 板载 IO**，符合"外扩板不含非安路 FPGA"的约束 |
