## 3. 问题③：技能短板的可执行补齐建议

> 说明：把 ③ 提前放到 ② 前面，是因为②的阶段划分依赖③的练习顺序。每条建议都落到**具体文件 + 具体行 + 具体动作 + 判断成功的方法**。

### 3.1 Verilog 复杂模块：读 → 改 → 写，三步走

**先建立一个认知**：图像处理类 Verilog 模块几乎都是同一个骨架——「视频流进 → 用行缓冲拼出 3×3 窗口 → 算一个结果 → 视频流出去」。`edge_detect_96.v` 就是这个骨架最干净的样例（149 行）。

**必读的 6 个位置**（我按实际行号给你，你对照着看）：

| 行号 | 内容 | 它在教你什么 |
|---|---|---|
| 1–18 行 | 参数定义 + 端口列表 | 模块的「外壳」；`tdata/tvalid/tuser/tlast` 是视频流的四件套（`tvalid`=数据有效、`tuser`=一帧的第一拍、`tlast`=一行结束） |
| 22–25 行 | `pix0..pix3` 从 96 位里切出 4 个像素 | 一个时钟周期同时处理 4 个像素（位宽拼接） |
| 29–32 行 | 灰度近似 `R/4 + G/2 + B/4` | **用移位和加法代替乘除法**：`{2'b0,pix[23:18]}` 就是「右移 2 位」（=÷4），`{1'b0,pix[15:9]}` 是「右移 1 位」（=÷2）。这是 FPGA 里最重要的基本功 |
| 44–45 行 | `(* ram_style = "block" *)` 两行存储器 | 告诉综合工具「请把它做成片上 Block RAM」，而不是一堆触发器 |
| 63–81 行 | `sobel_mag` 函数 | 3×3 窗口算梯度的标准写法；`<<< 1` 就是「×2」；第 77–78 行用「取反加一」求绝对值（这是补码运算的常规技巧） |
| 99–147 行 | 时序逻辑主体 | 第 110–112 行注释很重要：**行缓冲故意不复位**，因为「复位一整块缓冲区会被综合成一堆寄存器」，资源会爆 |

**练习 1（极小，约 1 小时内）——先建立「编译→上板→看变化」的闭环**

动作：把 `edge_detect_96.v` 第 4 行的 `EDGE_TH = 11'd80` 改成 `11'd40` 和 `11'd160`，各跑一次，看画面变白/变黑的程度。

⚠️ **关键教学点（这是初学者百分之百会踩的坑）**：在 `isp_top.v` 第 105 行，例化时写了 `.EDGE_TH (11'd80)`，**这个值会覆盖模块内的默认值**。所以你只改模块里的 80 是**不会生效**的——必须改例化处。请你自己动手验证这句话：只改模块内默认值 → 现象不变；再改 `isp_top.v` 第 105 行 → 现象变化。**这个坑搞懂了，你就理解了「参数传递」的实际含义。**

**练习 2（小，约半天）——改输出形式，理解窗口对齐**

`edge_detect_96.v` 第 96–97 行现在是「边缘=白，非边缘=黑」。改成「**在原图上把边缘画成红色**」：把 `out0` 改成 `edge0 ? 24'hff0000 : pix0;`。

⚠️ 你会发现：**红边和实际物体错位了**。原因：3×3 窗口的中心像素来自「上一拍」的数据（第 59–61 行把数据打了一拍存在 `*_prev*` 里），所以输出相对输入天然有延迟。**正确的改法**是把你用的原图像素也打一拍（新增寄存器，在同一 `always` 块里赋值）再叠加。这个练习的价值就在于：**你会第一次真正理解「流水线延迟」和「数据对齐」**——这是所有图像处理代码的核心难点。

（说明：延迟拍数我是从代码结构推断的，**请你在板子上用一张有明确直线/文字的图验证**，不要只信推断。）

**练习 3（中，约 1–2 天）——把自己的算法模块接进系统**

1. 复制 `edge_detect_96.v` 为 `my_algo.v`，模块改名 `my_algo`，先写成**直通**（不做任何处理，`O_tdata <= I_tdata`）。
2. 在 `isp_top.v` 里把第 102–119 行的例化换成你的模块，名称与端口保持完全一致。
3. 编译、上板，确认「画面与原来一样」——这证明你的模块**接口没接错**。
4. 再往里加逻辑（先做灰度，再做二值化，最后做边缘），**每加一步就上板看一次**。

**这条「先直通、再逐步加逻辑、每步都上板」的流程，就是专业做法**，也是把 G4 真正消除的唯一路径。

### 3.2 时序约束：你们不需要从零写，只需要会读「17 行」和会看「2 个数字」

**（a）把例程的 17 行读成 4 件事**

| 行 | 语句 | 通俗解释 |
|---|---|---|
| 1 | `create_clock ... -period 20.000 [get_ports {I_sys_clk}]` | 板上的 50 MHz 晶振：周期 20 ns。**周期和频率是倒数的关系**（1/20 ns = 50 MHz） |
| 2 | `create_clock -period 4.167 ... [get_nets {IO_rx_clk_pad_p}]` | MIPI 摄像头的高速时钟：4.167 ns ≈ 240 MHz（1/4.167ns ≈ 240M） |
| 4 | `derive_clocks` | 让工具**自动**推导出所有衍生时钟 |
| 6–11 | `rename_clock ...` ×5 | 只是给自动生成的时钟**起个好记的名字**（100M/24M/HDMI 像素钟/HDMI 串行钟/MIPI 字节钟），方便后面引用。**它不改变任何电路** |
| 14–17 | `set_clock_groups -asynchronous -group {...} -group {...} -group {...}` | 声明「这三组时钟互不相关，**不要互相做时序检查**」。用途是避免跨时钟域被误判为违例 |

> 重要提醒（避免误解）：`set_clock_groups` **不是**「写了就能过时序」的万能药。它的含义是「这几组时钟之间本来就没有确定的相位关系，工具不要按同步电路去要求它们」。真正的跨时钟域数据传递，仍然需要设计上处理（如用 FIFO、打两拍同步）——这属于后续要学的「跨时钟域（CDC）」话题，**初赛不要求你掌握，但要能说出上面这句话**。

**（b）具体动作（这是可执行的，不是「多练习」）**

1. 在 TD 里对 lab1 工程做一次完整流程：综合 → 布局布线 → 生成比特流。
2. 打开**时序报告（Timing Report）**，找到两个数字：
   - **WNS**（最差负裕量）：**大于 0 = 满足时序**；为负数就是「有路径跑不到目标频率」。
   - **TNS**（负裕量总和）：理想值是 0。
3. **把 lab1 的 WNS 抄在你们的共享记录里**（这是你们的第一个「时序基线」，以后每次大改动都和它比）。
4. 练习一次「故意制造违例」：在例程里随手插几级很长的组合逻辑（例如一长串加法），重新跑，看 WNS 变负——**见过一次负值，以后就不会慌**。

**（c）什么时候才需要你动 SDC？**（明确边界，省掉无用功）

- 只有当你们**新增了时钟源**（例如自己再加一个 PLL 输出）或**新增了带时钟的输入引脚**时，才需要补一句 `create_clock`。
- 否则：**照抄例程的 SDC 即可**。别人已经把这件事做完了。

### 3.4 顺手补掉的三块（都属于「知道了就不会错」的知识）

1. **工程里的文件清单 ≠ 实际生效的代码**。例程工程里存在「被收录但没被例化」的文件（例如 lab2 工程里的 `image_correction.v`，源码中找不到它的实例化）。看代码时以「谁例化了谁」为准，不要假设目录里的文件都在工作。
2. **复位策略**：像行缓冲这种大块存储器，**不要**塞进复位分支（见 `edge_detect_96.v` 第 110–112 行的注释）。这是「资源爆炸」最常见的原因之一。
3. **位宽与拼接**：`{1'b0, x}`、`{2'b0, y}`、`{a, b, c, d}` 这套写法在例程里到处都是，读熟它。**位宽不够会导致数据被截断**，这是初学者最高频的 bug 来源。

## 6. 分工与三个具体动作

### 6.1 为什么按「三条轨道」分，而不是按人「分模块」

因为三人水平相当，**不需要纵向的「师傅带徒弟」结构**，需要的是**横向的三条可独立验证的通道**。而例程已经天然把系统切成了三段，且三段之间用的是同一套视频流接口（`tdata/tvalid/tuser/tlast`）：

```
摄像头 →[采集]→ 算法处理 →[OSD 叠加]→ HDMI 输出
         └ 轨道A（链路与显示）┘
                  └ 轨道B（算法）┘
                            └ 轨道C（OSD 与交互）┘
```

**轨道划分与建议负责人**（X 稍强，建议承担「最容易卡住的那条」，随你们内部协商调整）：

| 轨道 | 建议负责人 | 负责的文件 | 独立验收方法 | 与其他轨道的接口 |
|---|---|---|---|---|
| A 链路与显示 | X | lab1 的采集/显示链、`hdmi_mixer.v`（显示侧）、稳定性测试、帧计数 | 单独跑 lab1：画面实时、无错位 | 上游收算法输出，下游接 HDMI |
| B 算法 | K | `my_algo.v`（从 `edge_detect_96.v` 改造） | 单独跑 lab2 工程，替换算法模块 | 输入输出均遵守 `tdata/tvalid/tuser/tlast` |
| C OSD 与交互 | 豪 | lab3 的 OSD 部分（`anlogic_logo_rom.v` / `osd_char_lib.v` 的使用与文字叠加）、按键（若可用） | 单独跑 lab3：Logo + 文字正常 | 在显示通路末端叠加，**不改动算法输出** |

**三条轨道之间的铁律**：接口签名（模块名、端口名、位宽、`tuser`/`tlast` 的含义）**尽早冻结**，之后谁都不许单方面改。这就是「三人水平相当」时最有效的防冲突手段。

### 6.2 每周一次「合流」（固定动作）

每周固定一个时间（例如周日晚），做三件事：① 三人各自演示自己轨道当前的效果；② 把三条轨道合到一个工程里编译一次，**只要编译通过就算合流成功**（哪怕效果还不完整）；③ 把本周遇到的坑写进共享记录。

**为什么必须每周合一次**：三人并行最怕「各自都很好、合起来不通」。每周花一小段固定时间做一次集成，是把「集成风险」摊薄到每周的唯一办法。

### 6.3 显示器与线材：一条专门的检查清单（本轮新增，依据官方 2.7 原文）

官方原文要求（`.extract\选题二.txt` 第 8 行）：带 HDMI 输入的显示器；**基础像素 1280×720@60Hz**；推荐 HDMI 1.4 及以上、纯铜、长度 ≤5 m。

你的情况：1080P 240Hz 显示器 + **只有一根 HDMI 线**。具体动作：

1. **确认显示器有 HDMI 输入口**，并记下有几个（1080P240 显示器通常有 1–2 个 HDMI + 1 个 DP）。
2. **确认这根线能不能同时满足两台设备**——只有一根线意味着：**板卡占用 HDMI 口时，你的电脑就没法用同一根线输出**。可选方案（按推荐顺序）：
   - 再买一根 HDMI 线（成本最低，也满足题面「数据线」的要求）；
   - 用 HDMI 切换器（免拔插）；
   - 接受手动拔插（可用，但频繁拔插容易接触不良）。
3. **确认这根线是 HDMI 1.4 及以上**（看线身上的标识或包装）。720P60 对带宽要求很低，普通的 1.4 线完全够用；**不建议用又细又长的廉价线**（官方原文点名「纯铜、≤5 米」）。
4. **预期现象先想好**：例程输出的是 **1280×720@60Hz**，而你的显示器是 1080P —— 显示器会自动把 720P 信号**放大到全屏**显示。所以画面上**可能看起来略微不够锐利或有轻微模糊，这属于正常的缩放，不是故障**。如果出现黑屏/无信号：① 先换回电脑确认线和显示器本身没问题；② 再检查显示器输入源（在显示器 OSD 菜单里手动选 HDMI）；③ 检查板卡是否真的在输出（换用另一个 HDMI 口试）。

### 6.4 一个具体的「练手级」核对任务（顺手把 G6 清掉）

用文本编辑器打开 `lab_ex1_mipi_hdmi_SC500_720P\lab_ex1_mipi_hdmi\user_source\hdl_source\design_top_wrapper.v`，搜索 `hdmi_mixer`，看它的例化处有没有传 `IMG_WIDTH`/`IMG_HEIGHT`。

- 我核对到的情况是：**lab1 的 `hdmi_mixer.v` 里参数默认值写的是 1920×1080（`IMG_WIDTH=1920/IMG_HEIGHT=1080`），而 lab3 的同名文件写的是 1280×720**。这两个例程看起来是同一套代码的不同版本。
- **但我没有核对 lab1 的例化处**，所以无法确定最终生效的是哪个值。**请你自己搜一下并记录结论。** 这件小事的意义在于：它让你第一次接触「默认值 vs 例化覆盖」这个真实工程里最常见的困惑（同样也是练习 1 的核心）。

### 6.5 需要你确认的 4 件事（确认后我可以把下一步再收紧）

1. **TD 的实际版本号**（`Help → About`）——决定要不要重装。
2. **「lab1 已跑通」的确切含义**：是「HDMI 上看到了实时画面」，还是「编译下载成功、但没接显示器」？——这直接决定 Gate 1 的起点。
3. **lab2 / lab3 能否编译通过**（先不下载）。
4. **HDMI 线打算怎么解决**（再买一根 / 用切换器 / 手动拔插），以及**板卡按键引脚是否已在约束文件中**（搜约束文件里的 `KEY`/`BUTTON` 字样）。
